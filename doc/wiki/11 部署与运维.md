## 2. 远端状态确认（不要盲信本地 ref）

- `doc/HANDOFF.md` §0.2.1（`:111-155`）：本环境沙箱会静默丢弃 `.git/refs/remotes/**` 的 git 写入，导致 `git status -sb` 误报 ahead。
- 正确做法：`git ls-remote origin refs/heads/main` 与 `git rev-parse HEAD` 比对；或用 GitHub API `gh api repos/wuwiwo/MyHealth/branches/main --jq '.commit.sha'`。**不要**用 `git status -sb` / `rev-list --count` 判断。
- 推送成功后若本地 `origin/main` 仍是旧 SHA，按 §0.2.1 用 shell 写回 `.git/refs/remotes/origin/main`（`mkdir -p` + 写入真实远端 SHA），复核 `git status -sb` 恢复为 `## main...origin/main`。这是本地 ref 修复，不是代码文件。

## 3. 推送通道

- `git remote -v` 指向 `ssh://git@ssh.github.com:443/wuwiwo/MyHealth.git`；本环境 SSH 通道**间歇性失效**（普通 `ssh` / `git push` 偶发 `Permission denied (publickey)`，但 `ssh -v -i ~/.ssh/id_rsa -o IdentitiesOnly=yes` 能认证）。
- PortableGit 全局 `credential.helper = git-credential-manager.exe` 在非交互环境会干扰认证；单独 `http.extraheader` 推送报 `invalid credentials` / `could not read Username`。
- **可靠方式**：清空 helper 并改用 `gh` 自带 credential helper 经 HTTPS：

```bash
GIT_TERMINAL_PROMPT=0 git -c credential.helper= \
  -c 'credential.helper=!gh auth git-credential' \
  push https://github.com/wuwiwo/MyHealth.git main
```

- `gh auth status` 显示已登录 `wuwiwo`，token 带 `repo` / `workflow` 权限。
- ⚠️ `AGENTS.md:111` 写「本机未安装 `gh` CLI」是旧环境结论，本机实测可用；`doc/HANDOFF.md` 的 wrapper 说明仅适用于 Android SAF 环境。
