# 数据持久化与云同步

> 事实源：`page/store.js`、`page/sync.js`、`page/api/data.mjs`、`page/index.html`、`page/vercel.json`。
> 核对版本：`2.14.16` / `5e4d15c`。相关：[[10 测试与版本纪律]]、[[11 部署与运维]]、[[06 宝珠系统]]。

## 1. `store.js`：唯一写入 localStorage 的模块

- `registerSchema({ key, version, defaultValue, validate, migrate })`（`:68-76,255`）写入 `REG`；`SHAPES`（`:25-42`）隐式注册。
- **物理键规则**（`:18,65`）：`dh-` + 逻辑名 + `-v<version>`；另有 `-bak` 副本（`:66,92`）。
- 读时链路：`loadMigrated()`（`:122-164`）逐级 `migrate` → `validate`（`:80-84`）；损坏时备份成 `*-bak` + 写 `_migLog`（reason `corrupt-json` / `validate-fail`，`:131-150`）再回落 `defaultValue()`。**没有独立的 `corrupted` 布尔标记**，以 `-bak` + 日志表达。入站值复用同一迁移链 `upgradeIncoming()`（`:104-118`），不写 `-bak`。
- `getLastModTime()`（`:372`）读 `dh-mod-time`（`:21`）；`onChange`（`:268`）由 `set / mergeAll / setAll` 触发（后两者传 `'*'`，`:320,350`）；`schemaNames()`（`:361`）是同步 / 备份的**唯一键名真源**。
- **已注册 21 个逻辑键，全部 v1**：
  - 隐式 16 个：`strength, cardio, weight, plans, cardioPlans, missed, game, refine, attrLog, records, prs, exercises, cardioTypes, profile, theme, challenge`
  - 显式 5 个：`battleHistory`（`battle-history.js:24,91`）、`groupProgress`（`group-progress.js:13`）、`level`（`level-system.js:206`）、`pets`（`pet-store.js:9`）、`skills`（`skill-store.js:9`）
- `dh-pets-v1` 内部字段见 [[05 宠物系统]]；`data.orbSynth`（每日合成计数）放在 `pets` 对象内部，因此**不新增 store key** 也能随云同步走（见 [[06 宝珠系统]]）。

## 2. `sync.js`：导出 / 拉取 / 推送

- `sync.js` 是全局函数脚本，无 ESM / CJS 导出。
- `getAllData()`（`:206-212`）顶层：`version: 5`（`:208`）、`lastUpdated`、**14 个扁平字段**（`SYNC_FLAT_PROJECTION`，`:109-152`）与 `keys`；`api/data.mjs` 空库 GET 返回 `version: 1`（`:41`）。
- 近 7 天导出 `buildRecentData()`（`:460-499`）只保留 cutoff 过滤后的 `entries / cardio / weight` + `profile / exercises / userInfo / recentWeight(≤5) / missed / game / challenge / summary / days`；**不含 `keys`、`prs`、`records`、`attrLog`、`cardioTypes`、`refine`、`plans`**。
- 拉取：`apiGet()`（`:44`）→ `mergeServerData()`（`:231`，扁平 unpack + `mergeKeySection()` `:219`）→ `store.mergeAll()`（`:246`）。推送：`apiPut()`（`:29`）PUT `/api/data`；`MAX_RETRY = 2` + 指数退避（`:28-55`）。
- `keys` 派生：`collectOtherKeys()`（`:172`）用 `store.getAll()`（`:182`）+ `store.schemaNames()` 兜底（`:185-189`），按运行期 `carried` 排除（`:176`）。
- 另有 JSON 导出 / 导入；`scripts/test-sync-coverage.js` 由 `schemaNames()` 派生断言「每个注册键都在载荷内」。

## 3. `/api/data` 安全现状 ⚠️

- `page/api/data.mjs`：**GET / PUT 均无请求鉴权**；CORS `Access-Control-Allow-Origin: *`、方法 `GET,PUT,OPTIONS`、头 `Content-Type`（`:32-35`）；PUT 用 `BLOB_READ_WRITE_TOKEN`（`:57`），Blob `access: 'public'`（`:55`）。
- `cleanupOldBlobs()`（`:18-29`）`KEEP_LAST = 20`（`:4`），只保留最新 20 个快照。
- **已知风险**：任何人可读并可覆写云端存档。这是待修的独立任务，本套文档只登记事实，不改变现状。

## 4. 模块加载顺序（`page/index.html`）

- 当前缓存戳 **`?v180`**（`:8` CSS、`:283-340` 脚本），共 **55** 个 `<script>` 标签，其中 **54** 个 `<script src>` + 1 段内联 `init()`（`:341`）。
- `store.js` 最先（`:283`）；`utils.js` 早于所有依赖 `APP_VERSION` / 日期工具的模块；`skill-icon.js` 必须早于 `game-render.js`（`:292-295`）；`monster-archetype.js` 在 `levels.js` 之后（`:290`）。
- ⚠️ `debug.js` 在 `:339` **并非最后**：其后还有 `codex.js`（`:340`）与 `init()`（`:341`）。旧文档「debug.js 最后」的说法不准确。
- 运行时函数守卫的必要性：`challenge.js` 早于 `pet-ui.js` 加载，结算面板用 `typeof orbIconHtml === 'function'` 守卫，见 [[06 宝珠系统]]。

## 5. 与旧文档的差异

`CONTEXT.md` 旧版写同步顶层对象为 `version: 4` 且列出 `entries, plans, missed, cardio, weight, cardioPlans, cardioTypes, game, exercises`（无 `keys`）；现行是 **`version: 5`** + `SYNC_FLAT_PROJECTION` 14 字段 + `keys`。完整对照见 [[12 术语表与过时文档对照]]。
