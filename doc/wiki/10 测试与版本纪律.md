# 测试与版本纪律

> 核对版本：`2.14.16` / `5e4d15c`。相关：[[11 部署与运维]]、[[08 数据持久化与云同步]]、[[09 UI 设计体系与无障碍]]。

| `test-orbs.js` | 宝珠数值、等价碎片分解、每日合成、跨日重置、`randomOrbType()` 覆盖 |

- **全量回归命令**（`doc/HANDOFF.md` §8，`:648,658`）：逐套件跑 `scripts/test-*.js` 并**以实时结果为准**；`§8.1`（`:660-676`）定义 F1~F5 五种结果格式。

- ⚠️ `scripts/check-release.js` 在本沙箱会报「pre-commit：无法调用 git（execSync 失败）」，并明确 **「未执行 ≠ 通过」**；版本发布三项必须人工核对，不能因脚本告警就当作通过。

## 2. 提交纪律（`AGENTS.md:66-76`）

| 阶段 | 判定 | 提交 | 版本发布三项 |
|---|---|---|---|
| **施工阶段** | 改 `page/*.js`、`page/index.html`、`page/index.css`、部署 / 运行配置或 `APP_VERSION` | 每次修改提交（`fix:` / `feat:`） | **触发** |
| **设计阶段** | 仅改设计文档 / README、CONTEXT 的文档性说明 | 每次修改提交，`docs:` 前缀 | **不触发** |

- 本套文档属于**设计阶段**：只动 Markdown，用 `docs:` 提交，**不** bump `APP_VERSION`、不生成 changelog、不动架构演化表。
- 并行会话纪律（`AGENTS.md:91-105`）：动工前查工作树、`git log --oneline -5`、HEAD；只提交本任务文件，不纳入他人的改动或历史临时文件。若他人已把改动 `git add` 进索引，用路径限定提交 `git commit -m "..." -- <自己的文件>` 绕过索引。

## 3. 版本发布三项（`AGENTS.md:30-62`）

1. **`README.md`**：顶部副标题版本号、版本表新增行、目录树、当前版本指向最新 changelog。
2. **`doc/changelog-vX.X.md`**：按 `## vX.X.X` 分节，三分类「新增功能 / 修复 / UI 调整」，只写当前版本，列出新增 / 删除文件。
3. **架构演化表**（changelog 底部）：文件数 = `page/*.js` 数量，最大文件 = 行数最多的 `page/*.js`，且保留 v1.0 至今全部历史行。

- 当前 `APP_VERSION = '2.14.16'`（`page/utils.js:5`）；README 版本表最新行 `2.14.16 / 2026-11-04`；`doc/VERSION-LEDGER.md` 下一个可用版本 **`2.14.17`**。
- 架构演化表最新行（`doc/changelog-v2.14.md:985`）：`| 2.14.16 | 53 | 3314 行 game-render.js |`；`:992` 现场复核 53 个 `page/*.js`、最大 `game-render.js` 3314 行、次席 `battle-group.js` 2190 行。
- 施工阶段改代码必须**同次**完成 bump、README、changelog、架构表、cache-busting，不得先落代码再决定 bump。

## 4. 并行 / 实时状态确认

- `doc/HANDOFF.md` §0.2.1（`:111-155`）：本环境沙箱会静默丢弃 `.git/refs/remotes/**` 的写入 → `git status -sb` 的 ahead / behind 数字**不可信**。确认是否已推送用 `git ls-remote origin refs/heads/main` 与 `git rev-parse HEAD` 比对两个 SHA，禁用 `rev-list --count`。详见 [[11 部署与运维]]。
