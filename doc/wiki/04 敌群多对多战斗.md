# 敌群多对多战斗

> 事实源：`page/group-levels.js`、`page/battle-group.js`、`page/group-progress.js`、`page/enemy.js`、`page/unit.js`、`page/talent.js`、`page/skill.js`、`page/status-defs.js`、`page/state-core.js`、`page/terrain.js`、`page/ai.js`、`page/game-render.js`、`page/game-battle.js`、`page/battle-history.js`、`page/fx-semantics.js`。
> 核对版本：`2.14.16` / `5e4d15c`。
> ⚠️ 与 [[02 关卡试炼与单敌战斗]] 是两套独立关卡。参战阵容来自 [[05 宠物系统]]，属性放大受 [[06 宝珠系统]] 与 [[07 玩家技能与媒体资源]] 影响。

## 1. 关卡结构

- **24 大关 × 10 小关 = 240 关**：`GROUP_MAX = 24`（`group-levels.js:29`），循环生成于 `:421-443`；ID `g{lg}-{st}`，大关键 `g{lg}`。
- 精英 `st = 5`、Boss `st = 10`（`:393-394,424`）。
- 每关敌人上限 `lg <= 2 ? 2 : 3`（`:395`）；编成：Boss 关 1 Boss + 2 护卫，精英关 1 精英 + 2 杂兵，普通关 `st <= 3` 为 1 敌、`st = 9` 为 3 敌（`:398-412`）。
- **程序化生成**（非静态表）：`groupHash / groupRng` 按 `(lg, st, slot)` 播种，同关配置恒定（`:120-133,277`）。
- tier 5 档 `minion / elite1 / elite2 / elite3 / boss`（`enemy.js:12-18`）；`lvScale`（`group-levels.js:273`）；g13+ 加压 1.45、g16+ 斜率 1.24（`:39-49`）。

## 2. 解锁与进度

- `group-progress.js`：物理键 `dh-groupProgress-v1`，默认 `{ version: 1, cleared: [] }`（`:5-20`）。
- `g1-1` 恒解锁，其余要求前一关在 `cleared` 中（`:60-69`）；`markGroupStageCleared()` 去重 push，返回 `firstClear / nextStage`（`:72-84`）。
- `currentGroupStageId()`（`game-render.js:775-781`）= `allStageIds` 中首个未通关关，全通返回末关。**无回退函数**；仅 `debug.js:312-328` 提供两步确认清空 `cleared`。
- 通关后锁定不可重打；解锁链完全由 `cleared` 派生。

## 3. 参战阵容与开战入口

- `PET_BATTLE_MAX = 4`（`pet-store.js:301-303`）；`_petBattlePicks` 源自 `dh-pets-v1.battlePicks`；`ensurePetBattlePicksLoaded()`（`game-render.js:755-770`）、`savePetBattlePicks()`（`pet-store.js:270-275`，`slice(0,4)`）。
- 阵容 = 玩家（`spd = 10`）+ `buildGroupBattlePets()`（`game-render.js:830-836`）；`GROUP_INHERIT = 0.50`、`PET_GROUP_SCALE = { R:1200, SR:1400, SSR:1500, UR:1600 }`（`group-levels.js:62-65`）。
- 调用链：`game-views.js:196` / `pet-ui.js:590` → `startGroupTrialWithPets()`（`pet-ui.js:1150-1157`，写 picks + save）→ `startGroupTrial()`（`game-render.js:784`）。
- UI 入口：培养页 `#trainStartBattle`（`game-views.js:119-120`）、`game-render.js:161`、`pet-ui.js:587-590`。开战唯一入口取 `currentGroupStageId()`，不另建战斗对象。

## 4. 群战引擎

- **行动队列**：先制档降序 → 同档 `effectiveSpeed` 降序（嘲讽 ×2）→ 同速我方先 → 创建序（`battle-group.js:564-577,389-394`）；反转场地改速度序、先制不受影响（`:401-404`）。
- **四阶段** `GB_PHASES = ['准备','行动','判定','结束']`（`:1453`）：准备 `:1596-1684`（含 `predeclareActions`）、行动 `:1722-1732`、判定 `:1776-1788`、结束 `:1791-1828`。`tick` `:2095-2104` / `step` `:2137-2182` 共用 helper，`step` 一次推进一个单位（`:2174`）。
- **胜负** `checkGroupWin()`（`:1583-1590`）：先判我方全灭 → `'enemy'`，再判敌方全灭 → `'ally'`；敌方全灭后覆盖，因此**双 KO 判我方胜**（`:1576`）。
- **Prepare 阶段一方灭队立即结束且不再行动**（`:1668-1674`）。
- **auto 连战**（v2.14.15）：`NEXT_MS = 1400` / `STEP = 700` / `BUBBLE = 900ms`（÷ 速度）（`game-render.js:477-483,934,939`）；guard rollback 校验「新战斗对象 / 未 done / `stageId === next`」，失败回滚 `_groupStageId` / `_groupRewarded` 并停止、绝不重试（`:727-744`）；每关幂等靠 `_groupRewarded`（`:502,1708`）+ `gb._historyId`（`:1974`）。终止条件：败不重试、无下一关、暂停 / 离视图 / 页面隐藏 / 切 tab（`:575-616,676-696`）。

## 5. 战斗数值

- `BASE_HIT_RATE = 0.95`（`:152`）；`groupHitChance = 0.95 + _accMod − (_eva + _evaPerm) + 潮湿 0.30`，clamp `[0.05, 1]`（`:155-179`）；`groupRollHit = gb.rng() < chance`（`:182-184`）。
- 暴击：斗者本能 30% / 150%、玩家 30% / 300%、宠物 15% / 160%，分别判定取最高、只结算一次（`:210-224`、`skills.js:38`）；**技能不暴击，普攻保留**（`:777,1088-1094`）。
- 伤害 `max(1, atk − floor(def/2) + floor(rng×4) + 1)`（`:719`）；魂伤 `sDef > 0` 同式，否则全额（`:816`）；蓄力重击 400%（`:70,77`）。
- `overkill` 基数 = 实际掉血 `hpBefore − hp`（`:800-807`、`skill.js:30-37`）；护盾对物理与魂伤均先吸收（`:48-55,795,832`）。
- ⚠️ 沙暴描述里的「命中 −20%」只在 `terrain.js:86` 的 desc，`groupHitChance` 未读 terrain → **落地未确认**。

## 6. 场地（6 种，敌我全场）

均作用于 `gb.units` 全体（`terrain.js:3`、`battle-group.js:1624-1625`）；g3 起每大关按种子选 1（`group-levels.js:173-181`）；每回合 `onTurnStart` / `onTurnEnd` 各结算一次（`:1626,1809`）。

| 场地 | 效果 |
|---|---|
| 沙暴 | 回合末随机 2 名受 `maxHP × 5%` 碎石，按 def 排名减 50% / 25% / 35%（`:83-107`） |
| 雪天 | 治疗 −50%，每 5~7 回合随机 1 人冰冻（`:110-134`） |
| 酷暑 | 回合末全体 4% + 每次普攻后攻击者 `maxHP × 2%`（`:141-153,694-701`） |
| 雨天 | 15% 潮湿；潮湿者受 `maxHP × 7%` 闪电，按 soulDef 减 60% / 35% / 45%（`:156-186`） |
| 反转场地 | 速度最低者先手（`:188-197`） |
| 毒气 | 第 5 回合起 35% 中毒 2 回合，3 次免疫，治疗 −75%（`:199-226`） |

## 7. 天赋 / 技能 / 状态

- 天赋注册 **14 条**（`talent.js:195`），敌群技能 **25 条**（`skill.js:332-619`）；技能池 `SKILLS_HIGH 18 / LOW 6`（`group-levels.js:256-267`）。
- hook 框架 8 个：`onApply / onExpire / onTurnStart / onTurnEnd / onBeforeAction / onAfterAction / onDamage / onHeal`（`state-core.js:13`、`talent.js:10`）；扩展 hook 另有 `onBeforeHit / onBeforeCrit / onBeforeSupport / onBeforeStatus / onBeforeHeal / onBeforeSupportEffect / onAllyDamage / onAllyStatus / onFoeHeal / onBattleStart / onAfterDamage`。
- 冷却 `counters.cd`，`cooldown` 2~8 回合（`skill.js:46-63`）；`startCooldown` 仅 lastword = 10（`:591-592`）；`applyStartCooldowns` 在 `createUnit()`（`unit.js:35`）；`tickSkillCooldowns` 在行动阶段、附身暂停（`battle-group.js:2042`）。先制度 `priority: 1` 仅 surprise / deepfreeze / possess（`:342,393,469`）。
- `talentDispatch()`（`talent.js:115`）在 `battle-group.js` 被调 24 处、`terrain.js:125`、`pet-codex.js` 1 处；`talentAura()`（`battle-group.js:187`）调用点在 `:254,1261,1304,2074,2075`。
- 状态 `status-defs.js` **23 条** `defineStatus` + `state-core.js` 内置 sleep 1 条 = **24 种**（`:296-323`）；`grade` 1 = 普通 / 2 = 高级 / 3 = 特级（`status-defs.js:4`）；`cleanseNegatives` 默认 `maxGrade = 2`（`state-core.js:191-198`）。战斗路径用 `ageStatuses` 而非 `tickStatuses`（`:103-106`）。

## 8. 战斗历史与演出语义

- `battle-history.js`：KEY `battleHistory`、`VERSION = 1`、`LIMIT = 100`、物理键 `dh-battleHistory-v1`（`:23-29`）；末尾最新、FIFO 丢最旧、同 id 幂等、回读物理键校验落盘。摘要字段 `id / endedAt / mode / stageId / result / rounds / metrics[playerDealt,playerTaken,playerHealed,terrain,dot,shield] / party[name,dealt,taken,healed,alive] / note`（`:129-132`）。
- **只记账、不判胜负**，不参与胜负 / 奖励 / 进度（`:8`）；`result` 由 winner 映 `win/loss`（`game-render.js:1985`）；`note` 仅同名单位时为「本场存在同名单位：按首个同名单位归因」（`:1996-1997`）。
- `fx-semantics.js` 三层：① `fxMarkForStatusId`（13 条稳定 id 映射，`:29-43`）② `fxMarkForText`（文案兜底）③ `fxMarkForEvent` 先 id 后文案、都无 → `null`，**绝不按 type / 关键词猜**（`:13-16,100-123`）。闭集自检 `fxUnregisteredStatusIds`；`FX_EXCLUDED_STATUS_IDS` 11 条带理由排除；严重度只有 `routine / notable / major`（`:22-23,138-160`）。

## 9. 奖励与掉落

- 胜：技能点基数 `4 + 周内 min(2.5, 胜局 × 0.5)` → 4 / 6 / 8 / 10 / 12 / 14 封顶，唯一源 `skill-store.js` 的 `SKILL_POINTS_PER_STAGE`（`game-render.js:1801-1809`）。
- 材料：营养液 1~2 / 饲料 1~3；敌数 ≥3 加炼化石 1，≥4 加灵能 1~2（`:1810-1817`）；套 `applyDropMults`（宝珠碎片 ×3 / 炼化石 ×2 / 灵能 ×2，`:1818-1824`）；幸运口袋（`:1825-1836`）；`grantMaterial` 落地（`:1838`）。
- 败：无奖励，成熟宠物 50% 概率受伤 `applyDefeatInjuries()`（`:1749-1757`）。

## 10. 已确认裁决（代码层）

- 单敌魂伤过护盾：`battle.js:213-222`。
- 荆棘反伤基数 = 护盾吸收前 `pDmg`（post-affix）：`battle.js:30-31,193-203`。
- Prepare 一方灭队立即结束：`battle-group.js:1668-1674`；双 KO 我方胜：`:1583-1590 / 1806-1808`。
- 场地被动作用于敌我全场、从 Prepare 阶段启用：`terrain.js:3`、`battle-group.js:1624-1625`、`game-render.js:852`。
- `doc/2.0 敌群设计.md` 是历史设计稿，不作事实源：例如「威吓」文档只写「施加者 <50%」，代码另加 5~10 回合随机先到者解除（`talent.js:342-389`）。
