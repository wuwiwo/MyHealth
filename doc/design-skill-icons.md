# 技能图标像素设计规格（v2.3.2）

> 目标：为**玩家技能 10 个**（`page/skills.js`）与**敌方技能 25 个**（`page/skill.js`）各绘制一枚
> **1:1、48×48 像素、像素风格**图标 SVG。
> 策略：**逐技能各一枚（共 35 枚）**——不归纳原型（与怪兽套的判据不同，见 §0）。
> 数据来源：`page/skills.js`、`page/skill.js`。
> 参照：`doc/design-pet-icons.md`、`doc/design-monster-icons.md`（本文件沿用其全部硬约束，
> 以便复用同一套校验脚本与光栅化器）。

---

## 0. 为什么这一套「逐技能各一枚」，而怪兽套要归纳原型

两套的判据**不同**，原因是数据性质不同：

| | 怪兽头像 | 技能图标 |
|---|---|---|
| 数量 | 189 个唯一敌人名 + 21 个敌群名 | **35 个技能**（玩家 10 + 敌方 25） |
| 名字与造型的关系 | **大量名字是同一造型的换词** —— `永恒壁垒` / `终极壁垒` / `星核壁垒` / `冥河壁垒` 在 16×16 下必然同构，逐名绘制只会得到十余枚几乎一样的方盾 | **每个技能的语义都不同** —— `暴击` / `治愈` / `冰冻三尺` / `地刺` / `暴风雪` 是各自独立的视觉概念，归纳会把本来能区分的图标压成同一个 |
| 增长性 | 项目仍在扩章（`GROUP_MAX` 18→21→24，已到 chap33），逐名映射每加一章都要新画 | 技能表由代码注册，**改动频率低**；新增技能时补一枚即可 |
| 归纳的收益 | 高（189 → 18，且去重目标本来就无法达成） | **低**（35 → 约 13，但会牺牲真实可辨识度） |

结论：**怪兽套归纳是因为「不归纳就无法去重」；技能套不归纳是因为「归纳会丢掉真实差异」。**

> ⚠️ 但**去重仍然是硬指标**：35 枚里有大量视觉近邻（`vitality` 与 `heal` 都是治疗十字、
> `meteor` / `boulder` / `stardust` 都是「自天而降的东西」、`block` / `fortify` / `bulwark`
> 都是防御），**必须靠形状而非颜色区分**（见 §3 去重红线）。

## 1. 统一技术规范（硬约束，逐条校验）

> 本节与 `doc/design-pet-icons.md §1`、`doc/design-monster-icons.md §1` **完全一致**，
> 目的：三套图标的校验脚本共用同一套判定逻辑。

### 1.1 画布与网格

| 项 | 值 |
|---|---|
| SVG 根标签 | `<svg xmlns="http://www.w3.org/2000/svg" width="48" height="48" viewBox="0 0 48 48" shape-rendering="crispEdges">` |
| 逻辑网格 | **16 × 16** 格 |
| 单元格尺寸 | **3 × 3**（px） |
| 坐标取值 | 所有 `x` / `y` / `width` / `height` **必须是 3 的倍数**，范围 0~48 |
| 背景 | **完全透明**，不画背景矩形、不画圆角底、不画边框 |

### 1.2 绘制方式（强制）

**必须用 ASCII 字符草图先定轮廓，再映射为 `<rect>`。**

- 在 SVG 内以注释形式保留 16×16 字符草图，便于复核；
- 每个字符 = 一个调色板键，映射为一个或多个 3×3 的 `<rect>`；
- **允许合并**同一行中相邻同色格为一个更宽的矩形（宽为 3 的倍数），以压缩文件体积；
- 只使用 `<rect>`（可选 `<title>` 作无障碍标签），**禁止** `<path>` / `<circle>` / `<ellipse>` /
  `<polygon>` / `<text>` / `<image>`。

> ⚠️ 技能图标是**符号**而不是**角色**，没有「脸」「身体」这类自然轮廓可依托，
> 因此**形状的正确性要求比宠物 / 怪兽更高**。ASCII 草图不是可选项。

### 1.3 颜色约束

- **纯扁平色**，禁止渐变（`<linearGradient>` / `<radialGradient>`）、禁止滤镜（`<filter>`）、
  禁止 `opacity` / `fill-opacity` / `stroke` / `stroke-width`；
- 每个图标**最多 8 种** hex 颜色（含描边色）；
- 描边统一使用 `K = #23262E`，用于外轮廓与五官，全 35 枚**必须一致**；
- **描边占比目标 ≤20%（软目标，允许例外）**：描边是「轮廓」而非「主体」，占比过高会让图标读作
  深色块。但**这是软目标而非硬门槛**，某些符号天然需要更多描边（细长武器、镂空结构、密集五官）。
  **判定原则：只要主体形状可读，占比超标可接受**；若主体读不出来，先改几何。
- 高光统一使用 `W = #FFFFFF`；
- 主体色按 §3 各技能专属调色板，**不得跨技能换色**。

> ⚠️ **深色主题可读性（硬指标）**：应用默认主题为**深色**，卡面底色 `--bg2 / --surface = #111827`。
> 宠物套的 `darkcrow` 曾在 v2.2.29 踩过隐形（主体 `#0B0D12` 对卡面只有 **1.10:1**，几乎不可见）；
> 怪兽套的 `lord` 在 v2.3.1 又踩了一次（主体袍服 `#3A2352` 对卡面 **1.30:1**，
> 卡面上只能看到一顶「飘着的金冠」）。
>
> 因此本套要求：**每个图标在深色卡面 `#111827` 与浅色卡面 `#ffffff` 之下，各自都至少有一种颜色达到 3:1。**
>
> ⚠️ **两种主题允许用不同的颜色。** 不要误写成「同一种颜色必须同时满足两边」——那是**过严**的：
> 深色卡面要求颜色够亮、浅色卡面要求颜色够暗，除中间灰外没有颜色能两边都达 3:1，
> 会误杀「亮主体 + 深描边」这类完全正确的设计。
>
> ⚠️ **必须逐色核对「主体」而不是只数「可读色个数」**：`lord` 的教训是它的「深色可读色 2」
> 由**装饰件**（金冠、立领）撑起，主体袍服本身不达标 —— 达标色在装饰件上等于没达标。
>
> 判定公式（WCAG 相对亮度）：
> `lin(c) = c<=0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`，
> `L = 0.2126R + 0.7152G + 0.0722B`，`contrast = (max+0.05)/(min+0.05)`。

### 1.4 构图

| 项 | 值 | 理由 |
|---|---|---|
| 主体包围盒 | **≥30×30 px（10×10 格）** | 接入尺寸 32px 下，不足 10 格宽的主体辨识度骤降 |
| 视觉重心 | 居中，四周留 ≥1 格透明边距 | 图标不带自己的背景，贴边会在卡片里显得拥挤 |
| 显示尺寸 | **必须是 16 的倍数** | 48→3px/格、32→2px/格（干净）；**24 不是 16 的倍数**（1.5px/格，会出现粗细不均） |
| 接入尺寸 | **32px**（与宠物套 / 怪兽套统一） | 卡片与芯片行的一致性 |

> **符号类图标特别要求**：主体应尽量填满 16×16 网格的中部（约 12×12 区域）。
> 与「角色」不同（角色有四肢可以贴边），符号画小了会在 32px 下变成一个小点。

## 3. 逐技能绘制提示词

> 每条的格式：**形象描述 / 像素化要点 / 调色板 / 构图草图指引 / 去重红线**。
> 调色板沿用宠物套与怪兽套的既有色值，**尽量不引入新色**。

### 3.1 crit — 暴击

**形象描述**：三道平行的斜向锐利爪痕，自左上划向右下，末端变细。爪痕周围散布放射状的红色星芒点，传达「瞬间爆发」。

**像素化要点**：
- 三道爪痕**等距**（相隔 2 格），每道由 3~4 段阶梯构成，**上端宽下端窄**（宽 1 格收成 1 格但斜向）；
- 爪痕用亮红 `#E8453C`，外沿包描边；
- 星芒用 4 个单格点（`#FF8A80`），分布在四角，**不要对称**（对称会读成装饰图案）；
- 主体占满中部 12×12 区域。

**调色板**：`K #23262E` 描边 · `R #E8453C` 爪痕 · `r #A82820` 爪痕暗部 · `W #FF8A80` 星芒点。

**构图草图指引**：爪痕 x 4~12、y 3~13；星芒点散布在 (2,3) (13,5) (3,12) (12,13)。

**去重红线**：**必须有三道平行斜痕**（不是一道、不是交叉）；不得出现盾牌（→`armorbreak`）；不得出现手掌（→`surprise`）。

### 3.2 vitality — 气力恢复

**形象描述**：一个粗壮的绿色治疗十字（十字臂等宽），十字周围有 4~6 个上升的浅绿粒子点。

**像素化要点**：
- 十字 **臂宽 2 格**、整体 **7×7 格**，居中；
- 十字用亮绿 `#4CAF50`，中心 1 格用更亮的 `#8BC34A` 做高光；
- 粒子点**只在十字的上半部**（传达「上升」），下方不画；
- 十字四角留出透明，避免读成方形块。

**调色板**：`K #23262E` 描边 · `G #4CAF50` 十字 · `g #2E7D32` 十字暗部 · `W #8BC34A` 高光与粒子。

**构图草图指引**：十字 x 5~11、y 5~11（臂宽 2）；粒子在 y 2~4 分散。

**去重红线**：**必须是绿色**（敌方 `heal` 是白色，这是首要区分点）；粒子必须只在上半部；不得画成盾牌。

### 3.3 meteor — 陨石轰炸

**形象描述**：一块**不规则**的燃烧陨石自左上角斜落，右侧拖着火焰尾迹，底部有撞击产生的火星四溅。

**像素化要点**：
- 陨石块是**不规则多边形**（不是圆、不是方），约 5×5 格，用暗棕 `#6B4A2F` + 亮面 `#A56A44`；
- 尾迹自石块的右上方向左上方延伸，用 3~4 段**逐渐变窄**的橙色 `#FF8C42`；
- 火星在石块右下，4~5 个单格点，用 `#FFD166`；
- **斜向**是它的核心识别特征（区别于垂直下压的 `boulder`）。

**调色板**：`K #23262E` 描边 · `S #6B4A2F` 石 · `s #A56A44` 石亮面 · `F #FF8C42` 火焰尾 · `W #FFD166` 火星。

**去重红线**：**必须正立且有贯穿锯齿裂纹**；不得倾斜（→`block`）；不得画成砖墙（→`fortify`）。

### 3.21 stardust — 星辰坠落

**形象描述**：一颗五角星自上垂直落下，下方拖着一条由密到疏的星尘轨迹。

**像素化要点**：
- 五角星**必须画成五角**（不是四角、不是六角），对角 7 格，居中偏上；
- 星体用亮黄 `#FFD166`，中心 1 格 `#FFFFFF`；
- 轨迹在星体**下方垂直**，由 4~5 段**逐渐变窄且变淡**的横条构成（`#F0D97A` → 越往下越短）；
- 轨迹两侧散 4 个星尘单格点。

**调色板**：`K #23262E` 描边 · `W #FFD166` 星 · `w #FFFFFF` 星心 · `y #F0D97A` 轨迹。

**构图草图指引**：星心 (8,6)、半径 3.5；轨迹 y 10~15 垂直向下收窄。

**去重红线**：**必须是五角星且垂直下落**；不得画成不规则石块（→`meteor`）；不得画成六角雪花（→`blizzard`）。

### 3.22 shrink — 变小

**形象描述**：左右两个向内指的箭头夹住中央一个正在缩小的方块，方块周围有收缩的虚线框。

**像素化要点**：
- 左右两个箭头**水平向内**，各长 4 格，用 `#8F6FD0` 紫；
- 中央方块 3×3 格，用 `#C0A8E8` 浅紫（表示「正在变小」的实体）；
- 方块外围有一圈**虚线框**（4 段短横线，间隔 1 格），用 `#8F6FD0`，表示「原来的大小」；
- 上下各 1 条短横线加强「压缩」感。

**调色板**：`K #23262E` 描边 · `V #8F6FD0` 箭头与虚线 · `v #C0A8E8` 中央方块。

**构图草图指引**：左箭头 x 1~4、右箭头 x 11~14、y 7~9；方块 x 6~9、y 6~9。

**去重红线**：**必须左右箭头向内**；不得画成向外扩张（画反了就变成「放大」）；不得画成上下箭头。

### 3.23 yawn — 哈欠

**形象描述**：一张张开的椭圆形大嘴（深色口腔），右上方漂浮着一个 Z 字，表示困倦。

**像素化要点**：
- 嘴是**竖向椭圆**（高 8 格、宽 6 格），外沿用 `#C98A5E`（唇），内部用 `#3A1414` 深红；
- 口腔内**不画牙齿**（这是与 `bite` 的核心区分 —— `bite` 有獠牙，`yawn` 是空洞的）；
- Z 字在右上角，由 **3 段折线**构成（上横、斜、下横），用 `#7FD4FF`；
- Z 字**必须大于 3 格高**，太小会看不见。

**调色板**：`K #23262E` 描边 · `S #C98A5E` 唇 · `r #3A1414` 口腔 · `C #7FD4FF` Z 字。

**构图草图指引**：嘴 x 3~8、y 4~12；Z 字 x 11~14、y 2~5。

**去重红线**：**口腔内不得有牙齿**（→`bite`）；**必须有 Z 字**；不得画成幽灵（→`possess`）。

### 3.24 drench — 打湿

**形象描述**：三滴水珠自上落下，下方是一片被浸湿的痕迹（波纹状）。

**像素化要点**：
- 三滴水珠形状**必须是水滴形**（上尖下圆），高度各 3~4 格，**大小不一、左右错落**；
- 水珠用 `#7FD4FF`，高光 1 格用 `#C8F0FF`；
- 下方湿痕是 **3 条水平波纹线**（长短递减），用 `#3AA8C9`；
- 湿痕的宽度要**大于水珠的总跨度**，表示「扩散」。

**调色板**：`K #23262E` 描边 · `C #7FD4FF` 水珠 · `W #C8F0FF` 高光 · `c #3AA8C9` 湿痕。

**构图草图指引**：水珠分别在 x 4 / 7 / 10，y 1~5；湿痕 y 11~14、x 2~13。

**去重红线**：**必须是水滴形（上尖下圆）**；不得画成圆形球（→`snowball`）；不得画成雪花（→`blizzard`）。

### 3.25 possess — 幽魂附身

**形象描述**：一个幽灵的轮廓（圆头 + 锯齿下摆），左侧有一个指向幽灵内部的箭头，表示「附身」的动作。

**像素化要点**：

- 箭头自左侧水平指向幽灵**中心**，长 4 格，用 `#8F6FD0`；
- 幽灵边缘要**比箭头亮**，保证主体可读。

**调色板**：`K #23262E` 描边 · `V #C0A8E8` 幽灵 · `v #8F6FD0` 箭头 · `d #3A2560` 眼睛。

**构图草图指引**：幽灵 x 6~13、y 4~13（锯齿下摆在 y 12~13）；箭头 x 1~5、y 8~9。

**去重红线**：**必须有无腿的锯齿下摆**；不得画成有牙的嘴（→`bite`）；不得画成雾气团（→`blackmist`）。

### 3.26 taunt — 嘲讽

**形象描述**：一张愤怒挑衅的脸 —— 两道下压的怒眉 + 两只眼 + 下方一条伸出的舌头（挑衅手势）。

**构图草图指引**：怒眉 y 3~4；眼 y 6~8；舌 x 7~9、y 10~13。

**去重红线**：**必须有怒眉 + 舌头**；不得画成治疗十字；不得画成爪痕（→`crit`）。

### 3.27 doom — 末日

**形象描述**：一个沙漏，上格装满沙子、下格已堆积一部分，顶盖和底盖是平直的横条。

**像素化要点**：

### 3.28 drainbuff — 摄取

**形象描述**：一支向上的粗箭头自下方目标中抽取能量，箭头与目标之间有流动的能量颗粒。

### 3.29 bulwark — 广域防御

**形象描述**：一道宽阔的弧形屏障罩住下方，屏障内部有三个人形/单位的小点，表示「保护多个」。

**像素化要点**：

### 3.30 cleanse — 净化

**形象描述**：一圈环形净化波向四周扩散，波的中心把几个暗色的污点推出去。

**像素化要点**：

- 环之间留 1 格透明（形成「波」的层次）；
- 4~5 个**暗色污点**（单格，`#5B3A8C` 或 `#3A1414`）分布在环外，且**离环的距离不同**（表示被推开的过程）；

**调色板**：`K #23262E` 描边 · `W #C8F0FF` 外环 · `C #7FD4FF` 内环 · `d #3A1414` 污点。

### 3.31 heal — 治愈

**形象描述**：一个白色的治疗十字，外圈环绕着一圈金色的光晕点，传达「恢复」。

**像素化要点**：

### 3.32 empower — 强攻

**形象描述**：一支向上的红色强化箭头，箭头前方（上方）叠加一把剑的剪影，表示「攻击力提升」。

### 3.33 lastword — 遗言

**形象描述**：一块圆顶墓碑立在画面下方，上方漂浮着几个升起的白色光点，表示「最后的话」。

## 4. 交付与验收

### 4.1 交付物

| 产出 | 路径 |
|---|---|
| 图标 SVG × 48 | `page/media/skills/<skillId>.svg` |
| 渲染模块 | `page/skill-icon.js`（唯一入口） |
| 预览画廊 | `page/media/skills/preview.html` |
| 校验测试 | `scripts/test-skill-icons.js` |

> ⚠️ **命名冲突风险**：三套 id 空间是独立的（`PLAYER_SKILLS` / `SKILLS` / 宠物 `p_*`）。
> 当前 48 个 id **无重名**（已核对），但渲染模块仍应**显式区分来源**，
> 防止将来某天出现同名 id 时静默取错图标。
>
> ⚠️ **`isPlayer === false` 必须同时认敌方表与宠物表**：
> 宠物技能注册在同一个 `SKILLS` 里，战斗中由同一段 `renderUnitSkillChips` /
> `showSkillDetail` 渲染，那些调用点会显式传 `false`。
> 若这里只认敌方表，宠物技能被判非法 → 界面**空白图标**（静默降级）。
> 这是 v2.3.2 测试实际抓到的缺陷，已在 `page/skill-icon.js` 与测试里加注释固定。

### 4.2 验收标准

每个图标必须**逐条**满足：

1. `<svg>` 根标签含 `width="48" height="48" viewBox="0 0 48 48" shape-rendering="crispEdges"`；
2. 只使用 `<rect>`，**无** `<path>` / `<circle>` / `<ellipse>` / `<polygon>` / `<text>` / `<image>`；
3. 所有 `x` / `y` / `width` / `height` 都是 **3 的倍数**且在 0~48 内；
4. 颜色数（含描边）**≤8**；
5. 每个 `<rect>` 的 `fill` 只接受：
   - 全局描边色 `#23262E`
   - `#FFFFFF`
   - 允许的调色板色值集合（见 §3）
6. 无 `fill-opacity` / `opacity` / `stroke` / `stroke-width` / `<linearGradient>` / `<filter>`；
7. 主体**包围盒 ≥30×30 px**；
8. 在深色卡面 `#111827` 与浅色卡面 `#ffffff` 之下，**各自**至少有一种颜色达到 **3:1**；
9. 文件大小 <6KB。

### 4.3 复核流程

- 复核维度：**尺寸合规 / 符号可辨识 / 同族去重 / 形象还原度**

### 5.3 方法论教训（本轮新增，务必保留）

#### ① ASCII 反打 ≠ 可读，两步都必须做

**ASCII 反打只能证明「我画的格子和我以为的一致」**，
**不能证明「这个图形在 32px 下能被认出来」**。
两者是不同类的错误：

| 步骤 | 能抓到的错误 | 抓不到的 |
|---|---|---|
| ASCII 网格反打 | **几何错误**（某格画了没有、位置偏了、形状不闭合） | 语义——形状对但读不出意思 |
| 6× 光栅化目视 | **语义错误**（在读成别的东西） | — |

本轮实例：`vitality` 的 ASCII 是个漂亮的菱形，光栅化后是「绿色椭圆」；
`crit` 的 ASCII 是放射星芒，光栅化后是「红色蜘蛛」；
`spotlight` 是「金色漏斗」。

**结论：逐枚图标必须走完「ASCII 反打 → 6× 光栅化目视 → 1:1 双主题确认」三步。**

#### ② `dilateOutline`（膨胀描边）—— 本轮最有价值的工具

给形状**外圈**加 1 格黑边，而**形体像素逐字节不变**。
解决了「细/渐细形状被逐格描边吃掉」的问题（`spikes` 的锥尖、`charge` 的 V 形带）。

两条使用边界：
- **1 格宽的孤立特征会变成「孤岛」** —— 必须 ≥2 格（`spikes` 的尖端曾因此变成浮在黑框里的点）；
- **陡峭的凹角会被邻格膨胀填掉** —— 星形这类凹形要改用「先画放大的描边色形体，再画本体」两层法（`stardust` 曾因此变成「金团子」）。

#### ③ 单色系 + 多块拼接 + 膨胀描边 = 必然碎裂

`p_shadowfist` 连改 8 版才摸清这条：
在同一色系（如紫 `#A87BDC`/`#CBAAF0`/`#6B4A9E`/`#EFE2FF`）里做多块拼接，
**四色明度相近**，`dilateOutline` 给每块各加 1 格黑边后，
所有块被黑边切碎成独立小方块，整体读作「紫色马赛克」。

**对策（二选一）**：
- 拉开明度（`p_shine`/`p_warmight` 的黄-橙-红三级），或
- 换双色系（`p_shadowfist` 最终改「钢灰白 + 紫点缀」）

#### ④ 相邻形态间距必须 ≥3 格（膨胀描边会粘连）

`p_sleep` 的两个 Z 曾因间距 ≤2 格，黑边融合成一个整块，读不出字母。
拉开到 ≥3 格 + 明度三级递减后才成立。

#### ⑤ 可见色块必须 ≥4 格宽

描边各占 1 格，剩 2 格本体才看得出颜色。
`p_shadowfist` 的 1 格宽速度线两版都被吃掉。

#### ⑥ 16 格分辨率画不出「手指缝」这类细节

只能用**剪影轮廓**表达结构（`p_shadowfist` v3 用黑色竖缝画指节 → 读成「笼子/栅栏」）。
