### 1.3 新技能：启风（`qifeng`）

| 项 | 内容 |
|---|---|
| 类型 | **辅助**（与气势如虹 / 气力恢复 / 瞩目互斥，同类型最多带 1 个） |

| 效果① | 每回合开始，使我方随机 **2 名**角色速度 **+n%**（满级 **10%**） |
| 效果② | 若我方持有**全场速度最快**者（敌我双方合并排序），则该角色每回合可**额外进行一次普通攻击**，该次伤害为 **n×8%**（满级 **80%**），即「再打一次，但只造成 80% 伤害」 |
| 条件 | 速度最快的判定**须为敌我双方最快**；不满足则效果②不生效 |
| 速度增益 | **持续至战斗结束，或直到被驱散** —— 按「可被驱散的状态」实现（非直改 `base`） |

### 5.0 装配口径（源码实测，先读这条）

| 维度 | 由谁决定 | 是否确定性 |
|---|---|---|
| 属性 / **词条** / 技能 | `group-levels.js` 的 `genEnemyCfg`，按 `(大关, 小关, 槽位)` 播种 | ✅ 同一关永远同一套 |
| **天赋** | ⚠️ **不在关卡配置里** | 🔴 **每场战斗重摇** |

🔴 **`cfg.talents` 从未被赋值** —— `genEnemyCfg` 里 `var talents = []` 之后没有任何 push，
`if (talents.length) cfg.talents = talents;` 因此永不成立 → 实战走 `createEnemyUnit` 的兜底分支
`pickRandomTalents()`（`page/enemy.js:38`）：按 `ENEMY_TIERS[tier].talent = [min,max]` 随机**个数**、
再从全部 14 条里随机**取哪几条**，用的是全局 `battleRnd()`，**不在 `createGroupBattle` 的种子体系内**。

实测（同一关 `g12-10` 的 Boss、同一份关卡配置，只换随机种子）：

| 种子 | 该 Boss 实际抽到的天赋 |
|---|---|
| 11 | `magicshield` + `slowstart` + `lazy` |
| 22 | `vigor` + `roughskin` + `magicmirror` |
| 33 | `multitarget` + `slowstart` + `blade` |

- ⚠️ **Boss 会抽到 `lazy`（懒惰）/ `slowstart`（慢启动）这类自我削弱天赋** ——
  `group-levels.js` 里确实有「Boss/精英只用 `TALENTS_HIGH`、排除 `TALENTS_LOW`」的注释与 `TALENTS_LOW` 常量，
  但**那段逻辑作用在一个永远为空的数组上**，兜底抽取完全不排除它们。
- ⚠️ 副作用：`test-group-inherit.js` 的两条断言（「Boss 天赋/词条/技能全部来自各自的高级池」
  「Boss 不再抽到 lazy / slowstart」）里，**天赋部分是空转的** ——
  该测试遍历的是 `e.talents`（配置字段），而它恒为 `undefined`，`(e.talents || []).forEach(...)` 一次都不进循环
  （`test-group-inherit.js:104`）；**词条与技能部分仍有效**，所以这条守卫只挡得住一半。
- 📌 影响面：单场难度方差被天赋抽签放大；也是此前实测里「同口径下个别大关难度倒挂」的一部分成因
  （v2.1.29 记录的 g19/g20 倒挂只归因于词条/技能，其实天赋抽签也在其中）。
- 数量口径（设计 vs 源码兜底）：杂兵 `[0,0]` · 精英 `[1,1]`/`[2,2]` · Boss `[1,4]` ——
  **Boss 天赋数每场 1~4 个不等**，与设计表「Boss 1~4 天赋」的字面一致，但**不是关卡固化的**。

### 5.1 天赋（14 条）

**5.1.1 利刃 `blade`**
- 设计：攻击造成伤害提升（**10%-50%**）
- 源码：`onDamage`（仅 `ctx.isPlayerAttack`，即本单位作为攻击方）→ `dmgBoost = 0.10 + level × 0.005`，再 `Math.min(0.5, …)`；无概率，恒生效
- ⚠️ **50% 上限不可达**：敌群敌人的 `unit.level` 被夹在 1~10（`genEnemyCfg` 的 `level = clamp(lg, 1, 10)`），
  故实际区间只有 **10.5%（g1）→ 15%（g10 及以上）**，与设计的 50% 差得很远。
- **评审** 根据关卡与敌人级别，数值为10%~50%

**5.1.2 振翅 `flutter`**
- 设计：每回合结束，自身根据**速度初始值**增加一定比例的速度
- 源码：`onTurnEnd` → 每回合 `+floor(初始速度 × 5%)`（至少 +1），**无上限**；留 `_flutterBase` 快照供「清除迷雾」还原 ✔
- ⚠️ 比例 5% 与「不设上限」均为源码自定（设计未给比例）；长线战斗会持续推高出手顺序
- **评审** 根据关卡与敌人级别，每回合速度提升5%~20%（至少+1）

**5.1.3 粗糙皮肤 `roughskin`**
- 设计：每次受到**普通攻击**伤害给予攻击者一定比例伤害（**无视防御**）
- 源码：`onDamage`（有 `attacker` 且 `ctx.isPhysical`）→ `reflectFlat = floor(本次伤害 × 15%)`，下限 1 ✔
- ⚠️ 比例 15% 为源码自定；v2.1.15 修过「受击方吃双倍伤害」的同源缺陷，现行为正确
- **评审** 根据关卡与敌人级别，反伤比例为10%~50%

**5.1.4 强健 `vigor`**
- 设计：自身攻击·防御·魂攻击·魂防御提升一定比例数值
- 源码：`statMods` 四项各 **+15%**（基于 base 算一次，`createEnemyUnit` 里写回 `base`）✔
- ⚠️ 比例 15% 为源码自定；**不含速度**（设计也只列了四项，一致）
- ⚠️ 它是**静态修正写进 base**，而「清除迷雾」的能力变化归零只覆盖 `grow_atk` / `grow_def` / 复仇 / 振翅 四种，
  **不含强健** —— 即「强健的加成无法被清除迷雾还原」（口径是否合理待确认，见 §5.5-1）
- **评审** 「强健的加成无法被清除迷雾还原」

**5.1.5 魔法镜 `magicmirror`** 🔴
- 设计：自身受到**指向性辅助类型技能**时，有几率免疫那次效果，并**反弹给施加者**
- 源码：`onBeforeSupport`（`ctx.targeted && ctx.support`）→ 30% 几率 `skipAction` + `mutations: reflectSupport`
- 🔴 **`onBeforeSupport` 全项目没有任何派发点** → 「免疫」与「反弹」**两项都从未生效**（空壳天赋）。
  证据：该 hook 名只出现在 `talent.js:171` 的注册处；`reflectSupport` 只在 `talent.js:177` 生产、**无消费者**。
  （与本轮 §2/§4 已修的那类「写了没接线」完全同型：v2.1.15 / v2.1.16 / v2.1.32 都栽在同一个坑上。）
- ⚠️ 附带：即便补上派发点，「反弹」目前**没有实现载体** —— 需要定义「把辅助效果原样施加回施法者」的语义
  （治疗类反弹回去等于给对方回血？增益类反弹给自己？），需要一并裁决。
- **评审** 受到敌人的指向性辅助类型技能时触发

**5.1.6 朴实 `plain`**
- 设计：自身的能力无法被任何效果影响
- 源码：`onBeforeStatus` → **无条件** `skipAction`（**所有**状态一律免疫：正面/负面、grade 1~3、含队友给的增益）
- ⚠️ 口径差异：设计写「能力无法被影响」，源码实现为「免疫状态」——
  对**直改 `base` 的成长类**（战意高涨/铁壁 词条、强健、复仇、振翅）**不生效**（它们不是状态）
- ⚠️ 连**己方治疗者的增益**也会被免疫（`强攻`/`坚壁` 之类），是否符合预期待确认（见 §5.5-1）
- **评审** 包含双方

**5.1.7 威吓 `intimidate`**
- 设计：战斗开始时，恐吓使敌方随机 1 名敌人，使其攻击力**大幅降低**。持续：**直到施加者生命值低于 50%**
- 源码：`onBattleStart` → 敌方随机 1 名 `_intimidated`；削减幅度 `INTIMIDATE_ATK_DOWN = 0.4`（**-40%**，
  `battle-group.js` 直接读该常量，单一来源）；`onTurnStart` 检查自身 <50% 血则解除（v2.1.14 补日志）✔
- ⚠️ 40% 为源码自定（设计只说「大幅」）
- **评审** 根据关卡与敌人级别，降低10%~50%，直到施加者生命值低于 50%或者持续5~10回合后

**5.1.8 魔法盾 `magicshield`**
- 设计：自身受到**魂攻击**伤害降低
- 源码：`onDamage`（`ctx.isSoul`）→ `soulDmgReduce = 0.3`（-30%）✔
- ⚠️ 生产端写 value 0.3，**消费端却硬编码** `dmg = floor(dmg × 0.7)`（`battle-group.js:383`），不读 `m.value` ——
  当前值恰好一致，但**改生产端数值不会生效**（同类隐患：写死两处）
- **评审** 根据关卡与敌人级别，降低15%~45%

**5.1.9 慢启动 `slowstart`**
- 设计：战斗开始的**前 x 回合**，自身无法行动
- 源码：`onBeforeAction` → `ctx.turn <= (unit._slowRounds || 2)` 时 `skipAction`，**实际恒为前 2 回合**
- ⚠️ `_slowRounds` 全项目无写入点；注册时的 `config: { rounds: 2 }` 也**不被读取** → 「x」不可配（值恰好一致，无行为差异）
- ⚠️ 结合 §5.0：**Boss / 精英也可能抽到它**（实测 seed=11 / 33 都出现了），等于开局白送两回合
- **评审** 根据关卡与敌人级别，需要2~4回合启动时间，boss不会获得

**5.1.10 懒惰 `lazy`**
- 设计：每回合开始有 **25%** 几率本回合放弃行动；放弃行动回合**自身受到伤害降低**
- 源码：25% `skipAction` + 该回合 `dmgReduce = 0.3`（-30%）✔
- ⚠️ 25% 与设计一致；减伤 30% 为源码自定；同 §5.0，Boss 也会抽到
- **评审** 根据关卡与敌人级别，每回合开始有 **25%** 几率本回合放弃行动；放弃行动回合**自身受到伤害降低** 20%~40%

**5.1.11 多目标 `multitarget`**
- 设计：自身普通攻击**造成伤害降低**，普通攻击可以**额外攻击 x 个敌人**
- 源码：普攻伤害 `dmgReduce = 0.3`（-30%）+ `multiTarget = (_multiExtra || 1) + 1 = 2`
  → `battle-group.js:736` 取 `targets.slice(0, 2)`，即**普攻最多打 2 个目标**各一次 ✔（= 额外 1 个）
- ⚠️ `_multiExtra` 无写入点；`config: { extra: 1, penalty: 0.7 }` 两者都**不被读取**（值恰好等价，无行为差异）
- **评审** 自身普通攻击造成伤害降低20%~30%，普通攻击可以额外攻击 1~2 个敌人

**5.1.12 嗜血 `bloodthirst`**
- 设计：自身造成伤害时，恢复本次伤害**一定比例**的生命值
- 源码：`onAfterDamage`（`ctx.dealt > 0`）→ 回复 **20%**，上限为自身 maxHP ✔
- ⚠️ 20% 为源码自定
- **评审** 根据关卡与敌人级别，自身造成伤害时，恢复本次伤害**10%~35%**的生命值

**5.1.13 复仇 `vengeance`**
- 设计：自身生命值**每降低一定比例**，攻击力与魂攻击提升
- 源码：每损失 **25%** 生命 → 攻/魂攻 **+10%**（`1 + 0.1 × 层数`，按快照重算而非复利，v2.1.15 修），留快照供清除迷雾还原 ✔
- ⚠️ 25% / 10% 为源码自定；层数上限 4（损失 100% 血），实际到不了
- **评审** ·每损失 **20%** 生命

**5.1.14 再生 `regen`**
- 设计：每经过 **2-3 回合**，恢复自身最大生命值一定比例的生命值
- 源码：`turn % 3 === 0 && turn >= 2` → **固定每 3 回合**回复 **8%** maxHP
- ⚠️ 设计写「2-3 回合」（含随机意味），源码取固定 3；比例 8% 为源码自定
- **评审** 根据关卡与敌人级别，每经过 **2-3 回合**，恢复自身最大生命值3%~8%的生命值
