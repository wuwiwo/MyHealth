## v2.1.20

**Date:** 2026-09-16

### 云同步丢数据（用户实测发现）

用户反馈「同步时，没有全部数据都同步」。查证：**推送载荷是硬编码的 14 个键**，
v2.x 新增的系统一个都没进去。

写了一个往返测试实测（本地写满 19 个在用的键 → 生成载荷 → 空库拉取合并 → 比对存活）：

| 键 | 内容 | 结果 |
|---|---|---|
| `groupProgress` | **敌群 18 大关 / 180 关通关进度** | ❌ 丢 |
| `pets` | **14 只宠物 + 材料袋（营养液/饲料/灵能/炼化石/高炼石/宝珠碎片）+ 宝珠库存** | ❌ 丢 |
| `skills` | **玩家技能等级 + 技能点 + 装备槽** | ❌ 丢 |
| `cardioPlans` | 有氧计划 | ❌ 丢 |
| `theme` | 主题（深/浅） | ❌ 丢 |

**存活 14 / 19，丢 5 个。** 换设备后：敌群进度、宠物、材料、宝珠、技能点全没了。

### 三处根因

1. **`getAllData()` 硬编码键列表**（`sync.js`）：只收集 `entries / plans / missed / cardio / weight /
   profile / game / prs / records / attrLog / cardioTypes / exercises / refine / challenge`
   这 14 个扁平字段。
2. **`mergeServerData()` 同样硬编码**：拉取时也只认这 14 个 —— 云端就算有别的键也写不回本地。
3. **`store.mergeAll()` 丢掉标量值**（`store.js`）：`if (typeof v === 'object' && validValue(...))`。
   `theme` 是字符串（`'dark'` / `'light'`），推送带得走、拉取写不回，表现为「同步后主题回默认」。

### 修法（从结构上杜绝再漏）

- **不再枚举键**：新增 `collectOtherKeys()`，从 `store.getAll()` 自动派生「除扁平字段外的全部键」，
  写进载荷的 `keys` 段（载荷 `version` 4 → 5）。以后新增 store 键**不需要再改 `sync.js`**。
- **拉取侧对称**：`mergeServerData()` 合并 `d.keys`；`buildImportMap()` 一并处理
  （否则「导出备份再导入」同样会丢）。
- **`store.mergeAll()` 去掉 `typeof v === 'object'` 限定**，形状校验统一交给 `validValue`。
- **兼容旧快照**：v4 及更早没有 `keys` 字段 → 自然跳过，不会把本地新数据抹掉（有测试守着）。
- **同步弹窗补上新系统摘要**：本地/云端两张卡各加一行
  「🐾 宠物 / 🔮 宝珠 / 🗺️ 敌群 / 💠 技能点 / 🧪 营养液 / 🍖 饲料」；
  云端若是旧版快照，显式提示「⚠️ 云端是旧版快照（不含宠物/敌群进度等），推送本地一次即可补齐」。

### 新增守卫测试

`scripts/test-sync-coverage.js`（**20 断言**）：

1. **从 `page/*.js` 源码自动派生应用真正在用的 store 键**，逐个做 push→pull 往返，断言 0 丢失
   —— 以后新增 store 键若忘了同步，这里直接红；新键若没在测试里登记样本，
   也会**报错而不是静默跳过**
2. 标量键（`theme`）必须能同步
3. 旧版快照（v4，无 `keys`）仍能合并，且不抹掉本地宠物数据
4. 内容级校验：宠物受伤进度 / 材料袋 / 宝珠库存 / 敌群进度 / 技能点，逐字段比对
5. `buildImportMap` 的「导出 → 导入」往返同样 0 丢失

### 测试

全量 **36** 个套件全部通过（新增 sync-coverage）。

### 文件

- `page/sync.js`（`collectOtherKeys` / 载荷 `keys` / `mergeServerData` / `buildImportMap` /
  `dataSummary` + 弹窗摘要）
- `page/store.js`（`mergeAll` 支持标量键）

## v2.1.19

**Date:** 2026-09-16

### 1. 修：手动模式重复发放通关奖励

`_groupDone()` **没有幂等保护**。手动模式下战斗结束后仍可继续点「下一步」，
`_groupStep` 走到 `if(!_groupBattle||_groupBattle.done){_groupDone();return}` 会再次调用它，
导致 `markGroupStageCleared` / `groupVictoryReward` 被重复执行 —— 技能点和材料重复发放。

新增 `_groupRewarded` 标志：`startGroupTrial` 开战时重置，`_groupDone` 内保证每场战斗只结算一次。

### 2. 降低每关技能点：10 → 4

`skill-store.js` 新增 `SKILL_POINTS_PER_STAGE = 4`（原写死 10）。周递增规则不变。
测试改为由该常量派生，不再写死期望值。

### 3. 宠物放大倍数改为 12 / 14 / 15 / 16

`PET_GROUP_SCALE` 由 `{R:8, SR:11, SSR:14, UR:18}` 改为 `{R:12, SR:14, SSR:15, UR:16}`。
**稀有度差距收窄**（原跨度 8~18，现 12~16），不再「只有 UR 能用」。

### 4~6. 成熟期受伤系统

| 规则 | 实现 |
|---|---|
| 成熟期战斗失败 → 50% 几率受伤 | `applyDefeatInjuries(d, speciesIds)`，仅对**本场参战**且未受伤的成熟宠物判定 |
| 受伤期间无法继续战斗 | `canPetBattle()` = 成熟 + 未阵亡 + 未受伤；`getBattleReadyPets` / `createPetUnitsForBattle` 均已过滤 |
| 营养液治疗 +10%~15% | `healPetInjury(pet,'nutrition')` |
| 饲料治疗 +4%~5% | `healPetInjury(pet,'feed')` |
| 恢复进度到 100% 解除受伤 | `pet.injured` / `pet.injuryHeal`（0→100，满值清空并解除） |
| **成熟期也需要喂饲料** | `feedPet` 原本 `if (stage !== 'grow') return`，现放开成熟期（恢复饥饿 + 治疗 4~5%） |
| 成熟期可喂营养液 | `feedNutrition` 放开成熟期（治疗 10~15%，不涨孵化进度） |

实测：营养液约 **8 次**治愈，饲料约 **23 次**，败北受伤率 **50.2%**（2000 次采样）。
UI：宠物卡显示「🤕 受伤 N%」，营养液按钮在受伤时标红。

  原因：若 g16+ 继续用 1.45，g18 Boss 需要约 **6~7 倍**属性才可能通关 —— 那是永远碰不到的内容。

g1~g13 全 100%，**g14~g18 全 0%** —— 「比现在更难通关」成立。

## v2.1.15

**Date:** 2026-09-13

**主题：把「写了没接线」的 9 处效果全部实装。** v2.1.14 在技能详情页用 ⚠ 披露了它们，
这一版把它们真正跑起来，并顺带修掉同源的 5 个隐藏缺陷。

### 为什么会有这么多死效果

共同模式只有两个：**只写不读的标记**（`_dodge` / `_fortify` / `_dmgReduce` / `_momBoost` / `_shield` …）
和**算了不用的中间结果**（`statMods()` → `_statMods`）。
根子上是「效果层」和「结算层」各自演进、没有统一通路。这一版把能收进状态系统的都收进状态系统，
剩下的挂到明确的消费点上。

### 1. 状态终于会过期（本轮影响最大的一项）

`state-core.js` 的 `tickStatuses()` 定义了但**全项目零调用**，后果比「数字不更新」严重得多：

- 中毒 / 减速 / 破甲 / 潮湿 挂上就是**整场**
- 冰冻 / 睡眠 / 畏缩 因为「受击解除」也没接线 → 该单位**整场无法行动**
- 单位详情里的「剩余 N 回合」是静态假数据

新增 `ageStatuses(unit)`：只做 duration 递减 + 到期移除 + `onExpire`，**不重复派发钩子**
（原 `tickStatuses` 把递减和派发揉在一起，直接调用会把中毒伤害算两遍）。
在单位回合末调用，并且**「跳过行动」的早退分支同样要调用**
（否则冰冻照样永久锁死 —— 修好一个坑又掉进同一个坑）。
`freeze` / `sleep` 的「受击解除」也补上了 `dispatch(target, 'onDamage')`。

### 2. `_statMods` 生效：属性修正从「算了不用」变成真修正

`statMods()` 算出来的结果从未写回 `unit._statMods`，而 `unit.js` 的 `effectiveSpeed` /
`effectiveStat` 读的正是它 —— 所以减速不影响出手顺序、破甲不影响承伤。
现在：`statMods()` 按 `st.stacks` 乘算 + 支持百分比（`statModsPct`）+ 支持实例自带 `modsPct`
（`applyStatus` 新增该参数），`refreshStatMods()` 在每次状态增删后写回，
伤害公式与出手队列改读 `effectiveStat` / `effectiveSpeed`。

**顺带把三处固定值改成百分比**（在几百上千的属性面前，固定 -5 / -10 / -15 等于没写）：

| 状态 | 改前 | 改后 | 依据 |
|---|---|---|---|
| 潮湿 | 魂防 -10 | 魂防 **-25%** | 设计文档「0%~25%」 |
| 破甲 | 每层 防御 -5 | 每层 防御 **-10%**（满 6 层 = -60%） | 设计文档「降低防御 10%，最大叠加 6 层」 |
| 魂防降低 | 魂防 -8 | 魂防 **-15%** | 文档未给数值，取中位 |
| 遗言诅咒 | 攻/魂攻 -15 | 攻/魂攻 **-25%** | 文档只说「大幅降低」 |
| 减速 | 速度 -3 | 不变（速度本身只有 3~15，-3 已经很痛） | — |

「潮湿」还补上了设计文档写了却从没实现的**命中率 +30%**（`groupHitChance`）。

### 3. 伤害修正类：广域防御 / 强攻 / 坚壁

- `bulwark` 广域防御：写 `_dmgReduce` 但伤害结算不读 → 改为 `wideguard` 状态；
  并给伤害路径补 `dispatch(target, 'onDamage')`（旧版只派发天赋，**状态钩子从来没被派发过**）
- `empower` 强攻：buff 按单位下发，而结算侧只消费「全体」类 buff → 静默丢弃。
  现在统一按 `key` 映射到状态（`atkup` + 实例 `modsPct: {atk: 0.3}`）
- `fortify` 坚壁：写 `_fortify` 无人读 → 改为 `guardup` 状态（每层 +10% 防/魂防，最多 5 层）

### 4. 判定与叠层类：变小 / 雪球 / 咬击

- `shrink` 变小：累加的是 `_dodge`，而命中判定读 `_eva` → 白写。
  改为 `_evaPerm`（**常驻**闪避，避免被「限时修正到期归零」顺手清掉）
- `snowball` 雪球：只累计层数、伤害恒定 120% → 新增 `stackPower` 按**百分点**累加
  （120% → 每层 +30% → 满 6 层 300%，与设计文档一致；用乘法会变成 579%）

### 5. 驱散与窃取：净化 / 清除迷雾 / 摄取

### 7. 两处「写了没接线」的引擎缺陷

#### (a) 威吓从未触发过

`talent.js` 的威吓挂在 `onBattleStart` 上，但**全项目没有任何地方派发过这个 hook**。
所以真正的问题不是「日志没说清威吓了谁」，而是**威吓事件根本没发生过**。

- 新增 `dispatchBattleStartTalents(gb)`：开战（回合 0）时对双方各派发一次 `onBattleStart`，事件落进 `gb.log`
- `target._intimidated` 此前是**只写不读**的死标记 → 现在在 `normalAttack` 与 `castSkill` 里按
  `INTIMIDATE_ATK_DOWN = 0.4` 统一削减伤害
- 威吓解除（威吓者血量 <50%）补日志，不再静默失效
- 单位卡加 `😱 攻-40%` 徽章，单位详情显示原因

#### (b) 嘲讽永不复位

`player-skill-hooks.js`（瞩目）与 `skill.js`（嘲讽技能）只把 `_taunting` 置 `true`，
**全项目没有一处置回 `false`**。后果有两层：

1. `selectTargets` 永远把敌方攻击吸到嘲讽者身上（永久嘲讽）
2. `unitInitiative` 里 `if (u._taunting) spd *= 2` 永久生效（永久 2 倍速）

现在用 `_tauntMark` 记录施加回合，`groupUnitTurn` 在**本单位下一次行动开始时**清除 ——
刚好覆盖「本轮剩余出手 + 到本单位下轮出手之前」，与「嘲讽 1 回合」的语义一致。

## v2.1.9

**Date:** 2026-09-13

### 敌群难度锚定：解决「属性太高、战斗没体验感」

**问题**：敌人属性是写死的绝对曲线（全 120 关攻击上限 449），玩家属性由「月训练容量 + 炼魂」驱动、无上界（炼魂满级即 攻 +3770 / 防 +1798 / 血 +6920）。配合固定减法伤害 `max(1, atk − floor(def/2))`，玩家防御一旦 ≥ 898，**全部关卡敌人每击恒定 1 点** —— 不是变简单，是数学上直接归零。模拟器实测：攻 2500 / 防 900 / 血 9000 的玩家对 g1~g12 Boss 全 100% 胜率、剩血 89~100%。

**改法**：`page/group-levels.js` 新增 `anchorStageEnemies(groupId, stage, allies)` —— 敌人属性由**参战我方阵容反推**，固定曲线降级为下限（所以后期关卡数字依然更大）。玩家变强的体现从「数值碾压」转为「能推到第几关」。

推导（自洽）：
1. 敌防 = 固定曲线 × `defScale`，使人均防御 ≈ 我方人均攻击 × 30%
2. 我方每回合有效输出 `allyDps` = Σ我方攻击 − n × 人均敌防/2
3. 敌血总量 = max(固定总量, `allyDps` × `hpP`)，据此得**实际预期回合数 R**
4. 敌攻 = 固定曲线 × `atkScale`，使 R 回合内我方总掉血 = `atkP`（0.05 → 0.55 随关卡爬升）

⚠️ 两个踩过的坑（已写进注释）：
- **R 必须用实际预期回合数，不能用目标回合数 `hpP`**：弱玩家打磨固定血量的 Boss 可能要 30 回合，若按 1 回合配攻击力，敌人总输出会超标 30 倍
- **技能余量 `skillAllowance = 1.80`**：实测敌人实际输出 ≈ 普攻模型的 1.75 倍（冲撞 200%、暴风雪 AoE 打全体 + 冰冻控场、暴击、破甲），不打折会把末关做成必死

**效果**（`scripts/balance-sim.js` 实测，每关 20 场）：

| 玩家 | g1-10 | g6-10 | g12-10 |
|---|---|---|---|
| 攻 2500 防 900 血 9000 | 100% / 剩 90% | 85% / 剩 61% | 95% / **剩 20%** |
| 攻 6000 防 2000 血 20000 | 100% / 剩 90% | 85% / 剩 61% | 95% / **剩 20%** |
| 锚定前（同属性） | 100% / 剩 100% | 100% / 剩 93% | 100% / **剩 89%** |

两档相差 2.4 倍的玩家跑出**完全相同**的结果 → 难度已与玩家强弱解耦。

### 修复

- 🔒 **修复「页面有时无法滚动」（线上偶发）**：`openModal` 用 `body{position:fixed}` 锁滚动，但存在两条漏解锁路径，`body` 一旦卡在 `position:fixed` 就**永久无法滚动，只能刷新页面**

- 🎮 **隐藏挑战小游戏点背景不再卡死**：游戏进行中（`ticking===true`）点背景，弹窗自己的处理器为了保护对局**故意不关闭**，但全局处理器仍会把 `open` 摘掉 → **弹窗隐形、游戏继续跑、结算结果渲染进隐藏弹窗** → 用户既看不到结果也点不到关闭 → 页面永久冻结。现加 `data-no-auto-close` 标记，游戏结束后自动解除
