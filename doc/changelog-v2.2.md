## v2.2.2

**Date:** 2026-09-29

> **WP-A 收官**：A1 属性公式 + A2 宝珠重构（两块**必须同时发版**，理由见下）。

### 🔢 A1 属性公式改为「基础值 × 倍率池」

```
最终属性 =（图鉴基础 + 炼化加成 + 天赋静态修正 + 团队凝聚 + 共鸣）×（稀有度倍率 + Σ宝珠%）
```

- **稀有度倍率改百分比表述**：R 1200% / SR 1400% / SSR 1500% / UR 1600%（`PET_GROUP_SCALE`，数值与旧的 ×12/14/15/16 等价）
- **逐属性独立**（血 / 攻 / 防 / 魂攻 / 魂防），**速度不参与**
- 🔻 **删除历史特例**：v2.1.17 的「宝珠加成不参与放大」（靠一个 orbBonus 增量字段实现）已删 ——
  百分比进池后天然与稀有度倍率同尺度
- 顺带删掉死常量 `PET_GROUP_REFINE`（声明后从未被任何代码消费）

### 💎 A2 宝珠重构（`page/orbs.js` 整文件重写）

| 项 | 旧（v2.1.17 ~ v2.2.1） | 新（v2.2.2） |
|---|---|---|
| 数值形态 | **扁平加点**（如 SSR 血气满级 +1175 血） | **百分比**（+N% 进倍率池） |
| 品质 | N / R / SR / SSR | **R / SR / SSR / UR**（**删除 N 档**） |
| 等级上限 | 10 / 20 / 30 / 40 | **R 10 / SR 25 / SSR 40 / UR 50**，**满级自动升品质** |
| 每级成长 | 固定值 | **R +1% / SR +2% / SSR +2% / UR +3%** |
| 单颗上限 | — | **+300%**（UR 满级 = +297%） |
| 获取方式 | 碎片**合成**（20 碎片、65%） | **隐藏挑战掉落**（每胜 1 颗；R 60% / SR 25% / SSR 12% / UR 3%） |
| 碎片用途 | 合成 + 升级 | **只用于升级**（消耗 =（等级+1）×2） |
| 分解返还 | 4 / 8 / 10 / 20 | 8 / 10 / 20 / **40**（UR 为外推值） |
| 月重置 | 等级回 1、碎片清空 | **不变**（品质保留） |

**存量迁移**（新增 `migrateOrbs()`，挂在 `getPetStore()` 读取路径上、**幂等**）：
旧 **N 档每颗 → 20 宝珠碎片**；R/SR/SSR **按品质映射 + 等级保号**、**超过新品质上限则截断**；
库存 `data.orbs` 与宠物槽 `pet.orbs` 两处都处理；**不发放一次性补偿**（dundun 裁决）。

### 🧩 为什么 A1 / A2 必须一起发

A1 的公式要吃「宝珠%」，而 A2 才把宝珠从扁平值改成百分比。若单独发 A1，
**现有存档里的扁平宝珠会被稀有度倍率 ×12~16 放大** —— 正是 v2.1.17 修过的那次事故
（满级 SSR 攻击宝珠 +248 → 约 4000，直接顶穿队伍）。

### 📊 平衡复测（WP-A 收官后，2026-09-29）

口径：**同一套配置只换宠物规则**做 A/B，其余全同（玩家继承 50% / `groupStageEnemies` / `groupTerrainFor` / 同种子序列）；

## v2.2.1

**Date:** 2026-09-29

> **口径修正版**：dundun 明确宠物属性的**总模型** ——
> **「直接加属性值」的属于基础属性部分；写成百分比的才进可叠加的百分比池**；
> `最终属性 = 基础属性 × 百分比池`。

### 🔧 修正 v2.2.0 的团队凝聚 / 共鸣落点

v2.2.0 把它们加在了 `boostPetForGroup()`（百分比池）**之后**，且共鸣按「参战宠物**自身**属性」算比例 —— 两处都不符合上面的模型。

| 项 | v2.2.0（已废） | v2.2.1（现行） |
|---|---|---|
| 落点 | 稀有度放大**之后**（固定值不再参与倍率） | **基础属性**（`boostPetForGroup` **之前**），随基础值一起进百分比池 |
| 共鸣基数 | 参战宠物**自身**属性 × 档位% | **未上场宠物**的基础属性 × 档位% |
| 与凝聚的关系 | 两种不同形态（一个固定值、一个百分比） | **同形**：都是「未上场宠物基础属性 × 比例」加到参战宠物基础属性（凝聚固定 10%、共鸣按持有总数 3/5/7/10%） |
| 「不受百分比加成影响」 | 曾误读为「结果不被放大」 | 正解：**计算源**取未上场宠物的**基础属性**，而非它们被百分比放大后的最终属性 |

- 新增 `benchBonusSum(benchPets, rate)` 统一两者算法、`benchPetList(units)` 统一「成熟 + 未受伤 + 未上场」判据、
  `applyBattlePetBaseBonuses(units)` 负责落点；`b`buildGroupBattlePets`` 的调用顺序改为 **建单位 → 基础值加成 → 稀有度放大**
- 测试：`test-pet-store` 30 → 32 断言，新增「共鸣取的是未上场宠物属性」与
  **顺序守卫**（源码级断言：`applyBattlePetBaseBonuses` 必须排在 `boostPetForGroup` 之前）

### 🐾 A3 上场宠物 2 → 4

- 新增唯一上限常量 **`PET_BATTLE_MAX = 4`**（`page/pet-store.js`）——此前「2」散落在 5 处调用点，改一处漏一处
- `createPetUnitsForBattle()` 默认上限改为该常量；`PET_CONFIG.maxRoster` 同步 2 → 4
- 宠物面板的**参战选择**上限、文案「最多 2 只 → 最多 N 只」（改为读常量，不再写死）、超限 toast 全部跟随
- ⚠️ 战场规模变化：我方最多 5 单位（玩家 + 4 宠）vs 敌方最多 3 —— 行动队列与 UI 布局已按 5v3 验证（全量测试通过，含群战引擎与日志审计套件）

### ✨ A4 团队凝聚（新）+ 共鸣（接线）

- **团队凝聚**（`page/pet-store.js` 新增）：所有「**成熟 + 未受伤 + 未上场**」的宠物，各把自己的属性 **×10%**
  作为**固定值**贡献给参战宠物（`TEAM_COHESION_RATE = 0.10`）
  - ⚠️ 关键实现点：**必须在 `boostPetForGroup()` 之后**叠加，否则这份固定值会被稀有度倍率（×12~16）二次放大，
    违背设计里「不受百分比加成影响」的定义
  - 取的是该宠物的**基础属性**（图鉴 + 炼化 + 天赋静态修正）
- **共鸣**（`resonanceBonus()` **首次接入战斗**）：按**持有总数**档位（>1 ×3% / >3 ×5% / >6 ×7% / >10 ×10%）
  对上场宠物自身属性加成。此前这个函数**全项目零消费点**，只有 `test-pets.js` 在断言它 ——
  属「函数写好了但没接线」，本版正式实装
- 两者**共存**（dundun 裁决），可叠加；实现时按「凝聚固定值 + 共鸣百分比」一次结算，并在加成后回满血

### 🔌 结构：参战宠物的**唯一入口**

新增 `b`buildGroupBattlePets`(petIds, maxRoster)`（`page/pet-store.js`）= 建单位 → 稀有度放大 → 凝聚 / 共鸣，
`game-render.js` / `pet-ui.js` / `debug.js` **三处调用点统一改走它**。

理由：本项目反复栽在「三处各自判断 → 口径分叉」上（v2.1.12 的 Debug 体检与实战不一致就是这么来的），
所以 Debug 体检、宠物面板开战、挑战页开战必须共用一条管线。
