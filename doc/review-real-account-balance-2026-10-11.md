玩家属性按 §1.2；40 个种子（每种子独立掷 Boss 词缀）；走真实入口 `buildBattleSides` + `rollBossAffixFor` + `createBattle(seed)`。

| 关卡 | 胜率 | 平均回合 | 与你的实际记录对照 |

### 2.2 单变量拆解（16-6，30 种子）

| 只改一项 | 胜率 | 解读 |
|---|---|---|
| 攻 +450 | **40%** | 输出侧收益最高 |
| 血 +1900 | 30% | 生存侧 |
| 防 +388 | 30% | 生存侧 |
| 魂攻 +400 | 30% | 对 `soulDef 385` 的 Boss 有效 |
| **魂防 +300** | **23%** | ⚠️ 只补魂防不足以翻盘，但它是**零成本就能补**的一项（见 §4） |

## 4. 可执行结论（按性价比排序）

| 优先级 | 动作 | 依据 | 预期 |
|---|---|---|---|
| 1 | **补魂防**（炼魂里优先堆 `soulDef`） | §2.2：魂防 0 时敌人魂攻全额命中；16-6 敌人 `soulAtk 500` | 16-6 从 0% → 23%；配合攻/血提升可过 |
| 2 | **攻/防/血 同步 +25%** | §2.1：×1.25 → 80% | 稳定通过 16-6，解锁 17 章 |
| 3 | **宠物炼化优先于自身训练属性**（若目标是敌群） | §3：不带宠 0%，满炼化 +4 个大关 | 敌群推进上限 g11 → g15 |
| 4 | 单敌与敌群的**目标不同**：单敌吃你自己的属性，敌群吃「属性 × 0.5 + 宠物」 | §2/§3 对比 | 想推单敌练属性，想推敌群练宠物 |

## 5. ⚠️ 安全提示（与平衡无关，但影响面更大）

`page/api/data.mjs` 的同步端点**没有任何鉴权**：

```js
res.setHeader('Access-Control-Allow-Origin', '*');   // 任意站点可跨域读取
if (req.method === 'GET')  { /* 直接返回最新快照，无 token */ }
if (req.method === 'PUT')  { /* 直接写入新快照，无 token */ }
```

| 风险 | 说明 |
|---|---|
| **可读** | 任何人知道 URL 即可 `GET` 到你的完整存档：训练记录、体重、身高/性别/出生年、关卡进度、宠物。本轮就是这么拿到数据的（未用任何凭据） |
| **可写** | `PUT` 同样无鉴权。写入后它成为「最新快照」，你的 App 下次拉取会经 `mergeServerData` 合并进本地 |
| **可致数据丢失** | `cleanupOldBlobs()` 只保留最新 **20** 个快照（`KEEP_LAST = 20`），持续灌入垃圾快照会把**你自己的历史快照挤掉** |

**建议修法（按成本从低到高）**：

1. **加一个共享密钥**：客户端在 `sync.js` 里带 `X-Sync-Key` 头，服务端比对 `process.env.SYNC_KEY`（一行校验，最低成本）。
2. **把密钥放进路径**：`/api/data/<random-slug>`，避免被扫描。
3. **GET/PUT 分权**：读用只读 token，写用写 token；并给 `PUT` 加频率限制。
4. 收紧 CORS：从 `*` 改为你的正式域名（注意本地 `localhost` 调试需要放行）。

> 这属于**独立任务**，与宠物平衡无关，本文只登记、不改动。
