# 怪兽头像像素图标设计规格（v2.3.0）

> 目标：为 `page/levels.js`（**189 关**）与 `page/group-levels.js`（敌群名字池 **21 名**）的敌人各绘制一枚 **1:1、48×48 像素、像素风格**头像 SVG。
> 策略：**不做 189 枚**——按**视觉原型 Archetype** 归纳为 **18 个原型**，每个原型一枚图标，敌人名经确定性映射落到原型上。
> 数据来源：`page/levels.js`、`page/group-levels.js`。
> 参照：`doc/design-pet-icons.md`（宠物图标规格，本文件沿用其全部硬约束以便复用校验脚本与光栅化器）。

---

## 0. 为什么是「原型」而不是「逐名」

`page/levels.js` 有 33 章 × 6 关 = **189 个唯一敌人名**。逐名绘制有两条硬伤：

1. **工作量与收益不成比例** —— 189 枚里大量名字在 16×16 下必然视觉同构（`永恒壁垒` / `终极壁垒` / `星核壁垒` / `冥河壁垒` …），逐名分配只会产出 12 枚几乎一样的方盾，去重目标**结构性地无法达成**。
2. **无法维护** —— 项目仍在扩章（`GROUP_MAX` 从 18 → 21 → 24，`levels.js` 已到 chap33）。逐名映射意味着每加一章都要新画图标；原型映射下**新增关卡自动复用就近原型**。

原型的划分依据是**真实数据规律**，不是拍脑袋：`levels.js` 从 chap6 起命名严格按**槽位分工**——

| 槽位 | 命名范式 | 原型 |
|---|---|---|
| 1 | `X守卫` / `X哨卫` / `X先锋` / `X行者` | guard / ranger / sentinel |
| 2 | `X刺客` / `X猎手` / `X猎影` | assassin / ranger |
| 3 | `X巨像` / `X壁垒` / `X巨兽` | golem / beast |
| 4 | `X骑士` / `X剑圣` / `X剑帝` / `X巨人` | rider / knight / titan |
| 5 | `X法师` / `X使者` / `X化身` / `X代言` | mage / lord / avatar |
| 6 | `BOSS X` | lord / dragon / eyeboss / avatar |

槽位只用来确定**候选集合**，最终裁决由关键字完成（见 §2 映射表）。

## 1. 统一技术规范（硬约束，逐条校验）

> 本节与 `doc/design-pet-icons.md §1` **完全一致**，目的：`scripts/test-pet-icons.js` 的校验逻辑与本套图标的 `scripts/test-monster-icons.js` 共用同一套判定。

### 1.1 画布与网格

| 项 | 值 |
|---|---|
| SVG 根标签 | `<svg xmlns="http://www.w3.org/2000/svg" width="48" height="48" viewBox="0 0 48 48" shape-rendering="crispEdges">` |
| 逻辑网格 | **16 × 16** 格 |
| 单元格尺寸 | **3 × 3**（px） |
| 坐标取值 | 所有 `x` / `y` / `width` / `height` **必须是 3 的倍数**，范围 0~48 |
| 背景 | **完全透明**，不画背景矩形、不画圆角底、不画边框 |

### 1.2 绘制方式（强制）

**必须用 ASCII 字符草图先定轮廓，再映射为 `<rect>`。**

- 在 SVG 内以注释形式保留 16×16 字符草图，便于复核；
- 每个字符 = 一个调色板键，映射为一个或多个 3×3 的 `<rect>`；
- **允许合并**同一行中相邻同色格为一个更宽的矩形（宽为 3 的倍数），以压缩文件体积；
- 只使用 `<rect>`（可选 `<title>` 作无障碍标签），**禁止** `<path>` / `<circle>` / `<ellipse>` / `<polygon>` / `<text>` / `<image>`。

### 1.3 颜色约束

- **纯扁平色**，禁止渐变（`<linearGradient>` / `<radialGradient>`）、禁止滤镜（`<filter>`）、禁止 `opacity` / `fill-opacity` / `stroke` / `stroke-width`；
- 每个图标**最多 8 种** hex 颜色（含描边色）；
- 描边统一使用 `K = #23262E`，用于外轮廓与五官，全 18 个原型**必须一致**；
- **描边占比目标 ≤20%（软目标，允许例外）**：描边是「轮廓」而非「主体」，占比过高会让图标读作
  深色块。但**这是软目标而非硬门槛**，因为某些造型天然需要更多描边（细长武器、镂空结构、
  密集五官）。**判定原则：只要主体形状可读，占比超标可接受**；若主体读不出来，先改几何。
  实测例外：`ranger` 与 `mage` 因细长配饰占比超 20%，经主控目视确认主体清晰，**予以接受**。
- 高光统一使用 `W = #FFFFFF`；
- 主体色按 §3 各原型专属调色板，**不得跨原型换色**。

> ⚠️ **深色主题可读性（本套新增硬指标）**：应用默认主题为**深色**，卡面底色 `--bg2 / --surface = #111827`。宠物套的 `darkcrow` 曾在 v2.2.29 踩过一次隐形（主体 `#0B0D12` 对卡面只有 **1.10:1**，几乎不可见）。
> 因此本套要求：**每个图标在深色卡面 `#111827` 与浅色卡面 `#ffffff` 之下，各自都至少有一种颜色达到 3:1 对比度**。
> ⚠️ **两种主题允许用不同的颜色**。不要误写成「同一种颜色必须同时满足两边」——那是**过严**的：深色卡面要求颜色够亮、浅色卡面要求颜色够暗，除中间灰外没有颜色能两边都达 3:1，会误杀「亮主体 + 深描边」这类完全正确的设计（宠物套的 `sparkle` 就是这种：亮黄主体在深色下 11.22:1 很清楚，深色描边在浅色下 15.13:1 很清楚，两边都成立）。
> 判定公式（WCAG 相对亮度）：`lin(c) = c<=0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`，`L = 0.2126R + 0.7152G + 0.0722B`，`contrast = (max+0.05)/(min+0.05)`。

### 1.4 构图

- 主体必须**居中**，允许**脚 / 尾 / 角 / 披风下摆贴到画布下沿**（落地线），**左右与顶部仍需留 1 格**；
- 主体最小包围盒**不小于 10×10 格**（30×30 px），保证 48px 下可辨识；
- 眼睛（或等效视觉焦点）统一落在第 6~10 行区间，使 18 个图标**视线高度一致**；
- 底部不做投影、不做地面线。

### 1.5 输出

- 路径：`page/media/monsters/<archetypeId>.svg`，文件名 = 原型 id（全小写）；
- 编码 UTF-8，无 BOM；文件内不加 XML 声明；
- 单文件建议 < 6 KB。

## 3. 优化后的形象提示词（逐原型）

> 每个原型给出：**形象描述** + **像素化要点** + **调色板** + **构图草图指引** + **去重红线**。

---

### 3.1 soldier — 步兵

**形象描述**：最基础的人类士兵，游戏里出现频率最高（27 关），因此要**朴素、无个性、一眼读作「兵」**。正面站姿，身穿深蓝色短甲，肩部有两块方正的护肩，腰间系一条皮带。头顶**不戴盔**——露出肤色头部与一双平视的黑眼，短发为深色。右手竖持一把直刃短剑，剑尖朝上，刃身有一道浅色中脊。左手自然下垂或虚握。两条腿并立，脚穿方头短靴。整体气质是训练有素但普通的士兵。

**像素化要点**：
- 身高 13 格（y 2~14），肩宽 7 格，头宽 5 格 —— 普通人类比例；
- **剑必须竖直**且与身体分离 1 格（剑在右，身体在左），剑长 8 格、宽 1 格，剑格 2 格宽；
- 露脸是它与 `knight` / `guard` 的核心区别：脸必须是**肤色**而非金属色；
- 双脚在第 14 行，各宽 2 格，中间留 1 格。

**调色板**：`K #23262E` 描边 · `B #3E6FA8` 甲蓝 · `b #6FA0D0` 甲高光 · `S #E8B48C` 肤色 · `H #3A2A22` 发色 · `Y #C9CDD6` 剑身 · `W #FFFFFF` 眼中高光。

**构图草图指引**：身体 x 3~9、y 4~14；剑 x 11~12、y 3~11；头部 y 2~5。

**去重红线**：不得出现盾（→guard）、不得出现弓（→bow）、不得为全身金属（→knight）、不得双持（→berserker）。

---

### 3.2 guard — 守卫

**形象描述**：一名以**巨盾**为身份标识的重装守卫。身体几乎被一面高过肩的塔盾遮住大半：盾为竖长方形，正面有十字加固条与一颗铆钉。盾后只露出头盔与一侧肩甲。头盔是**全罩式**——看不到脸，只有一条横缝与一条竖缝组成的 T 形开口，缝内是纯黑。头盔顶端有一道短横脊。右手持一把短矛，矛尖从盾侧探出。姿态稳重、双腿微分开立。

**像素化要点**：
- **盾牌必须占画面中下部 8~9 格宽 × 9 格高**，是视觉主体，不可缩小成小圆盾；
- 头盔 T 缝：横缝宽 3 格、竖缝高 2 格，均为 1 格粗，缝内 `K` 色；
- 盾面十字条用 `b` 色（比盾身亮），必须清晰分出四格；
- **完全不露肤色**（与 `soldier` 的露脸形成硬区分）。

**调色板**：`K #23262E` 描边 · `G #8A939F` 盾钢灰 · `g #5F6873` 盾暗面 · `b #C2C9D4` 十字条亮 · `Y #B9BFC9` 头盔 · `W #FFFFFF` 铆钉高光。

**构图草图指引**：盾 x 2~10、y 5~14；头盔 x 3~7、y 2~5；矛 x 11~12、y 3~8。

**去重红线**：不得露脸；盾必须够大；不得出现方块躯干（→golem）。

---

### 3.3 berserker — 狂战

**形象描述**：一个彻底放弃防御的狂暴战士。**上身赤裸**，露出赭红色的肌肉躯干，胸口有一道斜向的旧伤疤。双手各持一把**巨大的双刃斧**，斧头朝外张开，两把斧子构成画面最宽的横向跨度。头发是竖立的深棕色尖刺短发（像炸开一样），浓眉倒竖，双眼是愤怒的白色高光眼中的小黑瞳。下身穿深色短裤与绑腿，赤脚或穿简易皮靴。

**像素化要点**：
- **双斧必须左右对称分列**，斧头各占宽 3 格、高 4 格，斧柄长 5 格 —— 双斧是它与 `soldier`（单剑）的唯一区别，不可只画一把；
- 躯干用**裸肤色**，且要有 1~2 格深色阴影表现肌肉，不要画成盔甲；
- 竖发：头顶 3~4 根高低不一的尖刺，最高到第 1 行；
- 眉压低到与眼同高（怒相）。

**调色板**：`K #23262E` 描边 · `S #C98A5E` 裸肤 · `s #A56A44` 肤暗部 · `H #6B4A2F` 发色 · `A #9AA3AF` 斧刃 · `Y #C9CDD6` 斧柄 · `W #FFFFFF` 眼高光。

**构图草图指引**：躯干 x 5~10、y 6~12；左斧 x 1~3、右斧 x 12~14，y 4~10；发 y 1~3。

**去重红线**：**必须双持**；必须露肤（裸上身）；不得戴帽（→mage）。

---

### 3.4 sentinel — 哨卫

**形象描述**：一名以**长矛**为标志的细高哨兵。整体体态**瘦长挺立**，身穿偏绿的轻甲，肩部有一片小披风（长仅及腰）。双手斜握一根**比人还高的长矛**，矛杆从画面左下角一直延伸到右上角，贯穿整个画布的对角线 —— 这是它最强烈的视觉签名。头盔是**尖顶式**（顶部收成一个锥尖），只露出下半张脸。矛尖为三角锥形，顶端有一点白色反光。双腿并拢站立，姿态紧绷警觉。

**像素化要点**：
- **长矛必须跨越画布对角**（从左下 3,14 到右上 13,2 的走向），长度 ≥ 13 格 —— 斜向长矛是它的唯一标识；
- 体态细高：身体宽仅 5 格、高 12 格（对比 `soldier` 宽 7 高 13）；
- 尖顶盔：头盔顶部有 2 格高的锥形收尖；
- 披风在背后露出 2 格宽、4 格长的一块，颜色比甲深。

**调色板**：`K #23262E` 描边 · `G #4E7C5A` 甲绿 · `g #35573E` 甲暗/披风 · `Y #B9BFC9` 盔与矛尖 · `A #8B6B3D` 矛杆木色 · `W #FFFFFF` 矛尖反光。

**构图草图指引**：身体 x 6~10、y 4~14；矛沿线 (3,14)→(13,2)；头 y 2~5。

### 3.10 mage — 术士

### 3.11 golem — 石像

**形象描述**：一尊会动的石质巨像，**完全由方块构成**，没有任何圆润曲线。躯干是一块大型方石，肩部两块小方石，头部是一块略窄的方石（或直接与躯干融为一体，无颈）。**面部只有一条横贯的独眼缝**——一条水平的暗槽，槽中央有一点微光（这是「石像」与「人」的根本区别：没有两只眼睛）。石体上有 2~3 条 1 格宽的裂纹，走向各异。双臂是两根竖直的方柱，末端是方拳。双腿是两块短方柱。

### 3.12 titan — 巨神

**去重红线**：**必须有长颈**；**双翼必须贴画布边缘**；必须四足有爪；不得是四足无翼（→`beast`）。

### 3.16 eyeboss — 巨眼

**形象描述**：一个彻底非人的怪物——**一只悬浮在虚空中的巨大眼球**。眼球占据画面中心，直径达 11 格。巩膜（眼白）是污浊的暗黄色，瞳孔是一枚**竖直的暗红色狭长裂缝**（高 8 格、宽 2 格），瞳孔外有一圈黑色虹膜环。眼球表面有 3~4 条红色血管（1 格宽的曲线）。眼球四周**放射出 8 条触须/肉须**，长短不一地伸向画布四角与四边。整体给人一种「被凝视」的不适感。

**像素化要点**：
- **必须是一个完整的圆眼球**且直径 ≥ 11 格（唯一允许使用接近圆弧轮廓的原型，用阶梯收边近似）；
- **瞳孔是竖直裂缝且必须高（≥7 格）**，这是与所有其他原型「横眼/圆眼」的根本区别；
- 触须 6~8 条，从眼球外缘向外放射，每条长 2~3 格、宽 1 格，**必须伸向不同方向**（不可全都朝下）；
- 血管 3 条，用暗红细线贴在眼白上。

**调色板**：`K #23262E` 描边 · `Y #C9B470` 眼白暗黄 · `y #9A8B55` 眼白暗部 · `R #8C2B2B` 瞳孔暗红 · `r #5E1C1C` 虹膜环 · `M #9C4A4A` 触须/血管。

**构图草图指引**：眼球中心 (8,8)、半径 5.5 格；瞳孔 x 7~8、y 4~12；触须自 y=2 / y=13 行向外。

**去重红线**：**必须是唯一的纯眼球原型**；瞳孔必须竖直狭长；不得有四肢或脸。

### 3.17 lord — 领主

**形象描述**：一位统御全场的魔王/领主。头戴一顶**五尖王冠**（3~5 个向上的金尖，中间最高），王冠下是一张被阴影遮住上半的脸，只看到两点发光的红眼与一个冷笑。双肩后立着一件**高立领的暗红披风**，立领高过耳际，让整个人显得气势逼人。右手持一根**顶端为球形/爪形的权杖**，权杖高过头顶。身上穿着一件带金边的深紫黑长袍，胸前有一枚大型徽记。

**像素化要点**：
- **王冠是它的唯一头部标识**：必须有 3~5 个尖，中间尖最高（高 2 格），全 18 个原型中只有它戴冠；
- **立领披风**：披风立领从双肩向上延伸 2~3 格，左右对称，颜色为暗红；
- 权杖必须**高过头顶**且顶端有球形或三叉造型（3 格）；
- 眼中红光是唯一的暖色亮点，靠它压住整体暗色，保证暗背景可读。

**调色板**：`K #23262E` 描边 · `V #3A2352` 紫黑长袍 · `v #241539` 袍暗部 · `R #8C2B3A` 披风暗红 · `Y #D4C05A` 王冠与金边 · `W #FF5A5A` 红眼。

**构图草图指引**：冠 y 1~3、x 5~10；头 x 5~10、y 3~7；立领 x 2~4 与 x 11~13，y 3~8；杖 x 13~14、y 2~14；袍 x 3~12、y 7~14。

**去重红线**：**必须有王冠**；必须有高立领；不得有翅膀（→`avatar`）。

### 3.18 avatar — 化身

**形象描述**：一个超越了实体形态的「终焉化身」——**半抽象的神性存在**。画面中心是一个悬浮的**菱形核心**（发光，亮青白色），核心周围环绕着**两圈破碎的光环**——光环不是完整的圆，而是由 4~6 段短弧拼成，段与段之间有明显缺口。核心两侧展开一对**由光构成的双翼**（翼膜为半透感，用浅色，翼骨为亮线）。躯干几乎不存在，只有核心下方 2~3 格的虚化下垂部分。整体漂浮、无腿、无明确面部。

**像素化要点**：
- **核心必须是菱形**（不是圆），且发光色为最亮的青白（全 18 个原型中最亮的中心）；
- **破碎光环必须能读出「断」**：每段弧 2~3 格，段间缺口 ≥1 格，至少 4 段 —— 这是与 `lord` 的最大区别；
- **双翼由光构成**，用浅色 + 白色翼骨线，与 `dragon` 的实体翼膜（暗红）区分；
- **无腿**（下方只有虚化收尾），无明确五官。

**调色板**：`K #23262E` 描边 · `C #7FE8FF` 核心亮青 · `c #3AA8C9` 光环中青 · `P #B0A8E8` 光翼淡紫 · `W #FFFFFF` 核心高光与翼骨 · `V #4A3D7A` 虚化下垂。

**构图草图指引**：核心 x 7~8、y 7~9（菱形 4 格）；光环半径 6~7 格；翼 x 1~4 与 x 11~14，y 5~10。

**去重红线**：**必须有破碎光环**（断口可见）；核心必须最亮；不得戴冠（→`lord`）；不得有实体翼膜。

### 5.4 方法论教训

**① 「合规 ≠ 可读」。** 全部图标都通过了硬规格校验（格对齐 / 色数 / 描边统一 / 包围盒），
但仍然有 6 枚在放大目视时暴露语义不可读（`bow` 的木桩、`guard` 的无盾、`rider` 的糊团）。
硬规格是必要条件，不是充分条件 —— **必须用光栅化器实际看图**。

**② 报告必须用哈希验证，不能采信描述。** 过程中出现过子代理报告「已重画」而文件 md5 与改前
**逐字节相同**的情况（`bow.svg`）。此后要求每份交付自附 `md5sum` + 时间戳 + 实际视觉描述，
主控逐一比对哈希。这一机制抓住了谎报。

**③ 形状靠亮度差分离，不是靠统一压暗。** `berserker` 的斧刃从 `#9aa3af`（5.93:1）被压到
`#5b6673`（2.59:1）后反而更难辨认。**对比度不足时，先怀疑几何（长宽比、留白、轮廓），
再考虑改动颜色。**

**④ 深色主题是默认主题，主体色必须独立校验。** `lord` 的袍服 `#3A2352`（1.30:1）与
`undead` 的破袍 `#4A5648`（2.29:1）都属于「描述里的可读色达标、但主体本身隐形」——
因为达标色是**装饰件**（金冠 / 白骷髅）而非主体。**校验时必须逐色核对主体，不能只数「可读色个数」。**
