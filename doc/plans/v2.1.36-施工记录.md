## 1. 现状勘察（改之前的事实）

- `page/levels.js` 的 `LEVELS` 是**手写数据**（不是程序化生成），当前 **30 章 / 171 关**。
  ⚠️ 与敌群（`group-levels.js`，程序化生成）是**两套系统**，别混。
- 编排规则（chap22 起统一）：
  `x-1` 均衡 / `x-2` 高攻低防 / `x-3` 高防高血 / `x-4` 最高攻 / `x-5` 次高攻 / `x-6` BOSS（`boss:true, dualAffix:true`）。

- 数值取整习惯：atk / def / hp / soulAtk / soulDef **一律取 5 的倍数**。
- 章数派生：`game-render.js` 用 `Object.keys(LEVELS).length` 算章数徽标，解锁链与 `findLevel` 也是派生的
  → **扩章只需往 `LEVELS` 加 chap 块**，无硬编码残留（v2.1.32 已验证）。
- dundun **当前实际属性**（v2.1.34 起测量基准）：攻5686 / 防2756 / 血60290 / 魂攻770 / 魂防177。

### ⚠️ chap32/33 断层根因（未改，移交决策）

不是数值外推问题，是**单敌战斗的结构性事实**：`battle.js` 敌人每回合打两次
（物理 `rollDamage(enemy.atk, player.def, 3)` + 魂伤 `rollDamage(enemy.soulAtk, player.soulDef, 3)`）。
玩家魂防仅 **177**（魂攻 770，典型「只堆魂攻」build）→ chap32-3 光魂伤就 2112/回合，与物理量级相当；
而玩家魂攻 770 打敌人 soulDef 1830 → `max(1, 770-915)` = 1 点，等于白给。
净效果：**敌人实际 DPS 接近翻倍**。三个可选方向：① 维持现状（逼玩家补魂防，符合养成选择）
② 给后半段敌人 soulAtk 降权 ③ 给单敌战的玩家魂防加保底。**未擅自改，待 dundun 拍板。**

### 踩坑（本次新增，已写进 changelog）

- ⚠️ **单敌 `b.winner` 是布尔值**（`true` = 玩家胜），与群战字符串 `'ally'` 不同。
  写成 `'player'` 恒为假 → 测量显示「全败」。
- ⚠️ **普通关不吃词条**：`var affix = lv.boss ? rollBossAffixFor(lv) : null`（`game-battle.js:55`）。一律给药会测偏。
- ✅ **校验法（值得沿用）**：先看能不能复现上一版已知结论（chap28~30 普通关应全 100%），
  复现得了才采信新数据。本版就是靠这条抓出上面两个 bug。
