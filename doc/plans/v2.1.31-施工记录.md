## 1. 现状勘察（改之前的事实）

- `page/skill.js:457`（改前行号 441）`lastword`（遗言）：`cooldown: 7, startCooldown: 10`。
- **`startCooldown` 全项目只有两处引用**：定义处、以及 `game-render.js:1173` 把它**展示**给玩家看。
  → 没有任何结算/初始化读它 —— 典型「写了不读的标记」（PITFALL-12）。
- 设计文档 `doc/2.0 敌群设计.md:173`「遗言」原文：
  > 战斗开始，该技能进入冷却状态。发动后，自身阵亡，使敌方随机 1 名敌人攻击·魂攻击大幅度降低。
  > 同时每回合受到最大生命值的伤害（受到自身魂防御降低），持续回合：7 回合
  > 异常状态等级：特级 · **起始冷却：7-13 回合**
- `ai.js:88-97` 只在「`_tier==='boss'` 且自身血量 <35%」时才走特级负面分支；
  其余情况落到末尾「70% 最强 / 30% 随机」分支，而遗言的 `power`/`priority` 均为 0
  → **满血也会被随机抽中并自爆**。
- 冷却基础设施是齐的：`setSkillCooldown` / `skillOnCooldown` / `usableSkills`（过滤冷却中）
  / `tickSkillCooldowns`（`battle-group.js:752` 每次行动末尾递减）。**唯一缺的就是初始化那一步。**

## 2. 做法

### A. 接线点选在 `createUnit`

```js
/* skill.js —— 新增消费点 */
function applyStartCooldowns(unit) {
  if (!unit || !unit.skills || !unit.skills.length) return unit;
  unit.skills.forEach(function (id) {
    var d = SKILLS[id];
    if (d && d.startCooldown > 0) setSkillCooldown(unit, id, d.startCooldown);
  });
  return unit;
}

/* unit.js —— createUnit 末尾 */
if (typeof applyStartCooldowns === 'function') applyStartCooldowns(unit);
```

**为什么是 `createUnit`**：它是敌人 / 宠物 / 玩家**共用的唯一工厂入口**
（`createEnemyUnit`、`createPetUnit` 都走它），接这一处即可全覆盖，不必逐个战斗入口改。

**为什么用 `typeof` 判定**：`index.html` 的加载顺序是 `unit.js → … → skill.js`，
`createUnit` 只在**运行期**被调用，此时 `skill.js` 已加载；但部分测试只加载子集，
`typeof` 判定既避免加载顺序崩，也不影响正常运行。

### B. 防回归断言（`test-group-battle.js`）

1. 带 `lastword` 的单位**开场必须处于冷却**（`skillOnCooldown` 为真、`usableSkills` 不含它）
2. **递减 10 回合后恢复可用**（防止「冷却永不结束」的反向写错）
3. 未声明 `startCooldown` 的技能**不受影响**（`usableSkills` 仍含它）

## 5. 踩坑（本次新增）

- ⚠️ **断言别写「不存在的容器」**：我第一版写 `createUnit({skills:['charge']}).counters.cd.charge === undefined` ——
  但没有 `startCooldown` 的技能**根本不会创建 `counters.cd`**，于是直接 `TypeError` 让整个套件崩掉（退出码 1）。
  判据应盯着**真实可观察的行为**（`usableSkills` 含不含该技能），而不是去读一个可能不存在的中间结构。
- ⚠️ **多命令串联时别被输出串行误导**：`cmd1; cmd2` 两条 node 输出混在一起时，
  我把 A 套件的失败与 B 套件的「40 通过」看串了，一度以为 A 套件断言数是 40。
  **单独跑一遍并看退出码**才是可靠的。
