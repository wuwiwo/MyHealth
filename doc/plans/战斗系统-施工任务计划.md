# MyHealth 战斗系统施工任务计划

> 本文是施工任务表，不是代码变更记录。根据三轮审计、只读复核、63 套件全量实跑与真实 Chromium 验证整理。
> **施工前须重新确认 HEAD、工作树、`APP_VERSION` 与版本台账；不要按本文的旧基线直接开工。**

## 1. 目标、范围与基线

### 目标

1. 先修会造成错误胜负、错误 HP/目标/伤害结算的引擎问题，再修表现层。
2. 对每个“大类代码修改”推进 minor 版本 0.1：从 `2.4.10` 后首个大类用 `2.5.0`；同一大类内独立的小类可使用 patch，如 `2.5.1`。下一大类从 `2.6.0` 开始。
3. 纯文档计划或规范勘误遵循 `AGENTS.md`：`docs:` 提交，不 bump `APP_VERSION`。
4. 待作者裁决事项不得先实现、不得预分配版本；保持单敌与敌群两套引擎边界，不借修复扩大为全局重构。

### 已有证据基线

- 最近一次全量测试实跑：**63 套件 / 4,379 断言 / 0 失败**。施工时必须重新运行，本文数字只作参考基线。
- 已确认：真实敌群回合结束阶段没有应用场地 callback 返回的 `damage/statusApps`，只记录事件。`page/battle-group.js:1528-1534` 对比 `page/terrain.js:29-48`；现有 `test-terrain.js` 直接测试 helper，没有覆盖真实回合阶段。

- 已确认：玩家主动技能直接扣血并读取 `base.soulAtk`；`page/player-skill-hooks.js:306-355`。事件缺 `type/targetId` 会影响战报统计与飘字；`page/game-render.js:606-633,1052-1100`。

## 4. 各任务的统一修改提示

每个施工任务单应至少写清：目的、引擎范围（单敌/敌群）、根因、明确要改的文件/函数、不得触碰的未决规则、测试、验收标准、数值/RNG影响、版本号、交付物。修改提示：

- 修根因，不把真实入口问题只修在测试 helper；不以“代码运行成功”作为通过。
- 保持小步、按任务类别发布；一次只允许一项施工任务写入同一热点文件，避免多个会话同时改 `battle-group.js`、`player-skill-hooks.js`、`game-render.js`。
- 不改弱化/删除测试来迎合代码；新增测试应能在旧实现上失败，并锁住行为而非特定源码字面形式（除非这是刻意的架构守卫）。
- 随机行为必须注入固定种子；检查目标唯一性、RNG 消耗、全局输出与实际 HP 变化。
- 任何会改数值或胜率的任务均需报告固定种子前后胜负、回合数、各单位 HP、关键日志，并解释是否改变难度。
- UI 任务只能消费结算事实，不能反向改战斗引擎结果；浏览器测试需要保存视口、抽屉状态、速度档及截图/测量证据。

## 5. 交付标准与每版发布清单

### 代码任务交付

1. 代码改动仅限该任务范围；明确标出 `page/` 单敌或敌群引擎，不能用一边测试冒充另一边覆盖。
2. 对应现存测试扩展到行为级断言；新增测试文件只有在现有套件无法合理承载时才创建，并在计划中标注为“新增”。
3. 相关子集与全量测试均通过；全量运行器须确认 63 套件等当前实时套件全部执行且无解析漏项。
4. 有随机逻辑的固定种子回归通过；有数值影响时附平衡差异说明；UI 改动附真实 Chromium 验收。
5. 提交前 diff 只含当前任务文件；不夹带已有 `_tmp-*` 目录/并行改动。

### 每个代码版本必须同次提交

- `page/utils.js`：`APP_VERSION`。
- `page/index.html`：相关 JS/CSS `?vNN` cache-busting（值以当前源码为准）。
- `README.md`：顶部版本、版本表、当前 changelog 指向；文件树若新增/删除文件需更新。
- `doc/changelog-vX.Y.md`：只记录当前 release，包含“新增功能 / 修复 / UI 调整”分类与文件清单。
- changelog 架构演化表：保留 v1.0 至今历史，补充真实 `page/*.js` 文件数和最大文件行数。
- `doc/VERSION-LEDGER.md`：确认并登记 release 号、状态、提交哈希、changelog 路径。
- 新增/删除模块时检查 `CONTEXT.md` 模块列表；只改 `doc/` 的设计勘误按 `AGENTS.md` 使用 `docs:`，不 bump。
