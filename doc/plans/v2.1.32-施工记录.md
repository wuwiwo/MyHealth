## 1. 现状勘察（改之前的事实）

- `LEVELS` 是**手写常量**：`chap1~chap21`，每章 `{name, levels[]}`；chap1~3 各 3 关，**chap4 起固定 6 关**
  （x-1 均衡 / x-2 高攻低防 / x-3 高防高血 / x-4 最高攻 / x-5 次高攻 / x-6 BOSS）。
- chap16 起 BOSS 带 `dualAffix: true`（双词条）。
- **章数没有硬编码**（`grep` 复核）：
  - UI 徽标 `game-views.js:217` → `Object.keys(LEVELS).length`
  - 解锁链 `game-render.js:184 allPrevCleared()` → 遍历 `Object.entries(LEVELS)`
  - `battle.js:112 findLevel()` → 遍历 `Object.values(LEVELS)`
  - 下一关推进 `game-battle.js:157` → 遍历 `LEVELS` 找当前关的下一个
  → **加章只需往 `LEVELS` 加对象**，其余全部自动跟随。
- chap19→20→21 的逐字段比值稳定在 **1.113×/章**（atk/def/hp/魂攻/魂防 五个字段都是）。

## 2. 做法

### A. 加 3 章

数值 = chap21 × 1.113（取整到 5/10），编排照抄 chap4 起的固定形态，BOSS 带 `dualAffix`。
命名延续「超越极限」的递进：**22 界限突破 / 23 诸神黄昏 / 24 万象终章**。

### B. 测量口径

真实单敌引擎：`buildBattleSides` + `rollBossAffixFor` + `createBattle` + `battleTick`（注入 `mulberry32` 种子）。
基准账号沿用敌群实测的 攻2883/防1145/血24800/魂攻532/魂防99，扫倍率求 50% 胜率门槛。

### C. 技能审计方法

1. 从 `SKILLS` 注册表枚举全部**定义字段**，逐个统计「写入处之外」的读取点 → 找死字段
2. 枚举 `r.statusApps` / `r.heals` / `r.buffs` 三种结果通道负载里的**全部键**，逐个查消费者
3. 对每个技能，把**设计文档原文**与**实现**逐条比对（`doc/2.0 敌群设计.md` 技能章 + `doc/design-v2.0.md` §1 玩家技能）
4. 对玩家技能（`skills.js` 的 `effect(lv)` 字段）做同样的字段消费统计

## 3. 结果

### A/B. 关卡试炼扩章 + 实测

- 章数 **24**、总关数 **135**（3×3 + 21×6）
- 新增：chap22 界限突破 / chap23 诸神黄昏 / chap24 万象终章
- 实测（trials=12）：

| 章 | 22-1~24-5 普通关（1×） | BOSS 50% 门槛 |
|---|---|---|
| chap22 | 100% | 0.875× |
| chap23 | 100% | **0.975×** |
| chap24 | 100% | **1.075×** |

- 阶梯连续（每章 ≈1.11×），**chap24 BOSS 只需再练 +7.5% 属性**；非 BOSS 关在 1× 下全通
- **既有章零回归**：chap17~20 仍是 0.625×、chap21 仍 0.875×（与新增前一致）

### C/D. 技能审计：修掉 1 处死接线

**`skillsDisabled` mutation 无消费者** —— 末日（`doomed`）的 `onBeforeAction` 产出它，
但 `battle-group.js` 只读了同一 dispatch 结果里的 `skipAction`，mutation 被丢掉
→ 详情页（`SKILL_DOCS.doom`）写着「技能不可用」，实战照样放技能。

修法：`groupUnitTurn` 读 `before.mutations` 的 `skillsDisabled` → 本回合跳过技能选择、退化为普攻（仍会行动）+ 说明日志。

⚠️ **藏这么久的原因**：`test-status.js:85` 只断言 mutation「**被生产**」——
判据盯着中间结构（PITFALL-11 同类）。本版补 5 条**行为**断言（对照/禁用/仍普攻/日志/玩家侧）。
