### 1.2 行动队列如何确定

- `buildActionQueue(gb)`：取存活单位 → 按 `unitInitiative` 降序 → 同值 tie-break（**同速我方先手**，同方按 `gb.units` 里的创建序稳定排序）。证据：`battle-group.js:346-356`。
- `unitInitiative(u, skill)`：`effectiveSpeed(u)` +（`skill.priority×50`）+（`u._taunting` → `spd×=2`）。证据：`battle-group.js:338-343`。
- ⚠️ **先制度（priority）实际不进队列**：`buildActionQueue` 调用时第二个实参恒为 `null`（`battle-group.js:349-350`），`SKILLS[skill].priority` 分支（`:340`）因此永不命中。`priority` 目前只被 AI 选技评分读到（`ai.js:104`），而 UI 文案写「出手队列中优先行动」（`game-render.js:2112`）。
- 队列在**每回合开始**重建一次；建队列前统一 `refreshAllStatMods(gb.units)`，否则减速类状态影响不到出手顺序（`battle-group.js:1245-1246` / `1175-1176`）。
- 「反转场地」不影响队列：`buildActionQueue` 不读 `gb.terrain`（`battle-group.js:346-356`），场地本体也只产出一条日志（`terrain.js:147-155`）。

### 1.5 回合号 `gb.turn` 与 `onTurnStart` / `onTurnEnd` 的作用范围（结论）

- `gb.turn` 自增点：`battle-group.js:1243`（step，队列为空时）/ `1168`（tick），每次 +1 = 一个「回合」。
- 传给单位钩子的 `turn` 是 **`gb.turn + 1`**（`battle-group.js:942`），即**首回合传入 2**；`onBattleStart` 发生在 `gb.turn === 0`。`slowstart` 因此单独收 `ctx.actualTurn = gb.turn`（`969-972`、`talent.js:444-450`）。
- **`onTurnStart` / `onTurnEnd` 是「每个单位每次行动」各触发一次，不是「每回合一次」**：
  - 两个派发点都在 `groupUnitTurn` 内部（`961`、`1093`），而 `groupUnitTurn` 由队列逐单位调用（`1278`，tick 为 `1180`）。
  - 一个回合里 N 个存活单位 → 各钩子触发 N 次（每单位 1 次）。
  - 额外行动（疾影 `extraAction`）会对同一个单位再跑一遍 `groupUnitTurn`（`1287` / `1188`）→ 该单位同一回合内这两组钩子各触发**两次**。
  - 对比：`onBattleStart` 是每场每方一次（`1140-1141`），场地钩子是每回合一次（`1251`/`1262`）。

## 8. 需要作者注意的地方（只列事实与风险）

### 8.1 移到「准备阶段」会改变强弱的效果（依赖「自己行动前/后」语义）

1. **灵感涌动**（`pet-codex.js:442-458`）：`onTurnStart` 与 `onTurnEnd` 的派发点（`battle-group.js:961`、`1093`）都在**梦幻自己**的同一次 `groupUnitTurn` 内。当前效果 = 「随机 1 名友方魂攻 +20%，只持续到梦幻自己的行动结束」——**在梦幻之后出手的队友拿不到**，命中自己或先手队友才有意义。这正是任务里举的例子。
2. **气势如虹 / 气力恢复 / 瞩目 / 启风①**（`player-skill-hooks.js:120-199`）：挂点是 `battle-group.js:956`，只在**玩家单位自己**的回合开始触发（`actor.side==='ally' && actor._playerSkills`）。宠物档「气力恢复」挂在**宠物自己**回合开始（`124-131`）。
3. **复仇**（`talent.js:534-560`）：`onTurnStart` 读取的是**该单位自己行动开始时**的血量快照；挪到统一的准备阶段，读到的血量与层数会不同。
4. **威吓解除**（`talent.js:374-389`）：解除判定挂在**施加者自己**的回合开始（`961`），条件是「血量 <50% 或 5~10 回合走完」。
5. **慢启动 / 懒惰**（`talent.js:436-453`、`459-479`）：都依赖 `onBeforeAction`（`974`）与 `ctx.actualTurn = gb.turn`（`969-972`）；懒惰还依赖 `_lazySkip` 这个「本回合是否放弃行动」的瞬时标记。
6. **嘲讽**（`skill.js:470-480` + `battle-group.js:950-953`）：失效时点 = 该单位**下一次行动开始**；同时影响选目标（`423`）与出手排序（`341`）。
7. **幽魂附身**（`skill.js:84-96`、`battle-group.js:994`/`1108`）：禁技与「冷却暂停」的窗口 = 该单位本回合行动内。
8. **再生 / 振翅**（`talent.js:576-592`、`219-234`）：`onTurnEnd` 用 `ctx.turn`（= 实际回合号 +1）取模与累加，触发次数取决于「该单位这一回合是否跑了回合末」。
9. **蓄力释放点**（`battle-group.js:999-1009`）：释放被设计为「占用该单位的这次行动」（`acted = true`）；如果释放被挪到与行动无关的相位，需另行裁定是否仍占行动。
10. **状态 duration 的递减点**（`battle-group.js:1103`）在**单位自己回合末**：任何相位调整都会改变同一 duration 的实际覆盖长度（最多差一个单位行动）。

### 8.4 目前是「每单位触发」而不是「每回合触发」的 hook

**`onTurnStart`、`onTurnEnd`、`onBeforeAction`、`onAfterAction` 全部是每单位触发**（派发点位于 `groupUnitTurn` 内：`961`、`1093`、`974`、`1091`），并且：

- 一回合内 N 个存活单位 → 各触发 N 次；
- 同一单位因疾影额外行动（`1287` / `1188`）会再触发一轮；
- `onAfterAction` 每个单位每次行动触发**两次**（`1091` 丢弃 mutations + `1281`/`1182` 消费 mutations）；
- `onBeforeAction` 每次行动最多派发 **3 次**（状态侧 `973`、天赋侧 `974`、普攻分支 `1064`），其中只有 `974` 的 `skipAction` 生效（`1065-1066` 只取 `multiTarget`，`skipAction` 被忽略）。

对照：`onBattleStart` 每场每方一次（`1140-1141`）；场地 `onTurnStart`/`onTurnEnd` 每回合一次（`1251-1256` / `1260-1265`）；`playerSkillBattleStart` 每场一次（`1236-1242`）。

## 9. 拟定的四阶段模型（主控草案，待作者裁定）

### 9.1 现在的时序 vs 拟定时序

| | 现在（实测，带行号） | 拟定 |
|---|---|---|
| 回合开始 | `gb.turn++`(1243) → `refreshAllStatMods`(1245) → `buildActionQueue`(1246) → `resolveIceFollowUps`(1251) → 场地 `onTurnStart`(1253) | **准备阶段**（每回合一次，队列建立之前） |
| 各单位行动 | 按队列逐个 `groupUnitTurn(gb, u)`(1278)；内部：天赋 `onTurnStart`(961) → 状态 `onTurnStart`(965) → `onBeforeAction`(973/974) → 蓄力释放(1004) 或 技能(1053)/普攻(1080) → `onAfterAction`(1091) → `onTurnEnd`(1093/1095) | **行动阶段**（保留技能/普攻/伤害/治疗/状态**施加**；把「天赋 `onTurnStart`」上移到准备阶段） |
| 状态结算 | 混在**每个单位**自己的 `onTurnEnd`(1095) 里（dot、duration 递减、到期） | **判定阶段**（每回合一次，队列跑完之后统一结算） |
| 回合收尾 | 场地 `onTurnEnd`(1262) → `_stepQueue=null` → 胜负检查(1268) | **结束阶段**（场地 `onTurnEnd` + 回合末清理 + 胜负判定） |

### 9.2 四个阶段的职责（草案）

**① 准备阶段**（每回合一次，在行动队列之前）
- 场地 `onTurnStart`（雨天等）
- 冰魄余威（`resolveIceFollowUps`，设计上就是「回合开始触发、不占行动」）
- **全局型天赋的回合开始效果**（例：✨ 灵感涌动 给队友加 魂攻%）→ **本阶段的核心目的**：让这类效果在**行动阶段之前**落地，从而影响本回合出手的角色
- 属性修正重算（`refreshAllStatMods`）与**行动队列重算**（减速/加速要在排队前生效）
- ⚠️ 关键取舍：现在这些「回合开始」效果是**每个单位轮到自己时**才触发（961），改成每回合一次会**改变强弱**（见 9.4）

**② 行动阶段**（按行动队列逐个单位）
- 保留：`onBeforeAction`（状态 + 天赋）、技能施放 / 普攻、目标选择、伤害/治疗/护盾吸收结算、状态**施加**、`onAfterAction`（疾影的额外行动）、破盾反伤、启风的额外普攻
- 移出：天赋 `onTurnStart`（去准备阶段）

**③ 判定阶段**（每回合一次，所有单位行动完之后）
- 状态的**持续伤害** tick（中毒 / 附身侵蚀 / 末日 / 遗言）
- 状态 **duration 递减与到期**（「⏳ X 的【…】结束」）
- 蓄力类「下回合结算」的统一结算（现在在行动者自己的行动内 1004）
- 护盾 / 免疫的到期检查

**④ 结束阶段**（每回合一次，判定之后）
- 场地 `onTurnEnd`
- 回合级标记清理（`_qifengTurn` 等「每回合一次」守卫）
- 胜负判定（`gb.done` / `winner`）
- 下一个回合的准备
