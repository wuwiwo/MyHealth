## 2. 口径披露（复现前必读）

### 2.1 技能装配（`--skills` 指定的就是这一份）

`crit:20,block:10,vitality:20,goldshield:20,spotlight:10` —— **5 个技能全部顶到 `maxLevel`**：

| id | 名称 | 类型 | 等级/上限 | 本档效果（取自 `page/skills.js`） |
|---|---|---|---|---|
| `crit` | 暴击 | passive | 20/20 | 玩家 30% 暴击 / ×3.0；**宠物档** 15% / ×1.6 |
| `block` | 格挡 | passive | 10/10 | 常驻减伤 10% + 20% 格挡 −75% + 5% 完美格挡 (−90~99%)；宠物档无完美格挡 |
| `vitality` | 气力恢复 | support | 20/20 | 每 4 回合后 2 回合，每回合回 (防+魂防)×200%；宠物档每 5 回合 ×120% |
| `goldshield` | 金身护盾 | passive | 20/20 | 开战全队盾 (攻+魂攻)×500% + 免疫负面；破盾反伤 |
| `spotlight` | 瞩目 | support | 10/10 | 40% 嘲讽 1 回合；回合末全体回复 (防+魂防)×受击次数 |

### 2.2 宠物共享档 —— **含在内**

`balance-pets-ab.js:112`（v2.2.8 起）：
```js
if (typeof sb.attachPetSharedSkills === 'function') sb.attachPetSharedSkills(pets, sst);
```
**同一份 5 技能装配同时挂到玩家与 4 只参战宠**，且两列（无技能 / 含技能）共用同一份种子与同一套宠物，属公平对照。

⚠️ **因此「无技能 → 含技能」这一列差值是「玩家档 + 宠物共享档」的合并效果，本测量无法把两者拆开。**
（历史上的 WP-B 数字是分离的，但那是另一套工具/口径。）

### 2.3 未含（本次测量的已知空白）

- **宝珠**：`seedStore` 写 `orbs: []` → 宠物宝珠 0 颗。
- **宠物养成**：4 只均为 `refineLevel 0` / `refineStats {}` / `skillLevels {}` / `stage: mature` = **裸图鉴下限**；
  参战宠固定为 `sparkle(R) / chirpbird(SR) / icecrystal(SSR) / dream(UR)`（脚本内 `PETS` 常量，非玩家实际编队）。
- **宠物天赋/词条**：未挂任何 `petOnly` 天赋。
- **玩家侧**：无炼魂、无装备、无词条（只走 `inheritGroupStats` 的 50% 继承 + 技能）。

## 3. 异常 / 存疑点

1. **`g19` 是局部低谷：`g19` = 0%，而 `g20` = 8%（40t）**——阶梯**非单调**。40 trials 下 g19 为 0/40。
   推测 `g19` Boss 有克制本档配装（高魂防 / 免疫负面 → 直接吃掉 `goldshield` 的免疫与 `spotlight` 的嘲讽）的机制，
   但**本次未展开验证**，仅记录现象。
2. **12 trials 的采样噪声明显**：`g18` 含技能新旧宠 = 100% vs 92%、`g20` 含技能新宠 = 0% 但 40t = 8%（0/12 vs 3/40）。
   → **任何单点 8~92% 的值都不可当作稳定结论，12 trials 只适合分辨「0 / 中间 / 100」三档。**
3. **`g15` 在无技能口径下从 33%（12t 旧宠）跳到 88%（40t 新宠）**：说明 `g15` 刚好卡在宠物规则的临界线上，
   对宠物规则与样本量都高度敏感。
4. **`g16` 无技能新宠 40t = 98%（掉 1 局）**：属噪声，不是回退。
5. **脚本没有「只跑某一个大关」的开关**（`GROUPS` 是硬编码 14 个大关）。
   → 任务要求「边界大关单独 `--trials 40` 复测」的等价做法是**整条阶梯用 `--trials 40` 重跑**（本次即如此，见 §4），
   比只测单关更严格（一次覆盖 g15/g16/g17/g18/g20 全部边界点）。**未改动脚本源码。**
6. **未启用退路**：`git worktree add` 在 Windows 上**一次成功**，未走「复制 `page/` + `scripts/` 到 scratchpad」的备用方案。
7. 脚本自带的自检（注释要求 `g6/g10/g13` 恒为 100%）**在本快照复现通过**，故本次数据采信。

## 5. ⚠️ 对比警示：与 v2.2.9 及更早的数字**不可直接逐格对比**

v2.2.10 的 WP-D 做了两件**破坏性**的事（见 `doc/plans/v2.2.10-施工记录.md` §2.1 第 5 条）：

1. **暴击结算合并**：旧实现是 `playerCritHook()`（玩家/宠物档）与 `talentCrit()`（斗者本能）**两段独立掷骰、双重叠乘**
   （同时命中即 ×1.5 × 1.6 = **×2.4**）；v2.2.10 改为 `groupCritMult()` —— 两边**分别掷骰**、**都触发时取较高倍率**、**只结算一次**。
   → 宠物侧是**净削弱**（原本可能吃到 ×2.4 的组合被压到最高 ×1.6）。
2. **`gb.rng()` 调用顺序/次数改变**：掷骰从「两处各一次」变为「合并后的调用序列」。

合起来意味着：**即使 seed 完全相同，v2.2.10 的随机流与 v2.2.9 及更早不再对齐**。
所以：

- 本表数字**不能**与任何 v2.2.9 之前（含历史 `balance-pets-ab.js` 输出、历史 changelog 里的通过率）**逐格相减或做同比**。
- 本表只能作为 **v2.2.10 起点基线**；后续版本的平衡对比必须以本表（或同一 commit 重跑值）为基准。
- 同理，`--account old`（旧基准账号）的历史阶梯同样不再可比，本报告因此**只在需要时才用 `--account now`**。
