## 0. ⚠️ 先读：文档编号有出入（本任务最大的坑）

`v2.2-施工计划.md` §6.4 写的是「`page/talent.js` —— **宠物天赋** 14 条」，用户任务单也沿用「宠物天赋（14 条）」。
但事实是：

| 说法 | 实际位置 | 内容 |
|---|---|---|
| 「**14 条**」`blade / flutter / … / regen` | **`page/talent.js`** | 敌群/通用天赋（**非** `petOnly`），逐条评审在 `doc/2.2-修改提案.md` **§5.1** |
| 「**宠物天赋**」 | **`page/pet-codex.js`** | **10 条** `petOnly` 天赋（幸运口袋 / 漆黑之眼 / 凛冬之核 / 圣光守护 / 镜像结界 / 灵感涌动 / 心眼 / 斗者本能 / 不动如山 / 威压领域），评审在 **§3** |

→ 所以「按 §3 裁决逐条对齐 `page/talent.js` 的 14 条」这一句里，**§3 与那 14 个 id 不是同一批东西**。
本版按**文件 + id 清单**为准实施（即 §5.1 那 14 条），只有 **斗者本能（§3.12-1）** 确实属 §3，作为「WP-B 收口项」一并收口。

第二个出入：施工计划 §1.1 把「**敌群天赋接成长**」明确归给 **WP-F**，§6.4 的 WP-D 裁决要点又写「**不接成长**」
→ 两者一致（WP-D 不接成长）。因此 §5.1 里写「根据关卡与敌人级别，数值为 X~Y」的条目**本版不动**。

  （`talent.js:171`），**没有任何派发点**；它产出的 `reflectSupport` mutation **没有消费者** —— 免疫与反弹两项从未生效。

- `intimidate`（威吓）现仅「施加者 <50% 血」解除，无持续回合；`INTIMIDATE_ATK_DOWN = 0.4` 是 battle-group 直接读的唯一常量。
- `vengeance`（复仇）现按 `Math.floor(lost / 0.25)` 分层，每层 +10%。

  后 `talentCrit(actor)`（斗者本能）→ 同一单位同时具备两者时会**双重暴击叠乘**（×1.5×1.6 = ×2.4）。
- 状态实例形状：`applyStatus()` 建 `{id,duration,stacks,source,data,modsPct}`；`statMods()` 聚合 `def.statMods` /
  `def.statModsPct` / 实例 `st.modsPct`。状态定义可带 `positive: true`（`isPositiveStatus()` 判据）。

## 2. 逐条裁决 → 实施

### 2.1 实际改动（4 条天赋 + 1 处收口）

| # | 天赋 | 裁决来源 | 落地做法 |
|---|---|---|---|
| 1 | `magicmirror` | §5.1.5 + §5.6-3 | `castSkill` 对 `def.type === 'support'` 的**每个目标**派发 `onBeforeSupport`（**只在目标是施法者的对手时**）；命中 30% → 目标免疫 + `mirrorBlocked` 记账；反射落 `statusApps`/`heals`/`buffs` 三通道，**只反弹负面/减益类**（`!isPositiveStatus`），治疗/增益**仅免疫** |
| 2 | `plain` | §5.6-1 | 判据改「是否直接改属性」（`def.statMods`/`def.statModsPct`/实例 `modsPct`）；直接改属性→`skipAction`；混合型（`extraEffect` 标记）→ `stripStatMods` → 以 `noStatMods` 落库 |
| 3 | `intimidate` | §5.1.7 + §5.6-5 | 开场 `_intimidateTurns = 5 + floor(rnd×6)`；`onTurnStart` 改为「<50% 血 **或** 回合数走完」**先到者解除**，日志带原因 |
| 4 | `vengeance` | §5.1.13 + §5.6-6 | 间隔 25% → **20%**（`+1e-9` 防浮点少一层）；每层 +10% 不变 |
| 5 | `fighter_instinct` | §3.8 + §3.11A + §3.12-1 | 25% → **30%**；暴击合并为 `groupCritMult()`：两边**分别掷骰**、**都触发取较高倍率**、**只结算一次** |

### 2.2 配套改动（为了上面能落地）

- `page/state-core.js`：`applyStatus` 收 `opts.noStatMods`（`refresh` / `stack` / 新实例三条路径）；
  `statMods()` 见 `st.noStatMods` 直接 `continue`（跳过属性贡献，hooks 照常）。
  ⚠️ 只在 true 时写字段 → `undefined` 不进 JSON，**旧存档/快照形状不变**。
- `page/status-defs.js`：`lastworded` 加 `extraEffect: true`（它是唯一「属性修正 + 附加效果」混合的状态：
  降攻降魂攻 + 每回合掉血）。
- `page/player-skill-hooks.js`：抽出 `playerCritInfo(unit)`（返回 `{chance, critMult}`，**不掷骰**）；
  `playerCritHook` 改为调用它后掷骰（语义不变，旧测试照过）。
- `page/game-render.js`：威吓详情页文案同步「持续 5~10 回合，或威吓者血量低于 50% 时解除」。

### 2.3 判定无改动（10 条，留给 WP-F）

`blade / flutter / roughskin / vigor / magicshield / slowstart / lazy / multitarget / bloodthirst / regen`

理由：§5.1 对它们的评审一律是「**根据关卡与敌人级别**，数值为 X~Y」= **随大关/等级成长**；
施工计划 §1.1 把「敌群天赋接成长（12 条按 t）」归给 **WP-F**，§6.4 的 WP-D 也写「不接成长」。
为免后人再猜，已在 `page/talent.js` 顶部留一段说明注释把这 10 条与 4 条分列清楚。
