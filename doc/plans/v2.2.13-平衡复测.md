## 2. 口径披露（复现前必读）

### 2.1 技能装配（`--skills` 指定的就是这一份）

`crit:20,block:10,vitality:20,goldshield:20,spotlight:10` —— **5 个技能全部顶到 `maxLevel`**：

| id | 名称 | 类型 | 等级/上限 | 本档效果（取自 `page/skills.js`） |
|---|---|---|---|---|
| `crit` | 暴击 | passive | 20/20 | 玩家 30% 暴击 / ×3.0；**宠物档** 15% / ×1.6 |
| `block` | 格挡 | passive | 10/10 | 常驻减伤 10% + 20% 格挡 −75% + 5% 完美格挡 (−90~99%)；宠物档无完美格挡 |
| `vitality` | 气力恢复 | support | 20/20 | 每 4 回合后 2 回合，每回合回 (防+魂防)×200%；宠物档每 5 回合 ×120% |
| `goldshield` | 金身护盾 | passive | 20/20 | 开战全队盾 (攻+魂攻)×500% + 免疫负面；破盾反伤 |
| `spotlight` | 瞩目 | support | 10/10 | 40% 嘲讽 1 回合；回合末全体回复 (防+魂防)×受击次数 |

### 2.2 宠物共享档 —— **含在内**

`balance-pets-ab.js:112`（v2.2.8 起）：
```js
if (typeof sb.attachPetSharedSkills === 'function') sb.attachPetSharedSkills(pets, sst);
```
**同一份 5 技能装配同时挂到玩家与 4 只参战宠**，且两列（无技能 / 含技能）共用同一份种子与同一套宠物，属公平对照。

⚠️ **因此「无技能 → 含技能」这一列差值是「玩家档 + 宠物共享档」的合并效果，本测量无法把两者拆开。**
（历史上的 WP-B 数字是分离的，但那是另一套工具/口径。）

⚠️ **v2.2.12 起，宠物档在技能路径也真正生效**：`castSkill` 的技能伤害由「直接走 `talentCrit()`」改为与普攻同构的
`groupCritMult()`（`battle-group.js:517`），所以「宠物带技能出手」现在会吃到宠物暴击档（15% / ×1.6）。
这也是**含技能列**与 v2.2.11 及更早不可逐格对比的核心原因（见 §5）。

### 2.3 未含（本次测量的已知空白）

- **宝珠**：`seedStore` 写 `orbs: []` → 宠物宝珠 0 颗。
- **宠物养成/精炼**：4 只均为 `refineLevel 0` / `refineStats {}` / `skillLevels {}` / `stage: mature` = **裸图鉴下限**；
  参战宠固定为 `sparkle(R) / chirpbird(SR) / icecrystal(SSR) / dream(UR)`（脚本内 `PETS` 常量，非玩家实际编队）。
- **宠物天赋/词条**：未挂任何 `petOnly` 天赋。
- **玩家侧**：无炼魂、无装备、无词条（只走 `inheritGroupStats` 的 50% 继承 + 技能）。
- **敌群天赋「接成长」（WP-F，v2.2.10 起一直未做）**：`talent.js` 那 12 条仍是固定值，故 g19~g24 的墙角也可能部分源于此。
- **装备槽位纪律被绕过**：游戏内为「3 槽、同类型限 1」；而 `attachPlayerSkills` **不做任何槽位/类型校验**，
  脚本直接把 5 个技能（含 2 个 support：`vitality` + `spotlight`）塞进 `loadout`。
  → **本档是「技能上满」的理论配装上界，超出游戏内 3 槽上限，不是当前 UI 能实现的实际配装。**
- **幸运口袋（v2.2.13 新实现）不在测量面内**：它是**战斗胜利结算的掉落**天赋，且脚本的 4 只参战宠
  （`sparkle/chirpbird/icecrystal/dream`）**不含**携带者小负鼠（`possum`），胜负循环也在 `gb.done` 即停、
  不进入 `groupVictoryReward()`。→ **v2.2.13 的幸运口袋对本次通过率零影响**（只影响掉落层）。

## 4. 异常 / 存疑点

1. **`g19` 是局部低谷：`g19` = 0%，而 `g20` = 10%（40t）**——阶梯**非单调**。40 trials 下 g19 为 0/40。
   推测 `g19` Boss 有克制本档配装（高魂防 / 免疫负面 → 直接吃掉 `goldshield` 的免疫与 `spotlight` 的嘲讽）的机制，
   但**本次未展开验证**，仅记录现象。
2. **12 trials 会把边界带误判成「稳过」（本次最值得记住的一点）**：
   `g17`/`g18` 含技能 12t = **100%**，而 40t 只有 **93% / 95%**；`g20` 12t = **0%**、40t = **10%**。
   → **12 trials 的三个值（0 / 中间 / 100）里，「100%」不可当稳定结论**；凡落在 80~100% 之间的点必须 40t 复核。
3. **`g16` 无技能新宠 40t = 98%（掉 1 局）**：与 v2.2.10 相同，属噪声，不是回退。
4. **脚本没有「只跑某一个大关」的开关**（`GROUPS` 是硬编码 14 个大关）。
   → 任务要求「边界大关单独 `--trials 40` 复测」的等价做法是**整条阶梯用 `--trials 40` 重跑**（本次即如此，见 §5），
   比只测单关更严格（一次覆盖 g15/g16/g17/g18/g20 全部边界点）。**未改动脚本源码。**
5. **内部一致性佐证**：无技能口径（40t 新宠列）本次为 `g15 88% / g16 98% / g17+ 全 0%`，与 v2.2.10 报告**逐格一致**。
   机制上可解释：`groupCritMult()`（`battle-group.js:207-216`）**只在施法者实际带暴击档 / 天赋暴击时才多掷一次 `gb.rng()`**，
   无技能口径下宠物没有暴击档 → v2.2.12 新增的掷骰不触发 → 该列随机流未变。
   （这只是一次自洽检查，**不改变**「含技能列与 v2.2.11 不可逐格对比」的结论。）
6. **未启用退路**：`git worktree add` 在 Windows 上**一次成功**，未走「复制 `page/` + `scripts/` 到 scratchpad」的备用方案。
7. 脚本自带的自检（注释要求 `g6/g10/g13` 恒为 100%）**在本快照复现通过**，故本次数据采信。

## 6. ⚠️ 对比警示：与 v2.2.11 及更早的数字**不可直接逐格对比**

自 v2.2.11 基线之后，已叠加**两层改变随机流 / 战力口径**的变化，另有一层在 v2.2.10 已发生：

1. **v2.2.10（基线已含）**：WP-D 把玩家/宠物档暴击与天赋暴击（斗者本能）从「两段独立掷骰、双重叠乘」
   改为 `groupCritMult()` 的「分别掷骰、都触发取最高、只结算一次」，并改变 `gb.rng()` 调用顺序/次数。
   → 已使本表与 **v2.2.9 及更早**不可逐格对比。
2. **v2.2.12（第一层新变化）**：`castSkill` 的技能伤害接入 `groupCritMult()`
   （`battle-group.js:517`，见 changelog-v2.2.md `## v2.2.12` §1）。
   后果有二：**宠物技能伤害现在会暴击**（此前恒不暴击，只吃天赋 ×1.5），且**技能路径新增一次 `gb.rng()` 掷骰**
   （仅施法者带暴击档时，见 `groupCritMult` 实现）。→ **v2.2.11 记录的 g17 85% / g18 93% / g19 0% / g20 8% 不可逐格对比。**
3. **v2.2.13（第二层新变化）**：实现幸运口袋（`pet-codex.js` 的 `luckyPocketDrops()` 纯函数 + `game-render.js` 消费端）。
   它是**胜利结算掉落**天赋，不走战斗循环 → **对通过率零影响**（且本测量编队不含携带者小负鼠）。
   列在此处只为**版本完整性**，不构成一处通过率扰动。

**因此：**

- 本表数字**不能**与 v2.2.11、v2.2.10 及更早（含历史 `balance-pets-ab.js` 输出、历史 changelog 里的通过率）**逐格相减或做同比**。
- 本表只能作为 **v2.2.13 起点基线**；后续版本的平衡对比必须以本表（或同一 commit 重跑值）为基准。
- 与 v2.2.11 的关系**只允许做定性判断**（见 §3：档位是否迁移），**不允许**把两次数字相减当结论。
- 同理，`--account old`（旧基准账号）的历史阶梯同样不再可比，本报告因此**只在需要时才用 `--account now`**。
