## 0. 一句话结论

**含技能口径下，档位相对 v2.2.13 基线「零迁移」：仍可稳过到 `g16`（100%）；`g17` / `g18` 仍是边界带（40 trials：95% / 90%）；`g19` 仍是墙（恒 0%）；`g20` 仍是近墙（40 trials：8%）；`g21~g24` 恒 0%。**

**但本轮真正的发现是：v2.2.15 的唯一行为改动（广域防御减伤上限 `0.40 → 0.30`）在实测的 14 个 Boss 关里只落在 `g16`（Boss 1 个单位）与 `g18`（Boss 1 个单位）身上；`g17` / `g19` / `g20` 的 Boss 关根本不携带 `bulwark`，结构上不可能被它推动。** 而在 `g16` / `g18` 上该改动的效应也落在 40 trials 的噪声以内（一升一降各 1~2 局）。
→ **「g17/g18 是否更稳、g20 是否脱离近墙」这两个预期，本轮实测均未成立**；`g19` 仍是墙则被再次确认。

不含技能时整条阶梯仍大幅左移：`g15` 掉到 **88%**（40t）、`g16` 100%，**`g17` 起全为 0%**。

## 3. 与 v2.2.13 的定性对比（**只做定性判断，不做减法**）

> 对比对象：v2.2.13 冻结快照基线（commit `bff3767`，含技能 40 trials）：`g15 100% / g16 100% / g17 93% / g18 95% / g19 0%（墙） / g20 10%`。
> ⚠️ **两次数字不可相减**（中间叠了 v2.2.14 + v2.2.15 两层改动，敌方减伤数值变化会改变受伤/阵亡时点 → 出手序列与随机消耗可能分叉，见 §6）。以下只判断「是否仍在同一档」。

| 大关 | v2.2.13 基线（含技能 40t） | v2.2.15（含技能 40t） | 定性判定 |
|---|---|---|---|
| g15 | 100% | 100% | **稳过带未变** |
| g16 | 100% | 100% | **稳过带未变** |
| **g17** | 93% | 95% | **仍在 80~95% 边界带内 ✓（未迁移）** |
| **g18** | 95% | 90% | **仍为边界带（近满值，非恒 100%）✓（未迁移）** |
| **g19** | 0% | 0% | **仍为墙，结论未翻转 ✓** |
| **g20** | 10% | 8% | **仍为近墙（低两位数以内）✓（未迁移）** |

### 3.1 结论

**v2.2.15 的难度分档与 v2.2.13 基线一致 —— 稳过到 `g16`、`g17`/`g18` 边界、`g19` 墙、`g20` 近墙、`g21+` 不可过。三个待答问题（g17/g18 是否更稳、g20 是否脱离近墙、g19 是否仍是墙）的实测答案：**
- `g17` **仍在** 80~95% 带内（95%）；`g18` **仍在** 边界带（90%，且比基线还低 5pp）；
- `g20` **仍在**近墙（8%，比基线还低 2pp）；
- `g19` **仍是**墙（恒 0%）。
→ **档位零迁移；且「更稳/脱离」的方向不但没出现，两个点还各自轻微下行。**

### 3.2 预期落差（**如实记录，不粉饰**）

任务背景把 v2.2.15 描述为「上限从 0.40 收到 0.30」（相对 v2.2.14 是**变容易**）。但**本轮的对比基线 `bff3767` 是 v2.2.13**，在那一版里 `wideguard` 的减伤在 `status-defs.js` 中**硬编码 `0.20`**（`skill.js` 推送的 `b.value` 在 `battle-group.js` 的 buff 落地处被整个丢弃 = 死字段）。所以：

- **相对 v2.2.13 基线（恒 20%），本版（实测 30%）是「更难」，不是「更容易」**；
- 「收 0.40→0.30 = 更容易」只在**相对 v2.2.14** 时成立，而 v2.2.14 的冻结快照本轮**未测**（任务只给了 v2.2.13 基线）。

源码级证据（本次核对，非转述）：
- `page/skill.js:427`（快照）`range: { dmgReduce: [0.20, 0.30], dur: [3, 5] }`（基线同位置为 `[0.20, 0.40]`）。
- `page/battle-group.js:691`：`applyStatus(t, { id: 'wideguard', duration: dur, data: (b.value != null) ? { reduce: b.value * mul } : undefined })` —— 本版**真的把推送值落进实例 `data.reduce`**（v2.2.13 无此行）。
- `page/status-defs.js`（`wideguard.onDamage`）：本版 `var reduce = (st && st.data && typeof st.data.reduce === 'number') ? st.data.reduce : 0.20;`（基线为**硬编码** `value: 0.20`）。
- `page/skill.js:112-120` `skillRangeT(unit)`：敌方无宠物炼化标签 → `t = (unit.level − 1) / (SKILL_LEVEL_MAX − 1)`；本档敌方 `level = 10`、`SKILL_LEVEL_MAX = 10` → **t = 1（取上限）** → 实例减伤 = **0.30**，与任务口径「g10+ = 30%」吻合。

### 3.3 机制归因：本轮改动**结构上**只能触及哪些大关（只读探针实测）

`page/group-levels.js` 在 `bff3767 → 03d1e8f` 之间**未改动**（`git diff --stat` 只有 `skill.js` / `status-defs.js`），且敌方技能走
`groupHash(大关,小关,槽位)` 确定性播种 → **携带者集合与基线完全相同**。用只读探针枚举各 Boss 关的敌方技能：

| Boss 关 | Boss 技能 | 该关携带 `bulwark` 的单位数 |
|---|---|---|
| g10-10 | Boss·冰霜巨人 `[charge, bulwark]` | **2**（Boss + 1 精英） |
| g13-10 / g14-10 / g15-10 | — | **0 / 0 / 0** |
| g16-10 | Boss·冰霜巨人 `[bulwark, empower]` | **1**（Boss） |
| **g17-10** | Boss·混沌魔 `[cleanse, possess]` | **0** |
| **g18-10** | Boss·战争领主 `[cleanse, bulwark]` | **1**（Boss） |
| **g19-10** | Boss·暗龙 `[lastword, doom]` | **0** |
| **g20-10** | Boss·深渊之主 `[blizzard, heal]` | **0** |
| g21-10 | Boss·火焰王 `[taunt, charge]` | **0** |

**归因结论**：
1. **`g17` / `g19` / `g20` 的 Boss 关一个 `bulwark` 都没有** → 本次「上限 0.40→0.30」**在物理上不可能**推动这三关的胜率。它们本轮的数值与基线差异（93→95、0→0、10→8）只能来自采样噪声或 v2.2.14 的其它改动，**不是这次收上限造成的**。
2. 边界带里真正受影响的只有 **`g18`（1 个 Boss）** 与 `g16`（1 个 Boss，但余量充足、恒 100%）。
3. **内部一致性佐证**：无技能 40t 列里，**没有携带者的大关与 v2.2.13 报告逐格一致**（`g15` 88%、`g17+` 全 0%），**唯一变化的是 `g16`（98% → 100%，翻 1 局）**——而 `g16` 恰是携带者所在关。这与「改动只在携带者关卡生效」完全自洽，同时说明**该改动的效应在 40 trials 下低于可分辨阈值**（一升一降各 1~2 局，方向不一致）。
4. 「21 个敌方单位携带」与「实测 14 个 Boss 关里仅 4 个」并不矛盾：前者是**全部 240 关**的携带者总数，其余 17 个分布在各大关的第 1~9 小关；只是**本次实测的瓶颈段（第 10 小关）里几乎不覆盖**。

> ⚠️ 因此，若作者本意是「收到 30% 后让 `g17`/`g18` 更稳、`g20` 脱离近墙」，**本改动达不到该目的** ——
> 瓶颈不在 `bulwark`（`g17`/`g19`/`g20` 根本不带），而在玩家自身属性/魂防与 **`g19` Boss 抽到的 `doom`（无视防御与减伤）+ `lastword`**
> （与 `doc/HANDOFF.md` §6.3 / §10 记录的「g19 抽到 `doom_call + grow_atk`」方向一致）。

## 4. 异常 / 存疑点

1. **`g19` 是局部低谷：`g19` = 0%，而 `g20` = 8%（40t）**——阶梯**非单调**（跨版本稳定复现）。40 trials 下 g19 为 **0/40**。
   本轮已顺带取到机制线索：`g19-10` Boss = 暗龙 `[lastword, doom]`（`doom` **无视防御与减伤**，直接吃掉本档的 `goldshield` / `block` / 敌方 `bulwark` 等一切减伤），
   而 `g20-10` Boss = 深渊之主 `[blizzard, heal]`（温和得多）。**但仍为「未展开验证」，仅记录现象 + 线索。**
2. **12 trials 对边界带是「双向」不可靠（本次最值得记住的一点）**：
   `g17` 含技能 12t = **100%** 而 40t = **95%**（高估）；`g18` 12t = **83%** 而 40t = **90%**（低估）；`g20` 12t = **0%** 而 40t = **8%**（低估）。
   → **12 trials 只适合分辨「0 / 中间 / 100」三档，且「100%」与「0%」都可能骗人**；凡落在 0~100% 之间的点必须 40t 复核。
   （v2.2.13 只记录了高估方向，本次补上低估方向。）
3. **本版对边界带几乎无影响**（见 §3.2 / §3.3）：`g17`/`g19`/`g20` 无携带者 → 结构无关；`g16`/`g18` 各 1 个携带者且效应落在噪声内。
   **这是本轮的核心结论，也是与任务预期相反的结论，特此显式记录。**
4. **`g16` 无技能 40t：基线 98% → 本次 100%**（翻 1 局）。原因即 §3.3-3（携带者关卡 + 噪声），**不是回退**。
5. **`g15` 无技能 40t = 88%，与 v2.2.13 报告逐格一致**；机制上可解释：`g15-10` 无 `bulwark` 携带者，故该列随机流未变（自洽检查，**不改变**「含技能列不可逐格对比」的结论）。
6. **脚本自检通过**：脚本注释要求 `g6/g10/g13` 恒为 100%（`ai.js`/`terrain.js` 是否漏载、宠物是否走真实管道的哨兵），本快照在**两种口径 × 两种 trials 下全部复现为 100%**，故本次数据采信（PITFALL-17）。
7. **未启用退路**：`git worktree add` 在 Windows 上**一次成功**，未走「复制 `page/` + `scripts/` 到 scratchpad」的备用方案。
8. **脚本没有「只跑某一个大关」的开关**（`GROUPS` 是硬编码 14 个大关）。
   → 任务要求「边界大关单独 `--trials 40` 复测」的等价做法是**整条阶梯用 `--trials 40` 重跑**（本次即如此），
   比只测单关更严格（一次覆盖 `g15/g16/g17/g18/g20` 全部边界点）。**未改动脚本源码。**
9. **口径缺口（沿用 v2.2.13）**：敌群天赋「接成长」（WP-F）仍未做（`talent.js` 那 12 条为固定值），
   故 `g19~g24` 的高墙角**也可能部分源于此**，本报告无法把「bulwark 改动」与「WP-F 未做」的贡献彻底分离 —— 但 §3.3 已证明**在实测的 Boss 关里 bulwark 不是瓶颈**。
