## 1. 作者裁决（2026-10-09；终局时序于本轮施工前补充）

1. **收尾顺序固定**：胜负 → 战果（奖励/通关变化）→ 单场战绩与继续操作。奖励先完成原有入账，再展示已经入账结果；不能让奖励 toast 与详细战绩同时抢读。
2. **阶段时序固定**：胜负阶段 800ms；普通战果阶段 1,200ms；之后自动进入战绩/继续阶段。阶段 timer 驱动切层，不依赖 `animationend`。
3. **显式操作边界**：普通胜负与战果阶段提供清晰“继续”按钮，可提前推进当前流程的下一展示层；不支持点击背景隐式跳过。单敌自动胜利战果层提供“查看战绩”按钮，该操作进入战绩层并取消自动推进。关闭只关闭结果/战斗 overlay，不推进到下一关、不结算第二次。手动推进必须先取消对应阶段 timer；阶段按钮和自动 timer 均须幂等。
4. **单敌自动连战**：保留。单敌胜利路径先显示胜负 800ms，再显示已入账战果至少 2,000ms；计时到期仅当 auto 仍开启、overlay 仍打开且用户未操作打断时直接进入下一关，不再等待战绩层。“查看战绩”、关闭或用户手动继续均取消自动 timer；分享/其它离开本场结果流程的操作也取消 timer。失败（即使 auto 开启）关闭 auto，胜负 800ms → 无奖励但如实展示失败副作用的战果 1,200ms → 战绩/重试层；单敌失败只显示确实发生的失败结果（当前至少是本次无奖励/可重试，不虚构其它奖励/次数）。失败不自动重试。敌群本轮不添加自动连战，胜败路径统一 800ms → 1,200ms → 战绩层。
5. **中止路径与 timer**：异常中止保持第三种结局，不伪装胜败/战果、不自动续关；overlay 关闭、重试、手动下一关、新战斗启动均取消未执行的阶段/自动推进 timer；所有结算与副作用仍只由既有结算入口执行一次，UI 阶段 timer 不得触发结算。timer 以 `Date.now()` 记录绝对到期时刻；页面后台恢复时重新计算剩余时间，不依赖 CSS 事件；减少动态效果仅减弱视觉动画，不缩短已裁决的阶段时长。
6. **本场快照与已结束战斗**：在既有结束入口快照本场 levelId/NPC、奖励文本与真实失败副作用，不得从已推进的 mutable 当前关卡反查本场。群战已 done 后的结果面板关闭/重绘只允许继续复盘或退出；不得 resume 新行动、重新结算或再次打开一份过期本场结果覆盖玩家操作。
6. **历史留存**：单一独立 store key，单敌与敌群合计保存最近 100 场摘要，超限 FIFO；跨刷新保留；随现有 `store.getAll()` 同步、导出/导入。不得存完整逐步引擎日志，不改同步协议。写入失败不得静默影响战斗奖励或结果呈现；即时结果仍须可看。
7. **长期统计**：分模式显示场次、胜率、当前/最佳连胜、平均回合；单场玩家输出、治疗、承伤；敌群另列场地、DOT、护盾吸收。当前日志归因不能精确支持的数值应注明或显示“不适用”，不造精度、不跨模式做不可靠排名。
8. **验收阈值**：每模式至少 10 个真实事件样本，至少 8/10 能正确辨认行动者/目标/结果；UI 遮挡/裁切为 0。报告真实样本条件。
9. **动效**：本轮不引入音效/震动/摇屏；支持 `prefers-reduced-motion` 降低非必要动效，同时保留事件语义信息。

上述裁决不改变战斗伤害、命中/暴击、状态时序、AI、胜负规则、掉落和奖励数量。

## 3. 批次 A 实施规格：终局流程

### 3.1 共通阶段

- **胜负**：明确展示胜利/失败；保留战斗画面可辨认，不显示详细战绩。
- **战果**：显示已经结算的奖励和通关/解锁变化；此阶段不展示成套战斗统计。失败显示已发生的失败副作用（例如宠物受伤）但不虚构奖励。
- **战绩与继续**：展示现有单场摘要/战报及动作按钮；MVP/关键指标不与战果 toast 同时叠层。
- 阶段切换应单向、每场幂等；重新渲染不得重复发奖励、改进度、计失败次数或触发宠物受伤。
- 结果、奖励已由当前引擎流程结算的事实是唯一来源。此批只调 UI 展示与呈现时序，不把计时动画当作结算时机，不将引擎奖励移动到渲染 callback。
- 胜负/战果阶段必须在 `prefers-reduced-motion` 下可通过明确文本/瞬时阶段信息理解；不可依赖 CSS 动画结束事件推进流程，避免后台标签页节流导致卡住。

### 3.2 单敌专属

- 单敌现有奖励结算、属性推进和 `celebrate()` 时机需先审计；维持副作用只发生一次。
- 自动连战仅成功路线自动进入下一关；等待至少 2,000ms。按钮/关闭动作取消挂起的自动下一关 timer；失败自动关闭自动模式；异常中止不计胜败、不奖励、不可自动续关。
- 自动等待时间/界面按钮行为须通过假的计时器测试与真实浏览器点击验证。

### 3.3 敌群专属

- 移除胜利/失败路径中会与结果面板并发的 `toast` 奖励反馈；其奖励文本并入分阶段战果。
- `_groupRewarded` 继续保证幂等；胜利标记、奖励、宠物失败受伤、副作用顺序与真实结算保持一致。
- 不擅自给敌群增加连续战斗模式。

## 4. 批次 B 数据与指标字典

### 4.1 历史记录

- store key 暂名 `battleHistory`，逻辑 schema 起始版本 1；结构提案：`{version:1, battles:[...]}`。若当前 store 对 schema 形状、注册时机有项目约定，应按现有注册表实现。
- 每条最小摘要建议字段：`id`（稳定且唯一）、`endedAt`（本机 ISO 时间）、`mode`（`single`/`group`）、`stageId`、`result`（win/loss/aborted）、`rounds`、`metrics`、`party[]`（按有合法来源的数据记录名称、dealt/taken/healed/alive）；敌群额外 `terrain/dot/shield`。不得把 `gb.log` 全量写进历史。
- 战斗异常中止要记录为 `aborted`，不能算胜率分母。若异常无效上下文或历史写入失败，仍显示异常/本场 UI。
- 成功结算后 append once（用单场 id 或等价幂等标记）；渲染重复调用不重复记历史。历史保存失败需要 console 明确错误且面板提示“本场战绩未保存”；不回滚已发奖励。
- 最多 100 条，按 `endedAt` append；超出删除最旧。旧存档无 key → 空数据；不做回填/推断。
- 合并/导入行为依现有同步 `store.mergeAll` 整键覆盖，不做跨设备冲突合并新规则；需测试 push/pull 和 JSON roundtrip。现有 `sync.js` 通用 `collectOtherKeys()` 已自动包含新增未扁平化 store key，若测试证实不符合才改。

### 4.2 指标定义

- **场次**：记录数量（含 win/loss；不含 aborted）。
- **胜率**：wins / (wins + losses)；分母 0 时显示“—”。按模式独立计算。
- **当前连胜**：按结束时间倒序从最近记录开始连续 win 计数；遇 loss 或无可用记录停止，aborted 不纳入历史胜负序列但要明示口径（建议跳过 aborted）。
- **最佳连胜**：全历史 win 连续段最大长度；aborted 处理同上。
- **平均回合数**：已完成 win/loss 的有效 rounds 算术平均；空数据“—”。
- **单场贡献**：沿用该模式可信来源。敌群沿用 `groupBattleStats()` 口径及其同名归因披露；单敌若无完整来源/目标统计，只显示明确可得的数据/不适用，不从字符串随意解析造数。
- **避免横向误读**：单敌/敌群各自卡片与趋势；没有可靠共同单位/分母的指标不合并排序。

## 5. 批次 C 演出规则

| 事件级别 | 事件例 | 表现原则 |
|---|---|---|
| 常规 | 普攻、小额持续伤害 | 目标附近的精简数值/血条变化；限速控制密度。 |
| 重要 | 治疗、护盾吸收/破碎、状态施加/刷新/净化/抵抗/结束 | 目标锚定语义徽标；若身份或目标缺失则显示可读日志，不猜目标。状态常驻标记与瞬时变化提示职责分离。 |
| 重大 | 击杀、濒死、Boss 机制触发、战斗终局 | 优先可读短提示及目标焦点；动效克制，不遮挡按钮/单位状态，不延迟结算。 |

- ×1：逐事件显示。
- ×2：只聚合相邻演出窗口内同目标、同伤害类别的可加总事件。
- ×4/×8：以速度窗口聚合可加总的重复数值；行动者/目标/技能身份/状态/击杀等离散语义要保留，不得通过数值相加合并。
- 日志抽屉开时只在目标芯片上显示不遮挡日志的反馈；中央区反馈保持关闭，除非浏览器证明不相交并经主控验收。
- `prefers-reduced-motion: reduce` 禁用/缩短非必要位移、闪烁、缩放；关键文本、状态徽标、HP 与日志信息保持。

## 6. 主控验收协议

子代理需交付：变更文件清单、设计决策映射、测试命令与完整结果、固定种子差异、真实浏览器样本条件/截图或量测、未完成项与风险。Lead 必须：

1. 阅读当前 `AGENTS.md`、本计划、HANDOFF 相关节与发布纪律；复查实时 HEAD / `APP_VERSION` / 台账 / 工作区。
2. 亲自审查 staged diff，发现与他人工作冲突时停止，不覆盖不相关 `_tmp-*` 与并行修改。
3. 确认测试能在基线代码上为关键新增需求判红；测试保护实际行为，不弱化旧断言。
4. 运行相关套件与项目实际全量运行器；确认完整套件确已运行、失败数为零。
5. 亲自打开真实浏览器覆盖验收表，不接受仅 DOM 桩或子代理截图口述。
6. 检查无线上数值/RNG/胜负差异、发布三项/缓存戳/台账一致；限制提交范围只含本批文件，独立提交。
7. 验收失败则交回子代理按明确项修，不以“基本完成”合并；主控负责最终 commit。

### 批次 A 验收路径矩阵

| 模式 | 路径 | 重点断言 |
|---|---|---|
| 单敌 | win/manual | 胜负先显示 → 战果 → 战绩；奖励/进度一次；可下一关/关闭 |
| 单敌 | win/auto | 战果持续≥2s；点击中止 timer；无点击后只推进一次 |
| 单敌 | loss/auto | 关闭自动模式；不自动重试；失败计数一次；结果可辨 |
| 单敌 | aborted | 不显示胜负/战果伪装；不自动继续；错误上下文保留 |
| 敌群 | win | 不出现并发 toast；奖励文字/进度一次；详细统计后呈现 |
| 敌群 | loss | 受伤副作用最多一次；不显示胜利奖励；可关闭/复盘 |
