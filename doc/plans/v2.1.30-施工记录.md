## 2. 做法

### A. 加 3 个名字

```js
19: '试炼·太虚', 20: '试炼·混元', 21: '试炼·无极',
22: '试炼·鸿蒙', 23: '试炼·太初', 24: '试炼·涅槃'
```

命名沿用「道教宇宙论」序列（太虚 → 混元 → 无极 → 鸿蒙 → 太初 → 涅槃）。
**改名字只需改这一行**，循环、进度链、测试全部自动跟随。

### B. 难度斜率：沿用 `GROUP_TAIL_POW_EXT = 1.24`

按 v2.1.29 施工记录的既定原则：**不新加第三档斜率**（那会引入新的 [PLACEHOLDER]）。
实测结果超出判据后，本版仍**未改斜率** —— 因为数据显示根因不是斜率（见 §4）。

### C. 平衡实测（实战口径：`ai.js` + `terrain.js` + `groupTerrainFor` + 参战阵容）

基准账号 攻2883/防1145/血24800/魂攻532/魂防99，宠物 SR+SSR，trials=12：

| 大关 | Boss atk/def/hp | 50% 胜率倍率 | Boss 词条 / 技能 |
|---|---|---|---|
| g19 | 5425/2767/36624 | 4.8× | `doom_call + grow_atk` / `lastword + doom` |
| g20 | 7049/3595/47586 | 3.5× | `grow_def + grow_atk` / `blizzard + heal` |
| g21 | 9140/4661/61700 | 8.3× | `aoe_guard + skill_guard` / `taunt + charge` |

✅ **口径自校验**：本版扫描器复现了 v2.1.29 记录的 g20 3.5× / g21 8.3×（g19 记录 4.4×，本版 4.8×，在 trials 波动内），
说明测量可信，g22~g24 的数字可与既有阶梯直接比较。

### ⚠️ 超出判据，但**不是斜率问题**

v2.1.29 施工记录定的判据是「超过 10× 判定为永远碰不到，回来改斜率」。g24 落到 **22~25×**，确实超了。
**但改斜率解决不了**，因为：

| 场景 | g22 | g23 | g24 |
|---|---|---|---|
| A：现行 1.24 | 9.6× | <1×（1× 已 67%） | ≈23×（20×:8% → 25×:83%） |
| B：g22+ 换 1.14 | 5.4× | ≤3×（3× 已 100%） | 11.2× |
| C：g22+ 换 1.06 | ≤3×（3× 67% / 4× 100%） | ≤3×（3× 已 100%） | 5.4× |

把斜率压到 1.06 只是把「g22/g23 白送、g24 打不过」整体下移，**非单调依旧**。
根因是各关**词条/技能的确定性随机**（v2.1.29 已记录 g19/g20 倒挂、g21 悬崖同源），本版又抓到一个**明确的 bug**（见下）。

### 🐛 本版查出的真 bug：遗言（`lastword`）让关卡白送

**症状**：g23 的 50% 门槛 < 1× —— 玩家用**当前属性**就有 67% 胜率。
实打一场（g23-10，1×）：我方有效攻击 1441，打在护卫 def 4871 上**每击 1 点伤害**，
却 `winner=ally`、15 步结束、三敌 HP 全 0。

**根因链**：

1. `skill.js:441` `lastword`（遗言）的效果是**施放者自身立即阵亡**，只给对手挂 7 回合诅咒。
2. 它自 **v2.1.22** 起进了 `SKILLS_HIGH` —— 该池**Boss 与精英（含护卫）共用**，所以护卫也会抽到。
3. `ai.js:88-97` 的「特级负面」分支有 `_tier==='boss' && 自身血量<35%` 双门槛，
   但**其余情况会落到末尾「70% 最强 / 30% 随机」分支**，而 `lastword` 的 `power`/`priority` 均为 0
   → **满血敌人也会被 30% 随机抽中并当场自爆**（实测日志第 1 回合即触发）。
4. 独立缺陷：`startCooldown` **全项目无消费点**（`grep` 只有 `skill.js` 的定义与 `game-render.js` 的展示），
   `lastword` 标的「开场即进入 10 回合冷却」是**死配置**，所以第 1 回合就能放。

**波及范围**：24 个大关里 **11 个**敌人带 `lastword`
（g8 / g9 / g10 / g11 / g13 / g15 / g19 / g20 / g21 / g23 / g24；g23 = Boss 关三敌全带，g9/g11/g15/g20 各 2 个）。

**未在本版修改**（涉及战斗行为 + 会改变既有已通关卡难度，属设计决策，已列入待办）。候选修法：
a. 移出敌人池 ｜ b. 保留但只允许「Boss + 自身残血」施放 ｜ c. 独立修 `startCooldown` 死配置。

- ⚠️ **`Get-Content` 数行数会少数**：PowerShell 里用 `(Get-Content f).Count` 量 `game-render.js` 得 1237、
  `battle-group.js` 得 825，与架构演化表记录的 1288 对不上，一度以为「表写错了」。
  改用 `node -e "...split('\n').length-1"` 复核 → **1288，与表一致**。
  **量行数一律用 node，不要用 `Get-Content`**。
- ⚠️ **量 HEAD 版本也别用 PowerShell 重定向**：`git show HEAD:f > tmp` 写入时会多出十几行（CRLF/BOM 处理），
  同样会把数字带偏。
- ⚠️ **扫描器要先用已知基准自校验**：本次扫描前先用 v2.1.29 已公布的 g20 3.5× / g21 8.3× 复现一遍，
  数字对上才继续扫新关卡 —— 否则无法区分「关卡变难了」和「我的扫描器口径不对」。
