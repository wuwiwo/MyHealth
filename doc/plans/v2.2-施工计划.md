## 0. 施工原则

1. **工作包（WP）可独立提交**：每个 WP 完成后跑全量测试（`scripts/test-*.js`）+ 设计护栏（`test-a11y-tokens.js`），全绿再提交。
2. **顺序敏感**：WP-A（宠物属性/宝珠重构）会改动所有宠物数值口径，**必须先做**，否则后续平衡数值全部要重算两遍。
3. **口径统一**：敌群侧「随关卡与敌人级别成长」统一用 `t = (unit.level − 1) / 9`（`unit.level` = 大关号，夹 1~10），
   与 `skill.js` 既有的 `skillRangeT()` 同源；宠物侧区间仍用「炼化等级 ÷ 稀有度上限」。
4. **每个 WP 结束时更新**：`CONTEXT.md` 模块树（若新增文件）、`doc/HANDOFF.md` 对应章节。

## 1. 工作包拆解

### WP-A 宠物属性与宝珠重构（结构性，最高优先）

**A1 属性公式改为「基础值 × 倍率池」**
- 新公式：`最终属性 =（图鉴基础 + 炼化加成 + 天赋静态修正）×（稀有度倍率 + Σ宝珠%）`
  - 稀有度倍率（百分比表述）：**R 1200% / SR 1400% / SSR 1500% / UR 1600%**（与现值 ×12/14/15/16 等价）
  - **各属性独立计算**（生命 / 攻击 / 防御 / 魂攻 / 魂防），**速度不参与**
  - **炼化加基础值**、**宝珠 % 进倍率池**（dundun 裁决）
- 文件：`page/group-levels.js`（`PET_GROUP_SCALE` → 百分比、`boostPetForGroup()` 重写）、`page/pet-codex.js`（`createPetUnit()`）、`page/orbs.js`
- ⚠️ 旧实现「宝珠加成不参与放大（`_orbBonus` 排除）」在新公式下**自然消解**，需删除该特例并回归验证

**A2 宝珠系统重构**
- **删除 N 档**；品质链 **R(+10%, 10 级) → SR(+20%, 25 级) → SSR(+70%, 40 级) → UR(+150%, 50 级)**
  - 每级成长：R +1% / SR +2% / SSR +2% / UR +3%；**满级自动升品质**；单颗上限 **+300%**
- **宝珠本体改为「挑战」掉落**（不再是碎片合成）；**碎片只用于升级**
- **存量迁移**：现有 N 宝珠 → 分解为 **20 个宝珠碎片**（需一次性迁移逻辑）
- 文件：`page/orbs.js`（全面重写）、`page/pet-store.js`（材料定义 / 掉落）、`page/challenge.js`（掉落表）、`page/pet-ui.js`（宝珠 UI）
- 测试：`test-orb-wiring.js` / `test-orbs.js` 需按新口径重写

**A3 上场宠物 2 → 4**
- `createPetUnitsForBattle()` 默认上限 2 → **4**、`autoPickPets(2)` → 4、UI 文案「最多 2 只」→ 4
- 文件：`page/pet-store.js`、`page/game-render.js`、`page/pet-ui.js`
- ⚠️ 战场规模变化（我方 5 单位 vs 敌方最多 3）需验证行动队列与 UI 布局

**A4 团队凝聚（新）+ 共鸣接线**

### 6.2 ⏭️ 下一项：金身护盾「破盾反伤」（WP-B 收尾）

**裁决原文**：金身护盾被击破时，对**攻击者**造成**初始护盾 × 20%** 的伤害（**受魂防减免**）。

**已查清的关键事实（2026-09-29，v2.2.8 时点）**：

1. `absorbShield(target, dmg)` 定义在 `page/battle-group.js:40`，**签名里没有攻击者** → 拿不到反伤对象。
2. 它有 **5 个调用点**，全部在 `battle-group.js`：
   - `:70`、`:127` —— 在辅助函数内部（需确认这两个函数是否已持有攻击者参数）
   - `:412` —— 普攻伤害结算（此处 `actor` 在作用域内 ✓）
   - `:427` —— 魂伤第二段（`actor` 在作用域内 ✓）
   - `:490` —— 群攻/AoE 循环（`actor`/`t`/`dmg` 在作用域内 ✓）
3. 护盾被击破的判定点在 `absorbShield` 内部（吸收到 0 时撤 `_shieldImmune`），**已有**「破了」这个事实，缺的只是「谁打的」。

**实现方案（建议一次做完，避免口径分叉）**：

1. 在 `player-skill-hooks.js` 的 `playerSkillBattleStart` 里，给装配金身护盾的玩家记下
   `player._shieldReflect = { pct: 0.20, initial: 护盾初值 }`（`initial` 直接复用同处算出的盾值，别另算一遍）；
2. `absorbShield(target, dmg, attacker)` → **加第 3 参**，在护盾归零时若 `target._shieldReflect` 存在，
   记录 `target._shieldBroke = attacker`（**只记录事实，不在此处结算伤害** —— 该函数拿不到 gb，且它同时被
   普攻/魂伤/AoE 复用，就地结算会重复触发）；
3. 在**每个调用点之后**统一走一个小函数 `resolveShieldReflect(gb, target)`：若 `target._shieldBroke` 有值，
   对攻击者结算 `初始护盾 × 20%` 的伤害并**按攻击者的魂防减免**（口径同引擎既有「魂伤受魂防减免」），
   加事件日志，然后清空标记（**保证一击只触发一次**）；
4. 5 个调用点都要补上「传 attacker」+「调 resolveShieldReflect」——**这正是必须一次做完的原因**：
   漏一处就会出现「有盾的路径能反伤、没盾的路径不能」的分叉。

**测试**：`test-player-skills`（或新 `test-shield-reflect.js`）需覆盖
① 破盾时攻击者掉血 ② 反伤只触发一次 ③ 未带金身护盾不反伤 ④ 反伤受魂防减免（高魂防单位吃得更少）。

**风险**：`battle-group.js` 是核心战斗文件（962 行），改动面 5 处 → 改完必须跑全量 + 用
`scripts/balance-pets-ab.js --skills …` 复测一遍 g15~g18（确认没有把难度整体推平）。

### 6.3 ✅ 已裁决（2026-09-29，dundun）

⚠️ **过程教训**：讨论设计口径**必须贴设计原文**，不要只给系数代号或术语（作者原话：「你要跟我说原文呀，突然来一句都听不懂你说什么」）。
