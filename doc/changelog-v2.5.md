## v2.5.0

Date: 2026-10-06

**战斗结算完整性（v2.5.0 首版：异常不判胜 / Prepare 灭队即时结束 / 场地结果真实落地）**

本版是**引擎结算侧**的三条修复，**会改变战斗结果**（如实披露见「影响」一节）。
施工范围严格限定在 `doc/plans/战斗系统-施工任务计划.md` 的任务 1：

（raw/final/hpDamage 与 overkill 仍待裁决），**不动** Icebeam / 陨石 / 巨石 / AI 目标 / DOM·FX。

### 修复

#### ① 单敌引擎异常不再伪装成玩家胜利（`page/game-battle.js`）

**根因**：`runBattle()` 的 `catch` 把引擎异常当成「敌方 HP 已扣减的部分有效」处理 ——
`_battle.enemy.hp = Math.min(hp, 0)` → `_battle.winner = true` → `endBattle(true)`。
后果不是「少一条日志」，而是**结算污染**：异常会被记成通关（`cleared` 追加、
`current` 推进到下一关）、**发放炼化点战利品**、播庆祝动画，而真正的原因只留在 console。

**修法**：新增 `battleErrorContext()`（纯函数）+ `endBattleAborted()`：

- **不改 HP**（不伪造成击杀）、**不判胜**（`winner` 保持 `null`）、**不发奖**、
  **不推进通关**、**不计每日失败次数**（异常既不是胜也不是败）；
- 只把本场标记为「已结束」并置 `aborted = true`，避免定时器/自动模式继续推进；
- 界面如实显示 **「⚠️ 战斗异常中止」**（与「🏆 胜利！」「💀 战败」都不同），
  并明确写「本关不计胜负、不发奖励、不推进进度」；
- **保留可定位的错误上下文**：`stage` / `name` / `message` / **`stack`** / `level` /
  `npc` / `boss` / `affix` / `turn` / `playerHP` / `enemyHP` / `at`(ISO 时间)，
  同时挂在 `_battle.error` 与模块级 `_lastBattleError`，由 **`getLastBattleError()`** 读取；
- `console.error` 留在 catch 现场（本项目硬性护栏：**禁止静默 catch**）。

#### ② 敌群 Prepare 阶段灭队必须立即终止本回合（`page/battle-group.js`）

**根因**：`runPhasePrepare` 只负责「把本回合开始的效果落地」，全函数**没有任何胜负判定**
（`checkGroupWin` 只出现在 `runPhaseAction` 的每个单位之后与 `runPhaseEnd`）。
准备阶段被打死的一方不会被判负，**残存方照样建立行动队列并进入行动阶段**。

**修法**：在准备阶段逐单位结算之后、`predeclareActions`/`buildActionQueue` **之前**
补一次 `checkGroupWin(gb)`，命中则 `return []`（空队列）：

- 准备阶段能打死人的通道都在这一行之前跑完了（场地 `onTurnStart` / 末日·遗言 /
  开战钩子 / 玩家技能的回合开始部分）；
- **双方同时灭队 → 判我方胜**：直接用 `checkGroupWin` 的既有次序
  （先「我方全灭 → enemy」、再「敌方全灭 → ally」）得到 `winner = 'ally'`，
  与作者本轮裁决一致，不需要另写一套判定；
- `groupBattleTick` 与 `groupBattleStep` 都经由 `runPhasePrepare`，故两条驱动**结论一致**
  （step 路径返回 `{ done: true, turnEnd: true, winner: 'ally' }`）。

#### ③ 真实群战回合末的场地结果真正落地（`page/battle-group.js` + `page/terrain.js`）

**根因**：`runPhaseEnd` **直接调用** `gb.terrain.onTurnEnd(gb)` 并且**只消费 `events`**，
从不调用 `terrain.js` 的 `applyTerrainResult` → callback 返回的 **`damage` / `statusApps`
被整包丢弃**。同一处缺陷在 `runPhasePrepare` 的 `gb.terrain.onTurnStart(gb)` 上重复。
后果：沙暴碎石 / 酷暑失血 / 雨天闪电**对任何人都不生效**（只剩一行日志），
而 `scripts/test-terrain.js` 一直直接调 `terrainTurnEnd` helper，**长期测的是另一条路径**
（helper 会应用结果）→ 测试全绿、线上零效果。

**修法**：两条路径都改走 `terrain.js` 的既有唯一机制，不新造应用逻辑：

| 阶段 | 旧 | 新 |
|---|---|---|
| 准备（`runPhasePrepare`） | `gb.terrain.onTurnStart(gb)`，只取 `events` | **`terrainTurnStart(gb)`**（内部 `applyTerrainResult`） |
| 结束（`runPhaseEnd`） | `gb.terrain.onTurnEnd(gb)`，只取 `events` | **`terrainTurnEnd(gb)`**（内部 `applyTerrainResult`） |

- **敌我全体同等处理**：`applyTerrainResult` 按 `unitId` 在 `gb.units`（双方）里查单位，
  各场地 callback 也一律遍历 `gb.units` —— 与设计 `doc/2.0 敌群设计.md:207`
  「场地：对敌我双方均有效」一致；
- **从开战第一个准备阶段启用**，但**每个钩子只在本回合自己的时点跑一次**：
  回合末伤害不提前到开战瞬间、毒气的「5 回合后」、雪天的 5~7 回合间隔、
  雨天/沙暴的回合末条件全部保持原周期（**没有**新增开战一次性结算）；
- **顺序**：`runPhaseEnd` 里先应用（扣血/落状态）、后判胜负（末尾的 `checkGroupWin`）；
  场地在回合末击杀最后一名敌人时立刻分出胜负，不会停在「敌人 0 血仍在战斗」；
- **不重复应用**：每回合只在 `finishRound` 里跑一次结束阶段，
  tick / step 两条路径的 `gb.log` 与各单位 HP 逐字节一致。

### 影响（如实披露，改前 / 改后固定种子差分）

场地效果**第一次真正生效**，因此战斗结果必然变化。固定种子 A/B：**g3~g14 × 3 个小关 × 3 个种子
= 108 场**，同一份阵容与种子，只换 page 源码（HEAD 基线 vs 本版）：

| 指标 | 结果 |
|---|---|
| 结果发生变化的场次 | **65 / 108** |
| 其中 HP 变化 | 65 |
| 其中回合数变化 | 13（**12 场更短 / 1 场更长**） |
| 其中**胜负翻转** | **1**（`g13-5/s20261006`：修前 ally 胜 → 修后 enemy 胜） |
| 变化按场地分布 | 沙暴 45 / 雨天 11 / 酷暑 9；**无场地与雪天 / 反转场地 0 变化** |

- 翻转样例明细：修前 `ally` 胜（我方剩血 **1077**、三个敌人全灭）；
  修后 `enemy` 胜（我方 **0**、敌 e1=271 / e2=519 存活）。原因是沙暴每回合随机 2 名
  「**对敌我双方均有效**」—— 修前它只写在日志里，修后我方也要挨这份碎石伤害。
- **方向**：伤害型场地（沙暴/酷暑/雨天）现在对**双方**同时生效，整体是**难度上移**
  （回合数 12 短 / 1 长，因为双方掉血更快、战斗更快结束，但我方承受的绝对伤害增加）。
  ⚠️ **未做难度补偿**（是否回调应由作者看体感决定）。
- **雪天 / 反转场地 0 变化**：它们的 `onTurnStart` 本来就自己调 `applyStatus`，
  返回值只有 `events`（没有 `damage`/`statusApps` 需要应用）→ 与本版修复无关，符合预期。
- **RNG**：修复未新增/删除任何掷骰点（`applyTerrainResult` 不消耗 RNG；场地 callback 的
  RNG 消耗位置一字未动），故同种子两次跑仍逐字节一致（`test-group-determinism` 14/14 绿）。

### 已知残留 / 已暂停的子项（不猜测补完）

1. ⏸️ **场地伤害的「受 X% 防御降低」未实装（本版按计划暂停该数值子项）** ——
   设计写「沙暴：受 **200% 的防御属性降低**」「雨天：受 **300% 魂防御降低**」
   （`doc/2.0 敌群设计.md:212,223`），既有实现一律是**裸 maxHP 百分比、无减免**，
   且该措辞**无法唯一推出公式与下限**（是 `dmg - def×2` 还是 `dmg × (1-200%)`？
   下限取 0/1？）→ 按施工计划「暂停该数值子项另行确认」，**不自行创设公式**，
   也**不因此漏掉已确认的场地结果应用修复**。该缺口在 `doc/HANDOFF.md §10` 早有登记。
2. ⚠️ **场地 `desc` 里的被动数值仍只有文案、无消费点**（本版范围外，如实报告）：
   「沙暴：全场命中率 −20%」「雪天：潮湿/冰冻下受到治疗 −50%」「毒气：5 回合后全场治疗 −75%」
   目前 `terrain.js` 只实现了各自的伤害/状态钩子，这些**被动数值从未接过线**。
   本版只修「callback 返回的 damage/statusApps 不落地」，**未新增未裁决的场地数值**
   （新增 −20% 命中会显著改变所有含沙暴关卡的命中率，属另一个需要裁决的改动）。
3. ⚠️ **真实 UI 驱动的最后一回合收尾**（本版范围外，如实报告）：
   `page/game-render.js` 的 `_groupStep()` 在 `_groupBattle.done` 时**立即**调 `_groupDone()`，
   而 `groupBattleStep` 的文档契约是「已分胜负但本回合未收尾时再走一步把判定+结束跑掉」
   （`_roundOpen`）。因此**当战斗在行动阶段分出胜负时，真实 UI 会跳过这最后一个回合的
   结束阶段**（tick 路径会跑）。影响面：只影响该回合的场地回合末伤害与回合级守卫清理，
   **不影响胜负/奖励/进度**，且是本版之前就存在的行为（非本版引入）。测试按引擎契约驱动
   （`while (!done || _roundOpen)`）验证 tick/step 等价；是否修改 UI 驱动器需作者裁决。
