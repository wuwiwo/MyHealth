## v2.7.0

Date: 2026-10-06

**敌方 AI 技能目标真正进入执行路径**

只改**敌群**引擎的目标传递：`page/battle-group.js`（`selectTargets` 增加可选「已声明目标」 +
`castSkill` 接收它 + `groupUnitTurn` 把 `actTarget` 传下去）。**不改 AI 策略、不改普攻路径、
不改数值与技能定义、不合并两套引擎。**

### 修复

#### ① 已声明的目标此前对**技能路径完全无效**

**根因（三段链路，断在最后一环）**：

1. 准备阶段 `predeclareActions()` 用 `aiDecide()` 预先声明「本回合用什么技能、打谁」，
   只存**技能 id 与目标 id**（`{skillId, targetIds}`）；
2. 行动阶段 `takeDeclaredAction()` 把声明解析成 `actTarget`（单体 / 数组 / null），
   声明失效（技能进冷却、目标全灭、本回合已消费）时**当场用同一个 `aiDecide` 重选**；
3. `groupUnitTurn()` 拿到 `actTarget` 后 —— **只把它用在普攻路径**（`if (actTarget) targets = [actTarget]`），
   技能路径调的是 `castSkill(gb, actor, skillId)`，**不带目标** → `castSkill` 内部再走
   `selectTargets()` 随机选一次。

于是 AI 精心算出的目标（`ai.js` 的 `aiPickTarget`：**嘲讽强制** → 辅助技能挑**最残血友方** →
攻击技能按评分挑目标）对**所有技能**都被丢弃，等于每次技能出手都重新随机 ——
`test-engine-wiring.js` 里既有的「AI 选了谁」断言因此一直是**假绿**（它只盯决策，不盯真实结算）。

**修法**：

- `selectTargets(gb, actor, skillDef, forcedTarget)` 新增第 4 参；**只对单体类规则采纳声明**：
  - **生效**：`random1`（默认）、`enemy1`、`ally1`
  - **不生效**（目标由规则本身决定）：`all`（AOE）、`self`、`ally2` / `enemy2` / `enemy12`（多目标）
  - **数组型声明一律忽略** —— AOE 类会给出数组，不能把范围技能缩成单体
- **合法性校验**（“目标仍需经过存活和技能合法性校验”）：单位存在、`hp > 0`、
  且**阵营与该规则的候选池一致**；不合法就落回原有随机/AOE 选择 ——「声明失效 → 当场重选」，
  不会空放、不会打尸体、不会打自己人。
- `ally1` 的 `wounded`（圣光治愈「只挑未满血者」）仍是硬约束：声明目标满血而另有队友受伤时，
  按 wounded 口径改选伤员（这属于该技能的合法性，不是把治疗浪费在满血单位上）。
- `castSkill()` 改为 `selectTargets(gb, actor, def, opts.forcedTarget)`；
  `groupUnitTurn()` 的技能调用改为 `castSkill(gb, actor, skillId, { forcedTarget: actTarget })`。
- **未动**：`aiDecide` / `aiPickTarget` / `aiPickSkill` 的策略与掷骰、普攻路径（本来就用目标）、
  蓄力载荷释放路径（`opts.releasing`，无声明）、单敌引擎。

### 测试与验证

- `scripts/test-group-battle.js`：26 → **33**（新增第 9 节 7 条）：
  **9a 单体技能：真实受击者 = 已声明目标**（旧实现打错人 → 红）；
  **9e 友方技能（ally1）：治疗落在已声明目标上**（旧实现随机选靶 → 红）；
  9b 三类非法声明目标的回退（阵营不符 / 已阵亡 / 空 → 都落到合法存活目标、不打自己人、不打尸体）；
  9c AOE 的数组型声明**不会把范围技能缩成单体**；9d `self` 类技能不受声明影响。
  （9a/9e 是判别性断言，在旧代码上必红；9b/9c/9d 是**防回归护栏** —— 它们在新旧代码上都通过，
   作用是防止「强制目标」把 AOE/self/回退路径改坏，已在注释里标注性质。）
- `scripts/test-ai.js`：7 → **10**（新增 N 节 3 条，**端到端**）：用**真实 `aiDecide`**（不改策略）
  跑真实回合，在两侧插桩记录「AI 每次给出的目标」与「`castSkill` 每次收到的 `forcedTarget`」，
  断言 ① 确实发生了「决策 → 施放」；② **每一次** AI 技能施放都带上了目标；③ 携带的目标与
  同一施法者最近一次决策一致（逐次配对，**0 处不一致**）。旧实现 `forcedTarget` 恒为 null → 红。
- **先红后绿**：把本版两个套件放到 v2.6.0（`6ceee03`）的 `page/` 上运行 →
  `test-ai` **8 通过 / 2 失败**（N2/N3）、`test-group-battle` **31 通过 / 2 失败**（9a/9e）；
  在本版上 → **10/0** 与 **33/0**。
- 全量：**63 套件 / 4,504 断言 / 0 失败**（v2.6.0 基线 4,494；+10 = `test-ai` +3、`test-group-battle` +7）。
  **未删除、未弱化任何既有断言**；无未识别格式套件、无静默跳过。
- ⚠️ **顺带修掉一处既有的脆弱断言**：`test-player-skills.js` 的「启风②：伤害按 n×8% 缩放」
  隐含依赖「两次普攻都命中」—— 本套件用的是**单条共享种子流**，v2.7.0 改变了 `selectTargets`
  的掷骰次数（有强制目标时不再掷那颗骰）→ 流被平移 → 出现「第一次落空、第二次命中」→
  `0 < 伤害` 使断言变红（实测连续 12 次必红）。修法是**显式强制命中**（临时抬高 `_accMod`）
  并同时要求两次伤害都 > 0，让断言只测它真正要测的系数关系 —— **判据未放宽**，
  而是去掉了与命中运气相关的隐含依赖。

### 影响（固定种子 A/B，如实披露）

108 场**真实大关**战斗（g3~g14 × 3 小关 × 3 种子，我方装配三技能 lv10 + 一只成熟宠物），
同一种子只换 page 源码：

| 指标 | 结果 |
|---|---|
| **胜负变化** | **0**（两版都是 ally 105 / enemy 3） |
| 回合数变化 | **39 / 108**（**22 场更长 / 17 场更短**） |
| 单位 HP 变化 | 58 / 108 |
| 日志条数变化 | 54 / 108 |

**方向**：AI 现在能真正打到它选的人（默认是「最残血 / 威胁最高 / 被嘲讽者」），
敌方集火变得真实有效 → 多数场景战斗变长一点（敌方效率提高 = 玩家更难）；
同时也有 17 场变短（有时更快打死某个目标反而加速收尾）。**本样本内无胜负翻转**、**未做难度补偿**。
⚠️ 因为选中目标的路径变了，**同种子的随机序列与 v2.6.0 不同、不可逐格对比**
（`test-group-determinism` 仍是「同种子两次一致」14/14 绿）。
