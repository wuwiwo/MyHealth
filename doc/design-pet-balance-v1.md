## 0. 结论摘要（TL;DR）

**一句话**：宠物系统目前只有「稀有度 + 炼化」一条强度轴 —— 同稀有度宠物**完全等价**（属性逐字节相同），
炼化是唯一实质战力来源，而 14 只里有 6 只的招牌技能在**炼化 0 时是空转**。所以现状不是「某只宠物偏强」，
而是「宠物个体差异几乎不存在，存在的差异全部来自稀有度与炼化投入」。

## 1. 现状盘点（源码直读 + 本机实测）

### 1.1 属性账（确定性实测）

**口径**：`createPetUnit`（图鉴 + 炼化 + 天赋静态）→ `boostPetForGroup`（× 稀有度倍率）。
宝珠 = 0、团队凝聚/共鸣 = 0（队伍即全部持有宠物）、无玩家技能。
「满炼化」取**期望配置**：每级随机加 1 个属性 → 5 个属性均分（`refineStatGain` 的键集），
即 R 50 级每项 10 级、UR 100 级每项 20 级。生成脚本见 §5.1。

| 配置 | 血 | 攻 | 防 | 魂攻 | 魂防 | 速 |
|---|---|---|---|---|---|---|
| 裸 R（炼化 0） | 1200 | 120 | 60 | 72 | 36 | 5 |
| **满炼化 R（50）** | **4800** | 600 | 300 | 312 | 156 | 5 |
| 裸 SR（0） | 2100 | 210 | 140 | 140 | 84 | 6 |
| 满炼化 SR（60） | 8820 | 1050 | 476 | 644 | 252 | 6 |
| 裸 SSR（0） | 3000 | 300 | 225 | 225 | 150 | 8 |
| 满炼化 SSR（80） | 15000 | 1740 | 945 | 1185 | 630 | 8 |
| **裸 UR（0）** | **4800** | 480 | 320 | 320 | 240 | 9 |
| 满炼化 UR（100） | 24000 | 2400 | 1280 | 1600 | 880 | 9 |

**读数**：
- 同稀有度 14 只**完全同属性**（`pet-codex.js` 里四套常量，逐字段相同）。
- **满炼化 R 的血 = 裸 UR 的血 = 4800** —— R 的成长终点正好是 UR 的起点。
- 全跨度：血 1200→24000（**20×**）、攻 120→2400（**20×**）、魂攻 72→1600（**22×**）。
- 速度恒定 5/6/8/9，**不受炼化影响**（见 D6）。

### 1.2 技能区间在 t=0 的取值（源码直读）

区间驱动：`t = 炼化等级 ÷ 稀有度上限`（`skill.js:134-143`），`数值 = 下限 + (上限−下限)×t`（`skill.js:159-167`）。
**当某个键的下限为 0 时，t=0 的技能就是空转。**

| 宠物 | 技能 | 关键区间 | t=0 取值 | t=0 是否空转 |
|---|---|---|---|---|
| 闪闪星 R | 闪耀 | `acc [0,40]` | **0%** | ⛔ **空转**（仍耗 1 回合 + CD4 + 蓄力） |
| 水水滴 R | 打湿 | `soulDefDown [0,25]`、`hit [0,30]` | **0% / 0%** | ⛔ **空转** |
| 彭彭猪 R | 睡觉 | `power [0,300]`、`turns [1,3]` | **0%** 治疗 / 1 回合 | ⛔ **治疗空转**（仍自睡 1 回合） |
| 火焰鸡 SR | 火焰啄击 | `power [150,330]` | 150% | ✅ 正常 |
| 坚强岩 SR | 坚壁（`fortify`） | **无 range** | 固定 +10%/层 | ⚠️ **完全不吃成长**（见 D3） |
| 清脆鸟 SR | 歌唱 | `power [160,250]`、`sleepChance [0,30]` | 160% / **0%** | ⚠️ 伤害正常、睡眠空转 |
| 雷霆犬 SR | 雷霆冲撞 | `power [260,440]` | 260% | ✅ 正常（另有 35% 反冲，固定值） |
| 小负鼠 SSR | 双撞 | `power [180,270]`、`atkDown [0,10]`、`defDown [0,20]` | 180% / **0% / 0%** | ⚠️ 伤害正常、**降攻防与窃取空转** |
| 黑暗鸦 SSR | 幻影之瞳 | `confuseDown [0.15,0.75]` 等 | 15% 起 | ✅ 正常 |
| 小冰晶 SSR | 冰晶爆 | `power [160,250]`、`freezeChance [10,55]` | 160% / 10% | ✅ 正常 |
| 光之精灵 SSR | 圣光治愈 | `power [150,240]` | 150% → 回 **108 点**（裸装魂攻 72） | ⚠️ 近乎无效 |
| 梦幻 UR | 梦幻光球 | `power [220,310]` | 220% | ✅ 正常 |
| 无念熊 UR | 无影拳 | `power [55,100]` ×4 段 | 55% | ✅ 正常 |
| 圣光麒麟 UR | 战意灌注 | `atkBoost [3,30]`、`lifesteal [5,50]` | +3% / 5% | ⚠️ 幅度极小 |

> **合计**：3 只真·空转（闪闪星 / 水水滴 / 彭彭猪）+ 2 只关键功能空转（双撞的降攻防窃取、歌唱的睡眠）
> + 1 只完全不吃成长（坚壁）+ 2 只近乎无效（圣光治愈、战意灌注）= **14 只里 8 只的技能在炼化 0 时形同没有**。
> 而 R 级 3 只**全部**落在这一档，且 R 级零天赋 —— 即「R 级宠物在炼化 0 时既无技能也无天赋」。

### 1.5 实测一：炼化 0 的宠物 ≈ 不存在

**口径**：队伍 = `[玩家, 该宠]`；玩家用**旧基准账号** 2883/1145/24800/532/99 走 `inheritGroupStats`（继承 50%）；
每关取**第 10 小关（Boss）**；6 个种子；敌方**不随我方缩放**（`GROUP_ANCHOR.enabled = false`，`group-levels.js:459`）。

| 关卡带 | 只有玩家（不带宠） | 14 只宠物（炼化 0） |
|---|---|---|
| g12 / g13 / g14 | 39% 胜 · 13% 我血 · 52 回合 | **33% ~ 61% 胜**（≈ 基线 ± 噪声） |
| g14 / g15 | **0% 胜** · 0% 我血 · 22 回合 | **14 只全部 0% 胜 · 0% 我血** |
| g16 / g17 / g18 | 0% 胜 · 11 回合 | 14 只全部 0% 胜 · 12~14 回合 |

**结论**：炼化 0 时，宠物对胜负**没有可观测贡献**（g12-14 的波动在 6 种子噪声内；
g14 以上一律 0%，连存活回合都只比不带宠多 1~2 回合）。

### 1.6 实测二：满炼化后的逐只排名

**口径 A（单独测试）**：队伍 = `[玩家 + 该宠]`，g14/g15 Boss 关 × 6 种子。
**口径 B（边际测试）**：固定 3 宠核心 + 该宠，减去**同炼化档**的核心自身成绩。
核心 R = 闪闪星/水水滴/彭彭猪；核心 SR = 清脆鸟/小冰晶/光之精灵（用于测试 3 只 R 宠物，避免同种重复入场）。

| 宠物 | 稀有度 | 单独·满炼化（胜率/我血/回合） | 边际·满炼化（Δ胜率/Δ我血/Δ回合） |
|---|---|---|---|
| 无念熊 | UR | **83% / 41% / 25** | **+100pt / +53% / −20** |
| 梦幻 | UR | 58% / 24% / 33 | +83pt / +30% / −8 |
| 小负鼠 | SSR | 50% / 18% / 36 | +67pt / +32% / −2 |
| 圣光麒麟 | UR | 50% / 32% / 45 | +58pt / +33% / +8 |
| 黑暗鸦 | SSR | 17% / 1% / 53 | +50pt / +20% / +10 |
| 小冰晶 | SSR | 33% / 7% / 43 | +50pt / +24% / +2 |
| 光之精灵 | SSR | 25% / 9% / 51 | +50pt / +21% / +12 |
| 清脆鸟 | SR | 0% / 0% / 37 | +42pt / +9% / +8 |
| 火焰鸡 | SR | 0% / 0% / 38 | +33pt / +9% / +6 |
| 坚强岩 | SR | 0% / 0% / 39 | +17pt / +3% / +12 |
| 雷霆犬 | SR | 0% / 0% / 37 | **+8pt / +2% / +10** |
| 闪闪星 / 水水滴 / 彭彭猪 | R | 0% / 0% / 32~34 | +0pt（**天花板**，见下） |

> **对照**：核心 R 满炼化 = 0% 胜 / 51 回合；核心 SR 满炼化 = **100% 胜** / 52% 我血 / 39 回合。
> **天花板说明**：3 只 R 宠物的边际值是用「已 100% 胜的 SR 核心」测的 → Δ胜率恒为 0，**不具区分度**，
> 只作「加不加都不影响」的下界证据；它们真实的强度请看上表「单独测试」列（满炼化仍 0% 胜）。
> 更硬的一档（g16-18，全员 0% 胜）用**存活回合数**看：不带宠 11 回合 → R/SR 满炼化 15~17 → SSR 21~23 → UR 25~31。

**结论**：
- **稀有度是主序**：UR ≫ SSR > SR > R，与属性账一致。
- **同稀有度内部极差很大**（C5）：SR 内 清脆鸟 +42 vs 雷霆犬 +8（**34pt**）；
  UR 内 无念熊 +100 vs 圣光麒麟 +58（**42pt**）；SSR 内 小负鼠 +67 vs 其余 +50（17pt）。
  而它们**属性完全相同** → 差异 100% 来自技能与天赋。
- **两个反常点**：① **雷霆犬**（260%~440% 最高倍率单发）边际贡献垫底 —— 35% 反冲 + 蓄力丢一回合 +
  魂攻路线，实测最差；② **坚强岩**（坚壁不吃成长）靠 SR 基础属性吃饭，技能几乎不贡献。

## 3. 平衡目标与不变量

### 3.1 目标（建议阈值，待作者裁决）

| 维度 | 目标 | 现状 |
|---|---|---|
| 同稀有度内边际贡献极差（g14/15 带，满炼化） | **≤ 15pt** | SR 34pt / UR 42pt（C5） |
| t=0 宠物的边际贡献 | **> 0**（不允许空转） | 14 只全 0%（C3/D4） |
| 稀有度跨度（血/攻） | **≤ 8×**（现 20×） | 20×（C2） |
| 每只宠物至少一项「不可替代」 | 14/14 | 约 5/14（无念熊/梦幻/光之精灵/圣光麒麟/小负鼠） |
| 组队可行组合数（4 只/队） | R 队、SR 队均**可组** | R 只有 3 只 → 组不起（D8） |

### 3.2 不变量（不得违反）

1. 不改战斗引擎数值口径、RNG、胜负与奖励（与 `doc/plans/战斗体验施工计划.md` 同一纪律）。
2. 天赋**保持固定值**（`doc/2.2-修改提案.md` §3.11B 已裁决「天赋不需要升级」）→ 本提案不为天赋接区间。
3. 天赋**固有专属**，不跨宠物装配（v2.1.4 已回退旧实现）→ 新宠物天赋必须 `petOnly: true`。
4. 稀有度倍率、宝珠百分比、凝聚/共鸣比例的**唯一来源**保持在原文件，不在新代码里另立数值。
5. 月重置口径不变（炼化归零、宝珠品质保留）→ 本提案不新增「永久成长」以外的重置例外（P5 突破按设计文档已是永久）。
6. 新宠物必须走既有管道：`createPetUnit` → `applyBattlePetBaseBonuses` → `boostPetForGroup`（顺序有源码级守卫）。

## 4. 调整提案（全部待裁决）

> 每条给出：问题 → 方案 → 具体数值 → 实现落点 → 成本 → 验收方式。
> **成本分级**：**0 = 纯数据**（只改常量/区间，不动引擎）；**1 = 复用既有通道**；**2 = 需新增引擎能力**。

### P1 实装 §2.9 初始属性倾向（成本 0）

- **问题**：D1。作者已在 `doc/2.2-修改提案.md` §2.15 D 裁决「**需要实装**」，代码未做。
- **方案**：把设计 §2.9 的符号表转成**乘数表**落在 `pet-codex.js`，每符号 ±15%（非关键数值），
  在 `createPetUnit` 组装 `base` 时按物种应用；**结果四舍五入**，且必须在炼化加成**之前**（倾向作用于图鉴基数）。
- **数值**：沿用设计原文表格（14 行），不新增数值来源。示例：彭彭猪 血 `+++`(+45%)、攻 `--`(−30%)、
  防 `+++`(+45%)、魂攻 `---`(−45%)、魂防 `++`(+30%)、速 `---`(−45%)。
- **落点**：`page/pet-codex.js` 的 `PET_CODEX[].tendency` + `createPetUnit` 一行应用。
- **风险**：会改变**所有**宠物现有效能（尤其把 R 血从 1200 压到 660 的彭彭猪更脆）→ 需整体复测。
- **验收**：§5.2 三档难度带上重跑；断言「每只宠物最终属性 ≠ 同稀有度其他宠物」。

### P2 消除 t=0 空转：给 6 条技能加**功能性保底下限**（成本 0）

- **问题**：D4。下限为 0 的键在 t=0 等于没有。
- **方案**：把「功能下限」从 0 抬到**能感知但不强**的水平；**上限保持不变**（不改满炼化强度）。
- **建议数值**（待裁决）：

| 技能 | 键 | 现区间 | 建议区间 | t=0 效果 |
|---|---|---|---|---|
| 闪耀 | `acc` | `[0,40]` | `[8,40]` | 命中 −8%（2 回合） |
| 打湿 | `soulDefDown` / `hit` | `[0,25]` / `[0,30]` | `[5,25]` / `[8,30]` | 魂防 −5%、被命中 +8% |
| 睡觉 | `power` | `[0,300]` | `[60,300]` | 回 (防+魂防)×60% |
| 双撞 | `atkDown` / `defDown` | `[0,10]` / `[0,20]` | `[3,10]` / `[6,20]` | 降攻 3% / 降防 6% |
| 歌唱 | `sleepChance` | `[0,30]` | `[5,30]` | 5% 睡眠 |
| 战意灌注 | `atkBoost` / `lifesteal` / `skillLifesteal` | `[3,30]` / `[5,50]` / `[7.5,32.5]` | 建议**不动**（下限已非 0） | — |

- **落点**：`page/pet-codex.js` 各 `registerSkill` 的 `range`。
- **副作用**：`test-pet-skills.js` 有「t=0 取到 0」类断言（如睡眠 0%）→ 属**预期红**，需同步改断言（施工时）。
- **验收**：断言 t=0 时 6 条技能各自的产出量 > 0；三档带上 R 宠单独测试的胜率**高于**不带宠基线。

### P3 坚壁接成长区间（成本 0）

- **问题**：`fortify` 是唯一无 `range` 的宠物技能（`skill.js:578`），+10%/层固定 → 坚强岩的技能随炼化零成长。
- **方案**：给坚壁加 `range:{ defUp:[8,20] }`（每层防御/魂防增幅），或**换专属技能**（§2.15 B 曾裁决「复用」，此处建议复核）。
- **落点**：`page/skill.js` 的 `fortify` 定义（注意它是**敌群共用技能**，改它会影响敌人 —— 若不能改，
  则改为在 `pet-codex.js` 注册宠物专属变体 `p_fortify`，**推荐后者**）。
- **验收**：断言 t=0/t=1 的增幅不同；坚强岩边际贡献从 +17pt 提升到 SR 中位。

### P4 速度轴收口（成本 0，需裁决方向）

- **问题**：D6。设计 §2.8 含速度，实现不含。
- **两个方向（二选一）**：
  - **A 补实现**：`refineStatGain` 加 `spd: 1`（R/SR/SSR/UR 一致，与设计表相同）。
    → 满炼化 UR 速度 9+20 = 29；会显著改变先手顺序与 AI 目标选择，**属数值改动，需整体复测**。
  - **B 回改文档**：明确「速度是稀有度固有属性、不参与炼化」，并删除设计 §2.8 表里的速度行。
- **建议**：**B**（成本最低、不动平衡），并把「速度成长」列为未来独立任务。
- **验收**：若选 A，需三档带 + 固定种子 A/B 全量回归；若选 B，仅文档一致性。

### P5 实装突破（成本 2）

- **问题**：D7。设计 §2.8 的「3 倍属性、永久保留」是 SSR/UR 的核心长期目标，未实现。
- **方案**：在宠物存档加 `breakthroughs: [{ level:80, applied:true }, ...]`；达 80/100 级时把该次突破对应的
  **3 倍等级提升属性**累加进 `refineStats`，并标记为「不受月重置」。月重置时保留该部分。
- **落点**：`page/pets.js`（结构）/ `page/pet-materials.js`（结算与重置）。
- **成本说明**：涉及**存档 schema 变更**（需迁移 + 旧档零突破兼容），且 `pet-store.js` 有 schema 注册表约定。
- **验收**：旧档零突破正常；突破后属性 = 基础 + 炼化 + 3×该段等级收益；月重置后突破部分保留。
- **依赖**：与批次 B 无关（批次 B 动 `store.js` 注册表，P5 动 `pet-store.js` 的 pets 结构）→ **建议等批次 B 落地后再开工**，避免同窗口改存档结构。

### P6 稀有度跨度收口（成本 0，需裁决）

- **问题**：D2 / C2。20× 跨度使低稀有度完全作废。
- **三个候选（三选一）**：

| 方案 | 做法 | 效果 | 风险 |
|---|---|---|---|
| **A 提高低稀有度上限** | R 50→70、SR 60→80（SSR/UR 不动） | 满炼化 R 血 ≈ 6600（+38%）、SR ≈ 10800 | 需重算全部技能区间 t（区间随上限变化 → 所有 R/SR 技能曲线被拉长） |
| **B 收窄倍率差** | 倍率 1200/1400/1500/1600 → **1400/1500/1550/1600** | 裸 R 血 1400、跨度 1200→24000 变 1400→24000（17×） | 改动影响**所有**宠物与历史平衡数字；宝珠池坐标系不变 |
| **C 只改「终点」** | 保持倍率与上限，把 R/SR 的 `refineStatGain` 提高（R 血 30→45、SR 40→55） | 满炼化 R 血 ≈ 7050、SR ≈ 10500 | 与设计 §2.8 表不符（需同时改文档） |

- **建议**：**A + 只提上限不改倍率**，因为它不动「稀有度倍率」这个全局坐标系（宝珠/凝聚/共鸣都挂在上面），
  改动面最小；但要接受「技能区间 t 分母变化」带来的全量复测。
- **验收**：三档带上「满炼化 R 队」的胜率与「满炼化 UR 队」差距 ≤ 2 个难度档。

### P7 天赋强度对齐（成本 0，需裁决）

- **问题**：D5。幸运口袋战斗内零价值；R/SR 零天赋。
- **方案（三选一或组合）**：
  - **7a** 给幸运口袋加战斗内价值（如「战斗胜利额外回复 X% 生命」）→ 但它与「经济天赋」定位冲突，需裁决。
  - **7b** 给 R/SR 各加**一个**天赋（R 单、SR 单），把「天赋 = 稀有度红利」改成「天赋 = 物种特征」。
  - **7c** 承认「幸运口袋 = 经济天赋」，在 UI 明示其收益在结算期（**只改文案与面板**）。
- **建议**：**7b（R/SR 各 1 个天赋）+ 7c（明示幸运口袋定位）**。7b 与 P1（属性倾向）配合，能让低稀有度
  宠物有「特征」而不是「劣化版 UR」。
- **验收**：R/SR 宠物在 g14/15 的边际贡献不再为 0；每只宠物至少有一个「只有它有」的机制。

### P8 战力可视化（成本 1，纯 UI）

- **问题**：D10。
- **方案**：宠物面板在「最终属性」旁增加一列**相对强度档**（对当前所选敌群大关的人均属性比值），
  分档：`不足 / 相当 / 充裕`。复用 `petStatBreakdown()`（已有，纯展示）与敌群人均属性，**不新增数值口径**。
- **落点**：`page/pet-ui.js` 展示层；敌群人均属性取 `groupStageEnemies` 的现有结果（只读）。
- **验收**：同一宠物在 g6 与 g20 显示不同档位；不产生任何新战斗数值。
